# 需求确认书：用户资产管理与失败告知 GUI

状态：**owner 已于 2026-09-21 确认，进入正式产品设计。**  
关联：T-536、T-524 Agent Space 重构、现有 Portal、自动化失败通知 T-479。

## 背景与现状

Agent Space 重构已将用户数据资产、方法、Skill、任务、对话与 Agent 工作状态拆为独立对象，并冻结了 scope、版本、授权、审计和运行依据边界。当前 Portal 已有对话、自动化任务和我的文件；聊天右侧旧“工作空间”文件面板后续移除。

底座不是不可改变的前提：若 GUI 产品化证明既有对象边界、生命周期、授权或迁移假设与用户可理解的管理模型冲突，应提出具体冲突、影响对象与迁移边界后修订底座；不得为了兼容旧设计牺牲产品语义，也不得无依据破坏服务端 scope、版本和审计约束。

## 目标

通过 GUI 将用户拥有且能理解、能受控管理的资产组合产品化，使用户能够：

1. 管理资料、正式方法、私有 Skill 和持续自动化；
2. 可靠得知自动化或交付失败，并在需要时让 Agent 解释和处理；
3. 看见版本、采用/启用状态、影响与关联，但不承担运行时控制面的复杂性；
4. 让 Agent 在已有授权的对话或任务运行中形成可复用改进候选，经用户批准后逐步改善后续行为。

## 目标用户

当前单 Agent 投资决策助手的普通用户。用户以对话完成主要工作，以网页管理长期资产、查看版本和处理失败。未来多 Agent 是保留的演进方向，不纳入首版用户模型。

## 核心使用场景

1. 用户在“我的文件”查看上传资料、对话报告和自动化产物，并追溯其来源和任务引用。
2. 用户进入“工作空间 > 我的方法”，查看正式策略是否采用、版本变化及其影响的任务。
3. 用户进入“工作空间 > 我的 Skills”，管理私有 Skill 或安装的系统/市场 Skill。
4. 用户在现有自动化任务页查看任务目标、关联资料/方法/Skill、分层结果和失败事项。
5. 自动化或交付失败时，用户在网页待处理或微信提醒中得知影响，进入绑定该事实的问题处理对话，让 Agent 解释和提出方案。
6. Agent 在既有对话或已授权任务运行中发现可复用改进时，提出候选；用户审阅影响与版本后批准或拒绝。

## 需求范围

### 导航与页面

- 侧栏增加 `待处理` 和新的 `工作空间` 页面入口。
- `自动化任务`、`我的文件`保留为侧栏直接入口。
- 新工作空间是 GUI 信息架构，不是旧 Workspace 文件根、数据容器或权限边界。
- 工作空间首版仅有 `我的方法`、`我的 Skills` 两个 Tab，默认进入我的方法；不预设概览仪表盘。
- 聊天右侧旧只读“工作空间”文件面板属于后续移除范围，不为其保留兼容设计。

### 我的文件

- 保留现有资料库的上传、预览、下载、重命名、归档、来源和版本能力。
- 补充文件来自上传、对话或自动化，及其被自动化读取/更新、所属任务结果的关联信息。
- 方法或 Skill 的内容来源只能跳转其主管理入口，不提供第二个编辑入口。

### 我的方法

- 方法体系是一等资产，不以普通文件列表语义管理。
- 默认页是方法体系列表。每张卡片显示名称、用途、当前采用或未采用、最近变更、使用该方法的自动化数和待确认版本。
- 详情页提供版本 Diff、历史、恢复、任务影响、关联资料和创建/编辑入口。
- 多套方法可并存；默认运行或具体任务只使用明确采用或固定绑定的版本。

### 我的 Skills

2026-09-23 owner 补充裁决：原下述“私有 Skills/已安装 Skills”双区块及系统发布项仅能安装/卸载的定义，由[产品设计 §4.2](./agent-space-user-product-design.md#42-我的-skills)中的单助手安装模型替代。系统基础 Skill 不向用户展示或开放管理；用户可管理的预置 Skill 默认安装且启用，允许停用、启用、卸载和从目录找回。“安装即生效”以适用场景为限，不能解释为每轮注入；存量用户的采用与历史选择另行核对，不能批量覆盖。以下原始条目保留为当时需求记录。

- 私有 Skill：用户可查看、创建/编辑、比较版本、启停和安装。
- 系统/市场 Skill：用户只可安装、卸载、显式升级，不能修改发布版本。
- 首版只展示“我的私有 Skills”与“已安装 Skills”，不做市场浏览或推荐中心。
- Skill 内容不能扩大工具、数据、scope 或持续执行权限。

### 自动化任务

- 基于现有 `/automations` 升级，不创建平行模块。
- 保留创建、编辑、暂停/恢复、运行历史和既有 scope 校验。
- 任务详情补充：用户目标、可跳转的方法/Skill/输入输出资料、执行/产物/投递分层结果，以及关联失败事项入口。
- `Commitment` 保持服务层履约语义，在任务和失败说明中以用户可理解的结果呈现，不成为首版独立管理对象。

### 待处理与通知

- `待处理` 是 Portal 全局失败告知入口；自动化模块保留领域内“需要处理”筛选，但不再是失败的唯一发现路径。
- 首版只展示失败事项。用户可选择进入对话处理或暂不处理；不向用户暴露细粒度事项分类或手动收口流程。
- 每张失败卡片只显示失败任务/交付、发生时间、直接影响、当前系统状态，以及“让 Agent 解释并处理”入口。
- 网页保存完整失败告知；微信是同一失败事项的简短提醒投影。
- 用户可管理微信提醒开关、静默时段和可提醒类别；偏好不改变任务/run 事实、事项状态或自动化授权。
- 成功和自动恢复默认不主动提醒。

### Agent 改进能力

- Agent 可在已有、受 scope 与授权约束的交互会话或自动化任务运行中，因明确触发（包括找到可复用的失败处置）选择提出 lesson/workflow 草案。
- Agent 不必每轮强制反思，也不得脱离用户对话或既有任务另起全局自我诊断/反思运行。
- 草案不自动改变后续行为，也不得直接修改方法、Skill、任务、通知偏好、权限或工具范围；用户在对话中审阅、批准或拒绝后才按对象版本契约生效。
- 对话中产生的候选在当前对话展示；失败运行产生的候选附着同一失败事项，不另发第二条微信；不影响当前结果的候选低优先级网页可见、默认不微信提醒；拒绝后无新事实不得重复打扰。

## 统一对象规则

- 一个对象有一个主管理入口；同一底层内容版本可被多对象引用，但其他页面只读追溯，不形成双重编辑入口或分叉版本链。
- 内容版本与运行生效分离：资料保存不自动影响运行；方法须采用；私有 Skill 须安装/启用；任务修改形成新 revision；已绑定任务保持原版本直至明确改绑。
- 对象详情按需显示来源、被使用于和影响，不建设用户维护的全局关系图，也不暴露 scope、checksum、授权、run-basis 或 Agent Space 拓扑。
- 首版默认单 Agent。用户通过 Skills、方法、资料、自动化和偏好间接管理助手；多 Agent 底座保留，未来再产品化。

## 不在范围内的事项

- 发布 Agent Space 控制面、run-basis 或 Agent 安装清单给普通用户。
- 恢复旧 Workspace 作为文件容器、权限边界或方法发现路径。
- 新建 Skill 市场、推荐中心或用户维护的全局关系图。
- 首版多 Agent 管理、Agent 自生成代码工具、越权访问或后台脱离既有任务的独立自我反思运行。
- 在本设计阶段修改生产 DB、真实 Workspace、resolver、微信投递或 Portal 代码。

## 约束条件

- 服务层继续强制 user/project/instance scope、授权、版本固定、审计、幂等和写入边界；GUI 和 Skill 文本不能成为安全边界。
- 真实用户资产和历史运行不被批量覆盖；涉及迁移须有独立的备份、隔离演练、逐对象采用与回滚设计。
- 区分执行成功、产物生成、投递成功与用户已读，不以任一单独事实冒充全部履约。

## 首版优先级

**必须**：新工作空间的两 Tab；现有文件/自动化的关联升级；全局失败告知与问题处理对话入口；版本与显式生效规则；通知偏好边界；Agent 可持久化纠错草案的端到端能力设计。

**应该**：跨对象的来源/使用/影响跳转；失败说明中的履约影响；候选提议的低噪声投影。

**可以后置**：多 Agent 用户管理、Skill 市场与推荐、工作空间概览、细粒度事项分类。

## 验收标准

- 用户能从侧栏进入待处理、自动化任务、我的文件和工作空间；工作空间默认打开我的方法，并可切换我的 Skills。
- 用户能管理文件、方法、私有 Skill、已安装 Skill 和自动化，而不会在多个页面编辑同一语义对象。
- 修改资料、方法、Skill 和任务时，页面能清楚区分新版本已保存与是否已影响后续运行。
- 自动化或交付失败在网页中可见，并可进入带关联事实的问题处理对话；微信提醒与网页指向同一失败语义。
- 用户界面不展示内部 scope、checksum、run-basis、工具调用或权限结构；这些也不能通过 GUI 被修改。
- Agent 的可复用改进只能以候选方式提出，未经用户批准不得影响后续默认行为；不得存在无任务/无会话上下文的独立自我反思执行路径。
- 原有自动化、文件和对话行为在升级后保持其既有 scope 与运行约束。

## 假设、风险与待定项

- `attention_item` 是否成为具体领域对象、其去重/恢复/归档状态机和跨端投递键，属于后续开发设计，不是当前用户需求决定。
- 现有 Agent Space state 服务已有对象、版本与批准机制，但当前模型工具表尚未提供候选创建/修订能力；正式设计必须定义此端到端接线及其运行入口。
- 现有自动化失败通知 T-479 的“恢复微信推送”与“成功默认不打扰”存在产品策略冲突，实施前需按本确认书调整并回归验证。
- 旧右侧工作空间面板的移除时机、会话附件/报告替代预览体验和迁移计划需单列实施任务。
