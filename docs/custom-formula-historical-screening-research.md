# 用户自定义公式历史截面选股需求调研记录

> ⚠️ 状态更新（2026-09-03）：本文 §3 的**现状结论已过时**——"筹码数据缺失导致无法承接"的前提不再成立（`chip-distribution.ts` 换手率衰减代理模型已现役，可算 WINNER）。现行现状盘点、终局定义与阶段划分见 [strategy-indicator-roadmap.md](./strategy-indicator-roadmap.md)。本文的 §6 支持等级、§7 分阶段采购条款、§9 验收标准、§10 风险表作为方法论继续有效。

> 调研日期：2026-07-27  
> 状态：调研结论，可作为客户答复与后续立项输入；尚未形成实施承诺  
> 关联文档：`composite-indicator-system.md`、`market-data-service-design.md`、`data-source-policy-decision.md`、`data-provider-cost-evaluation.md`

## 1. 调研目的

本次调研源于一个明确的客户需求：客户提供自己定义的选股公式，希望 Invest Agent 在指定历史交易日收盘后，使用该公式对全 A 股进行筛选，并返回符合条件的股票。

调研需要回答四个问题：

1. 这个需求的产品和技术本质是什么；
2. 现有 Invest Agent、通达信接口和公开数据能力能否直接满足；
3. 免费数据、付费数据和近似计算分别能做到什么程度；
4. 如果决定建设，应补充哪些平台能力，以及如何分阶段验证。

## 2. 核心需求定义

该需求本质上是一项用户自定义的量化选股能力，而不是普通的股票问答。

目标用户流程为：

```text
用户提交选股公式和目标日期
  -> AI 理解公式、补充必要参数并识别原始公式方言
  -> 平台保存原始公式及其版本
  -> AI 将公式转换为平台受控的中间表达
  -> 平台校验函数、字段、数据依赖和执行口径
  -> 历史截面引擎取得目标日期及计算窗口所需数据
  -> 引擎对目标日期当时的全 A 股股票池执行公式
  -> 返回命中股票、条件值、数据来源、口径和缺口
  -> AI 解释结果，但不替代确定性计算
```

“历史截面筛选”在本文中专指：以某个历史交易日为观察时点，只使用该时点已经可获得的数据，对该时点有效的全市场股票池执行同一公式。它不同于查询今天的股票，也不同于把今天的股票名单和今天已知的信息回填到历史日期。

## 3. 本次调研结论

### 3.1 总体判断

该需求可以建设，但不能被简化为“给 AI 一个行情 API”。完整能力至少包括公式管理、公式编译、数据适配、历史截面还原、全市场计算和结果审计。

现有系统尚不具备完整能力：

- 已有行情服务偏向单股查询、持仓巡检、复盘和规则检查，并未积累可直接用于任意历史截面的全市场数据集；
- 已有复合指标设计可承载用户规则和受控计算，但未形成面向全 A 股历史截面的公式编译与批量执行服务；
- 现有免费数据可以支持一部分常规指标，却不能覆盖所有平台专有指标；
- 当前测试过的通达信接口能够执行部分历史内置查询，但没有验证出通过 API 上传并运行任意用户公式的能力；
- 对包含 `COST`、`WINNER` 等筹码函数的公式，缺少相同口径的底层数据时，无法保证与同花顺或通达信结果严格一致。

因此，近期不能向客户承诺“任意公式、任意历史日期、与原平台完全一致”。可以承诺的方向是：先对公式做能力诊断，再根据数据和函数支持情况提供精确、兼容、代理或不支持四类明确结论。

### 3.2 免费与付费的正确边界

免费不等于近似，付费也不等于准确。

- 对 OHLCV、成交额、换手率以及由其确定性推导的 `MA`、`EMA`、`REF`、`HHV`、`LLV`、`CROSS` 等指标，只要数据完整且复权和缺失值口径明确，免费数据也可以精确计算；
- 对筹码分布、Level-2、逐笔成交、专有资金指标等免费数据没有的字段，只能购买相应数据、明确使用代理模型，或判定不支持；
- 付费数据主要改善覆盖、历史深度、稳定性、频次和服务保障，不能自动保证与客户原公式所在平台的函数语义一致；
- 即使采用付费供应商，平台仍需保留字段归一化、来源记录、质量检查、缓存和降级机制。

### 3.3 是否必须先建设大型本地数据池

不必在第一阶段复制专业量化平台的完整数据库，但必须具备可复现的数据供给层。

第一阶段可以采用：

```text
供应商或公开数据源
  -> 按任务拉取所需历史窗口
  -> 规范化与质量校验
  -> 本地任务缓存/结果快照
  -> 截面计算
```

当筛选次数、历史范围和并发用户增加后，再把高频复用的数据逐步沉淀为本地历史数据池。无论是否长期存储原始数据，每次正式筛选都应保存足以复现结果的数据版本、来源和计算记录。

## 4. 已验证的外部能力

### 4.1 通达信接口测试

本次使用通达信 API/MCP 做了只读验证。已确认：

- 可以自动调用，无需为普通查询人工上传代码；
- 可以执行部分内置的历史市场查询；
- 指定 2026-07-24 的历史内置涨停查询能够返回结构化结果，说明接口具有一定历史日期查询能力。

未确认或未支持：

- 通过 API 上传、保存和运行任意通达信公式；
- 按用户自定义公式对全 A 股执行历史截面计算；
- 返回公式所需的历史 `COST/WINNER` 底层筹码数据；
- 对客户公式提供与通达信客户端一致的计算口径保证。

结论：通达信接口目前可以作为候选数据源或内置查询补充，不能据此视为可直接托管用户公式的量化执行平台。若仍需人工导入客户端公式，则不符合 Invest Agent 的自动化产品目标。

### 4.2 Tushare Pro 调研

Tushare Pro 是当前成本较低、且公开文档中明确提供筹码数据的候选供应商：

- `cyq_perf` 提供每日筹码成本分位、平均成本和胜率等字段；
- `cyq_chips` 提供按价格分布的每日筹码占比，可用于计算特定价格下的获利盘比例；
- 两个接口的数据从 2018 年开始，均要求至少 5,000 积分；
- 5,000 积分档公开频次为每天 20,000 次，`cyq_chips` 另有每分钟 200 次限制；
- 2026-07-27 检查到的新用户注册公开规则为 100 积分，不能免费访问上述两个关键接口；
- 官方未公开承诺普通用户可获得覆盖上述接口的临时免费试用，购买权限不支持退款。

结论：Tushare 值得作为首个低成本付费候选，但在采购前仍需通过供应商样例、临时测试权限或小范围授权，验证字段含义、单次返回规模、全市场调用方式、历史完整性和商业使用条款。

### 4.3 其他候选来源

- AKShare、BaoStock：现金成本低，适合历史日线回填、普通指标计算和交叉验证，但不能默认提供稳定、同口径的专有筹码数据；
- JQData、RQData：可能提供更完整、整洁的本地量化数据能力，但当前公开价格和具体商业条款不足，需要直接询价和申请试用；
- Wind、Choice、iFinD 等专业产品：数据能力更强，但价格和授权模式暂不适合当前实验性 MVP，不能作为默认前提。

MCP 或 SDK 只是接入形式，不等于数据授权。是否可用于客户服务，还要确认缓存、展示、二次计算和结果分发权利。

## 5. 平台需要补充的能力

### 5.1 公式资产管理

用户公式应作为 workspace 内的版本化资产保存，至少包含：

- 用户原始公式及来源方言；
- 规范化公式或抽象语法树；
- 平台中间表达；
- 参数、函数和字段依赖；
- 股票池、目标日期、复权和过滤口径；
- 支持等级及近似说明；
- 公式版本、创建时间、确认时间和验证状态。

公式修改后必须产生新版本。历史任务引用固定版本，不能被后来修改覆盖。

### 5.2 受控公式编译器

AI负责理解和初步翻译，但最终执行表达必须由确定性服务校验。平台不能直接 `eval` 用户文本或无约束执行 AI 生成代码。

第一版应只支持明确白名单，例如：

- 算术、比较、布尔组合；
- `MA`、`EMA`、`SMA`、`REF`、`HHV`、`LLV`；
- `CROSS`、`COUNT`、`EVERY` 等常用时间序列函数；
- 受控的行情、交易状态和基本面字段。

编译阶段必须返回：是否可执行、缺少哪些字段、哪些函数存在方言差异、需要多长历史窗口、预计数据量和计算成本。

### 5.3 历史截面数据服务

除了 K 线本身，还需要能够按历史日期还原：

- 当时已上市且尚未退市的证券集合；
- 证券代码和名称变更；
- ST、停牌、退市整理期等交易状态；
- 涨跌停制度和所属交易板块；
- 复权因子、分红送转等公司行为；
- 财务数据的实际披露时间，而不是仅按报告期归属；
- 公式需要的行业、股本、估值、筹码或其他扩展字段。

这部分的核心要求是 point-in-time correctness，即避免未来数据污染。

### 5.4 全市场截面执行器

执行器应负责：

- 根据目标日期生成有效股票池；
- 汇总公式所需的历史窗口和字段；
- 批量拉取、缓存和归一化数据；
- 按股票并行计算并限制资源；
- 对缺失数据、停牌、窗口不足和供应商错误给出确定状态；
- 返回命中结果、关键中间值、未计算数量和失败原因；
- 保留任务级审计、公式版本和数据来源。

AI不应在对话上下文中逐只计算约五千只股票。AI负责发起任务和解释结果，批量计算属于服务层。

### 5.5 数据供应商适配层

平台应定义自己的规范字段，而不是让用户公式直接依赖某个供应商接口。例如：

```text
market.close
market.volume
market.turnover_rate
chip.cost_15pct
chip.cost_85pct
chip.winner_rate
chip.distribution
```

免费或付费供应商分别实现这些字段。更换供应商时，公式和 AI 工作流不应随之重写。每个字段还需要携带供应商、原始口径、市场时间、抓取时间、置信等级和警告。

## 6. 结果支持等级

平台对每个公式，而不是对整个供应商，给出以下等级：

| 等级 | 判定标准 | 对客户的表达 |
| --- | --- | --- |
| 精确支持 | 所有字段可得，函数语义和执行口径已验证 | 可按平台声明口径确定性执行 |
| 兼容支持 | 数据可得，但与原公式平台存在已知口径差异 | 可执行，结果可能与原平台略有差异 |
| 代理计算 | 一个或多个关键字段由明确的替代模型估算 | 仅作近似筛选，必须展示替代项 |
| 不支持 | 缺少不可替代数据、函数或授权 | 不执行，不伪造结果 |

一次公式中只要存在代理字段，整个筛选结果就不能标为精确支持。结果页和 AI 回复必须显示该次任务实际采用的等级，而不能只在公式创建时提示一次。

## 7. 建议的分阶段建设路径

### 阶段 0：公式诊断，不做全市场承诺

目标：用户提交公式后，系统能够解析并报告数据和函数缺口。

交付物：

- 公式版本化存储格式；
- 受控中间表达和首批函数白名单；
- 数据依赖分析器；
- 精确、兼容、代理、不支持四级诊断结果；
- 使用少量固定股票和固定日期的公式语义测试集。

### 阶段 1：普通数据的历史截面选股 MVP

目标：使用免费或现有数据，对只依赖 OHLCV、复权因子、交易状态和常用技术指标的公式完成全 A 股日线历史截面筛选。

交付物：

- 历史股票池和 point-in-time 状态还原；
- 普通日线与复权数据适配；
- 全市场批量执行 API 和 MCP 工具；
- 结果审计、缓存、失败统计和可复现快照；
- 至少一个已知公式与基准平台的小样本对照。

### 阶段 2：专有数据插件与代理模型

目标：针对已证明有客户价值的具体数据缺口，引入付费供应商或经确认的代理算法。

进入条件：

- 已有真实公式被阶段 1 的数据缺口阻塞；
- 能明确列出所需字段和预期调用量；
- 供应商提供样例或试用验证；
- 已确认商业使用、缓存和结果展示条款；
- 采购成本低于自行维护或持续无法交付的成本。

首个候选可围绕 `COST/WINNER` 对 Tushare 筹码接口做小范围验收，不应先购买分钟、Level-2 或终端产品。

### 阶段 3：规模化和性能建设

只有在任务量证明按需拉取无法满足性能后，再建设更完整的本地数据仓库、增量更新、列式存储、任务队列、并发调度和结果复用。当前不应预先建设机构级量化基础设施。

## 8. MVP 范围与非目标

建议 MVP 包含：

- A 股日线级历史截面；
- 用户显式指定的公式、日期和股票池口径；
- 受控公式子集；
- 普通行情和可验证的衍生指标；
- 异步任务、结果列表、计算详情和审计信息；
- 明确的数据缺口与近似告知。

建议 MVP 不包含：

- 任意通达信、同花顺或其他平台公式的完全兼容；
- 分钟、Tick、Level-2 和高频回测；
- 自动交易或下单；
- 收益承诺、策略有效性承诺；
- 未经验证的专有指标复刻；
- 为一次客户请求预先建设完整机构级数据仓库。

## 9. 验收标准

后续实现至少满足以下标准，才能称为“历史截面选股能力”：

1. 用户公式存在不可变版本，筛选任务可追溯到该版本；
2. 系统在执行前能列出全部函数、字段、历史窗口和支持等级；
3. 目标日期股票池不包含当时尚未上市的股票，并正确处理退市、ST和停牌口径；
4. 财务及分类数据按当时可见时间生效，不使用未来信息；
5. 对支持的普通公式，可以在固定历史日期完成全市场筛选并返回逐股关键条件值；
6. 数据缺失不会被静默填充，代理模型不会被标记为精确数据；
7. 同一公式版本、同一数据快照和同一执行配置可重复得到相同结果；
8. 结果包含数据源、市场日期、抓取时间、复权方式、股票池口径、未计算数和警告；
9. 单只股票失败不会使整个任务无结果，系统能够汇总失败原因；
10. AI只解释确定性执行结果，不在没有执行证据时生成股票名单。

## 10. 风险与应对

| 风险 | 影响 | 应对 |
| --- | --- | --- |
| 公式方言不同 | 翻译后结果与客户平台不一致 | 保存原始方言，建立函数语义表和对照样本 |
| 免费接口不稳定 | 历史任务失败或数据缺失 | 多源适配、缓存、重试、来源健康和显式降级 |
| 付费数据仍不匹配 | 花费后仍无法复现客户结果 | 采购前要求样例/试用，按字段验收而非按品牌采购 |
| 未来数据污染 | 历史筛选结果失真 | 建设 point-in-time 股票池、披露时间和公司行为处理 |
| 近似结果被误认为精确 | 损害客户信任和投资判断 | 任务级支持等级、强制警告和结果审计 |
| 任意代码执行 | 主服务和用户数据安全风险 | 受控 AST/规则树，必要脚本进入独立沙箱 |
| 全市场计算成本过高 | 延迟、限频或任务拥堵 | 先按需缓存，批量接口优先，异步队列和资源预算 |
| 数据授权不清 | 商业和合规风险 | 接入前确认 API、缓存、展示和衍生结果分发条款 |

## 11. 待决策和待验证事项

1. 第一版支持哪一种原始公式方言：平台自有 DSL、通达信兼容子集，还是由 AI 统一转换；
2. MVP 的全 A 股股票池是否包含北交所、ST和退市整理期股票；
3. 默认使用前复权、后复权还是不复权，以及客户能否覆盖默认值；
4. 免费历史数据源的字段完整性、调整口径、调用稳定性和使用条款；
5. Tushare `cyq_perf/cyq_chips` 按交易日和按股票查询的实际返回上限及全市场调用成本；
6. JQData、RQData 是否能提供覆盖关键字段的免费试用及商业报价；
7. 筛选结果和底层数据分别保留多久，哪些属于 workspace 用户资产，哪些属于服务级缓存和审计；
8. 客户是否要求与某个指定平台逐股一致，还是接受 Invest Agent 自己公开、稳定的计算口径。

第 8 项会直接改变产品承诺和成本：如果客户要求与某个专有平台完全一致，就必须取得该平台的数据和语义授权；如果客户接受 Invest Agent 的公开口径，则可以用可验证的免费/付费混合数据逐步建设。

## 12. 当前建议与客户答复边界

当前建议是立项建设“受控公式的日线历史截面选股”，而不是立项建设“兼容任意量化平台的任意公式”。先完成公式诊断和普通数据 MVP，再以真实被阻塞的客户公式作为付费数据采购依据。

现阶段可对客户表达：

> 我们已经确认该需求属于用户自定义公式的历史截面量化选股。平台需要先识别公式所用函数和数据，再判断能够精确执行、兼容执行、使用代理数据，还是暂不支持。普通行情和常用技术指标具备建设可行性；涉及筹码或其他专有数据的公式，需要增加相应数据授权后才能保证口径。我们不会在数据不足时把近似结果表述为精确名单。

现阶段不应对客户表达：

- 已经支持任意公式；
- 免费数据一定只能近似；
- 购买任意付费 API 后即可与同花顺或通达信完全一致；
- 当前已经能够可靠给出包含 `COST/WINNER` 公式的全 A 股精确历史名单。

## 13. 后续实施交接

执行 Agent 应以本文阶段 0 为起点，先审计现有 `composite-indicator-system`、市场数据 facade、workspace 资产归属和 MCP 服务边界，再形成独立的实施设计。不要在没有数据契约和公式语义测试集的情况下直接增加全市场循环或自由代码执行。

验收 Agent 应以第 9 节逐项检查，重点识别未来数据污染、公式语义漂移、近似结果未告知、数据授权缺失和 AI 绕过确定性执行生成名单等问题。
