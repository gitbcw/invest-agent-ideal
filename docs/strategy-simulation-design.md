# 策略模拟与进化反馈：产品设计

日期：2026-09-19。

状态：历史产品设计草案；专用执行器方向已于 2026-10-07 移除并归档（见 [docs/archive/2026-10-07-strategy-simulation-legacy/](./archive/2026-10-07-strategy-simulation-legacy/)），当前执行口径为 Agent-first，见 [templates/skills/strategy-simulation/SKILL.md](../templates/skills/strategy-simulation/SKILL.md)。本文保留早期用户目标和范围取舍，不作为当前工程执行输入。

## 1. 产品目标与已确认决定

面向 mg 这类已有投资策略的用户，提供一个可开启、持续运行的“策略模拟”功能。用户不必每天发起选股、记账和复盘；系统按确认过的策略自动运行，在 Portal 留下可查记录，并每周提出有依据的改进建议。

最小闭环：选择策略 → 澄清执行规则 → 确认开启 → 每日模拟与记账 → 每周复盘 → 建议修订 → 用户确认后以新版本继续验证。

本轮已确认：

- 只能在 AI 对话中首次开启，Portal 提供专门页面查看。
- 策略不完整时先澄清，不能带着未解决的执行歧义开始。
- 首版日频：收盘后判断，下一交易日按约定模拟成交；不做盘中触发交易。
- 初始净值为 1，以收益率、胜率、回撤等比例指标呈现，不要求填写真实资金金额。
- 每日有记录和日报，每周有专门复盘及策略进化建议。
- 首先验证单个策略完整闭环，随后支持多个独立策略模拟；数据与界面从开始保留多模拟结构。
- 自动运行和提出建议；修改正式运行规则需要用户确认。

首版不接真实交易、不依赖实盘录入、不做自动参数寻优、不承诺盈利、不建设多个策略共用资金的组合账户。实盘对照是后续扩展，不是开工前置条件。

## 2. 用户如何使用

### 2.1 开启前：通过正常对话补齐规则

用户：“帮我把我的控盘度加量价策略开一个模拟。”

AI 读取用户指定的策略资产，说明找到的来源及版本，检查缺口。例如：“选股条件已有了，还缺退出条件和每只股票的仓位比例。我们先确认退出条件。”每轮只问少量关键问题；已经明确的内容不重复询问。

规则齐备后，展示一张可阅读的开启摘要：策略名称与版本、选股范围、买卖条件、仓位规则、日频执行方式、成本口径、初始净值 1、开始日期、日报与周报位置。用户确认这一份摘要后，服务创建模拟并返回 Portal 链接。

用户同意开启，意味着授权该版本持续进行模拟，不需要逐笔确认模拟订单；不包含真实交易或未经确认的规则变更。

Portal 空页面只有说明和“去对话开启”入口。该入口可以携带意图进入对话，但不能直接激活模拟。

### 2.2 开启后：用户不回来也继续运行

系统每日按交易日历处理已冻结订单、估值、选股和下一交易日的决策，形成日报。没有买卖也生成记录，解释是无条件命中、继续持有、无法成交还是数据不完整。

用户打开 Portal，可立即看到：是否正常运行、数据更新到哪一天、模拟净值、今日动作、当前持仓、历史交易及周报。用户也可以在对话中询问某次买卖，AI 从同一份账本读取依据。

### 2.3 每周：系统主动形成复盘

周报自动出现在策略模拟页面，分析本周和启动以来的表现，给出“继续观察 / 建议调整 / 建议停止”及理由。用户可以进入对话讨论具体建议。

用户不回应时，原规则继续运行。没有足够证据时，周报可以没有修改建议；不得为了体现“进化”每周硬改一次策略。

首版默认 Portal 内提示新周报，不另加每日微信推送；微信摘要作为后续可选通知能力，不影响模拟或报告是否完成。

## 3. 策略开启条件与澄清机制

检查的是“规则是否可执行”，不是预先判断策略是否赚钱。

| 必需内容 | 必须回答的问题 |
| --- | --- |
| 标的范围与数据 | 哪个市场、哪些证券；指标定义、数据来源和更新时间是否可满足？ |
| 选股 | 条件、周期、阈值、候选过多时的排序及并列处理是什么？ |
| 买入 | 何时产生信号；是否允许重复买入、加仓；订单何时执行？ |
| 卖出 | 退出条件、优先级；是否减仓；同一天买卖条件冲突如何处理？ |
| 仓位 | 每个标的占比、总仓位上限、持仓数量限制、现金不足时的选择与分配？ |
| 日频适配 | 是否明确接受收盘判断、下一交易日执行，而非盘中触发？ |
| 模拟口径 | 成交条件、成本、未成交、公司行动、估值缺失和基准如何处理？ |

初始净值 1 不消除仓位规则。相同的选股结果，等权买入与集中持仓会有不同的组合收益和风险。AI 可提出仓位默认建议，但须在开启摘要中明确，并由用户确认；不能暗中默认全仓。

“趋势良好”等模糊条件有两种处理：澄清成确定性条件；或声明为 AI 判断环节，固定输入范围、判断要求、输出结构和未知时的处理方式，保留每次输入、依据及模型/提示版本。关键交易条件仍无明确执行责任时，不允许开启。

区分两种阻塞：

- **规则缺失**：继续澄清，保留草稿，可以跨会话恢复。
- **能力不支持**：说明具体缺失。例如需要盘中止损或当前无法获得的指标，不能以代理或日频规则静默替代。经用户确认修改成可支持的版本后重新校验。

### Skill 与服务的分工

建议新增产品 Skill `strategy-simulation`，负责选择策略、检查语义缺口、低负担提问、解释默认口径、请求确认及解释结果。Skill 不是执行闸门。

服务层必须强制：用户隔离、结构校验、受支持规则与数据能力校验、版本绑定、确认、幂等开启和审计。仅字段非空不代表规则可执行；执行器不认识的条件必须拒绝，不能将任意自然语言直接当作可执行规则。

确认绑定准确的草稿 revision 与策略快照。确认后若内容变化，旧确认失效。开启前检查当前数据访问能力；后续临时失效进入受阻状态，不能因曾通过检查就继续伪造结果。

读取既有策略不修改用户原文件。新 Skill 模板也不能自动覆盖真实 Workspace；已有用户采用模板资产遵守项目逐用户、逐文件的确认与备份规则。

## 4. 日频运行协议（建议默认值）

首期执行适配器建议限定 A 股股票、只做多、无杠杆。其他资产不能只改名称就套用成交与交易日规则。

### 4.1 时间顺序

1. D 日收盘数据就绪后，先结算之前已冻结、计划在 D 日开盘执行的订单，再按 D 日收盘数据估值。
2. 使用截至本次决策时点可得的数据，依据冻结规则判断买卖，保存全量候选、筛选理由和未选原因，形成 D+1 交易日订单。
3. 订单必须在目标开盘前冻结；启动过晚、数据晚到或决策超时，不得补记为当天开盘成交。记录错过本次窗口，等待下一轮有效决策。
4. 下一次取得对应交易日数据后，用实际开盘行情和交易状态核验订单，记录成交或未成交。可以收盘后入账，但不能利用当天后续表现修改此前订单。
5. 日报展示当日入账、收盘持仓和下一交易日待执行订单，明确“信号日 / 模拟成交日 / 入账时间”的差异。

因此首版不依赖盘中决策服务，也不宣称开盘时就已实时更新账本。页面明确最近结算日与待结算状态。

### 4.2 成交与记账

- 采用归一化虚拟现金和虚拟数量，允许分数单位；组合起始现金和净值均为 1。前台以仓位百分比和收益率展示，不强迫换算人民币。
- 分数单位模型不模拟真实账户整手约束、固定最低佣金和规模冲击；明确标为归一化日频模拟，不能冒充可逐笔复制的真实账户。
- 默认成交参考为目标交易日未复权开盘价。核验交易日、停牌、涨跌停和必要交易状态；缺少可成交证据时标记未成交或待核验，不能仅凭存在价格就成交。
- 首版可采用保守口径：开盘触及涨跌停的相关订单不假定成交，展示该假设；无盘口证据不推断排队成交。
- 默认订单仅对目标交易日有效；未成交不自动追价或递延，下一轮按策略重新判断。卖出失败则继续持仓并记录风险暴露。
- 同日默认先处理卖出、再处理买入；资金只有在卖出实际模拟成交后释放。买单采用事前确认的排序和仓位算法，不因当天涨跌临时改变顺序。
- 遵守市场 T+1 等约束；不允许负现金、卖空或超出确认的仓位上限。成本占用纳入资金检查。
- 建议基线综合摩擦为单边 10 bp，另展示单边 30 bp 敏感性；两者都是统一假设，不冒充真实税费。参数随运行版本固定，同时展示毛收益与扣成本收益。
- 持仓按收盘价估值，现金默认不计息。技术指标可用明确的复权口径，但成交与现金分红、拆合股等必须一致处理，避免复权收益与分红重复计算。
- 缺少持仓估值或公司行动数据时，标记估值不完整；可显示带日期的最后已知数值，但不能作为当日有效净值参与正式指标。数据恢复后修订须可追溯。

### 4.3 调度、失败与生命周期

基于交易日历和数据就绪条件触发，不能把周一至周五直接等同交易日。每个模拟、交易日、运行阶段有幂等键，调度重试不能重复订单或成交。

业务状态：草稿、待澄清、待确认、运行中、暂停、已结束；另以每日运行健康标识正常、受阻、失败，避免把一次失败误判为用户暂停。

建议暂停语义：暂停新决策，取消尚未执行的订单，保留持仓并继续可用估值；明确暂停期间不执行退出规则，该区间不能宣传为策略全程执行结果。恢复从下一合法决策窗口开始，不回补假想交易。

结束保留完整历史和未平仓持仓估值，不伪造清仓；胜率仍只统计已完成交易。首版暂停、恢复、结束均经对话调用具名能力，Portal 提供“去对话管理”入口。

行情失败、账本失败、报告失败分别记录：报告失败不回滚已记账交易；账本失败不发布成功日报。只重试失败阶段。缺失的历史 AI 判断不能用今天的知识补写成当时决策。

## 5. 指标：用百分比评价，但不混成一个正确率

| 指标 | 首版口径 |
| --- | --- |
| 净值 | 现金加持仓估值，初始为 1；净值 1.08 对应累计收益 +8% |
| 累计收益率 | 当前有效净值 / 初始净值 − 1 |
| 日 / 周收益率 | 当前期末有效净值 / 上一期末有效净值 − 1；首周从启动净值计算并标注非完整周 |
| 最大回撤 | 从有效每日净值序列计算峰值到后续低点的最大跌幅；标注为日频收盘回撤，不是盘中回撤 |
| 胜率 | 扣基线成本后盈利的已完成交易数 / 全部已完成交易数；盈亏为零单列且仍计入分母 |
| 平均盈利 / 亏损与盈亏比 | 按已完成交易净收益率分组计算；没有亏损样本时不伪造有限盈亏比 |
| 基准对照 | 建议沪深 300，同起点归一化；显示同期收益差（百分点），注明行业/风格差异未消除 |
| 证据完整性 | 已完成交易数、未平仓数、运行交易日、未成交数、缺失与异常日期 |

一笔“已完成交易”默认是同一证券从空仓建仓到全部平仓的持仓周期；加仓和分批卖出归入同一周期，以累计买入成本为收益率分母。它是交易统计口径，不替代按每日仓位计算的组合收益。

没有已完成交易，胜率显示“暂无已平仓样本”，不能显示 0%。未平仓浮盈进入净值，但不算胜率。净值存在缺口时，指标展示缺口或不完整状态，不静默连线伪造连续表现。

胜率不是策略正确率：高胜率仍可能因少数大亏而亏损。页面同时展示收益、回撤、胜率及样本量。首版不把短期结果年化后作为主指标，不设跨所有策略通用的“合格胜率”。

## 6. Portal 页面

新增一级业务入口“策略模拟”，实现位置为本仓库 `apps/portal`。

页面层级：模拟列表 → 单个模拟详情 → 某日记录 / 某周报告 / 策略版本。

| 区域 | 用户看到的内容 |
| --- | --- |
| 模拟列表 | 名称、策略版本、运行状态、累计收益、最近更新；多个模拟独立展示，不合成账户收益 |
| 详情顶部 | 初始净值 1、当前净值、收益率、回撤、胜率与样本量、数据截至日期 |
| 表现 | 净值与基准曲线；明确缺口、暂停区间、成本口径和版本起点 |
| 今日 / 日历 | 当日候选、买卖、未成交原因、无操作原因、日报、下一日订单 |
| 持仓与交易 | 仓位占比、买卖日期、收益率、信号依据、关联规则和数据来源 |
| 每周复盘 | 本周与累计结果、典型成功和失败案例、未知项、改进建议、去对话讨论入口 |
| 策略与规则 | 冻结的策略摘要、模拟约定、来源版本、与后续版本的变化 |

运行失败时顶部明显显示原因和最后成功日期；旧报告仍可查看，但不能让旧数据看起来像今天的成功结果。移动端保留同样的信息和入口，不要求依赖大表格查看核心状态。

Portal 与聊天读取同一事实源，AI 报告里的数值来自服务统计，不由模型重新计算。日报/周报不是易过期的临时聊天附件，随模拟历史保留。

## 7. 每周复盘怎样帮助策略进化

报告固定回答：本周执行了什么、结果怎样、哪些规则值得关注、证据有多强、下一步建议是什么。

建议必须关联具体交易、候选、规则和数据；同时列反例、样本量及不确定性。区分策略问题、数据问题和执行器问题，不能因数据缺失就建议修改投资规则。

建议结构：发现 → 证据 → 可能解释 → 建议改变的一个条件 → 下轮如何验证。结论可为继续观察、建议调整、建议停止；后两者不自动执行。

首次可先通过一个策略产出建议并完成澄清验证。用户正式采纳改进时，建议创建关联的新版本模拟，初始净值仍为 1，旧版本保留；不在旧成绩中途静默替换规则。

多个独立模拟支持后，可让原规则和新规则从同一未来时点、相同初始条件进行对照。旧版本全历史收益与新版本短期收益不能直接排名为改进证据。发现问题所用的历史样本与检验新规则的后续样本分开标记。

系统自动完成的是执行、记录、评价和建议的反馈循环；正式规则演进仍由用户确认。用户一周不回复，不阻塞原版本继续运行。

## 8. 技术职责与接入边界

本节是工程设计输入，不宣称已经具备模拟引擎。现有文档存在旧 ACP、旧 Portal 仓库及候选分支说明，实施以 `AGENTS.md` 指定的当前 `main` 与同仓 Portal 为准，不按旧拓扑新建旁路。

| 层 | 职责 |
| --- | --- |
| 对话与产品 Skill | 意图、策略语义澄清、解释规则、申请确认、解读复盘 |
| 服务 / MCP | 草稿与状态机、能力检查、确认与 scope、冻结版本、账本、指标、幂等与审计 |
| 调度与执行器 | 交易日和数据时点、信号求值、模拟订单结算、失败恢复、日报周报触发 |
| 外部数据能力 | 行情、交易状态、指标输入、公司行动及基准，保留来源/as-of/质量信息 |
| Portal | scoped 读取、状态与结果展示、跳转到关联对话，不成为第二个事实源 |

建议领域对象：SimulationDraft、Simulation、StrategySnapshot、DailyRun、SignalDecision、Order、Fill、Position、NavPoint、WeeklyReview、EvolutionProposal。每个对象绑定用户作用域和 simulationId；运行记录同时绑定规则版本和来源快照。最终表结构需后续工程设计核对现有持久化约定，不把上述名称直接当成已确定表名。

建议具名能力覆盖：读取可选策略、保存/读取澄清草稿、校验、请求开启确认、确认开启、查询状态/记录/报告、暂停/恢复/结束、提出和采纳新版本。具体工具名称和路由在工程阶段确定，共享同一服务语义，不新增通用 YAML 写入接口。

服务持久化是模拟账本和统计的唯一事实源；Workspace 中的策略资产作为来源，报告文件为可阅读产物。禁止让 AI 直接编辑 CSV/Markdown 充当订单、持仓或净值权威账本。

调度复用现有任务运行、锁和审计基础，但模拟执行是有确定性状态的业务流程，不能只创建一句“每天按策略交易”的自由文本自动化任务。周期已授权执行与用户改规则确认分开设计。

工程接入优先核对：`src/mcp/service-tools-core.ts`、`src/db/schema.ts`、`src/lib/mastra-strategy-library.ts`、`src/services/automation-tasks.ts`、`src/services/automation-runner.ts`、`src/scheduler/`、`src/portal/` 和 `apps/portal/src/`。这些是待核对接入点，不代表所有现有能力均可直接复用。

## 9. 实施顺序与验收

### 阶段一：单策略纵向闭环

在隔离用户和测试数据中完成：对话澄清 → 确认开启 → 至少两个连续交易日的信号/结算 → 日报 → 跨周报告 → Portal 查看 → 进化建议回到对话。首先证明状态和账本正确，不用收益好坏判断功能是否完成。

### 阶段二：多个独立模拟与版本验证

允许同一用户运行两个以上独立模拟，复用第一阶段能力；完成作用域、资金隔离、并发重试和同策略版本衍生验证。多模拟是本设计的后续交付阶段，不仅是增加 simulationId 字段便宣称已支持。

### 阶段三：真实数据前向试运行

在用户明确采用具体策略版本后，开启限定范围试点，检查自然交易日更新和首份自然周报。隔离测试通过不等于真实用户策略已通过，也不自动授权修改 mg 资产或发布生产。

| 验收项 | 可观察的通过条件 |
| --- | --- |
| 缺口澄清 | 缺少退出/仓位规则时不可激活；AI 能说明具体缺口并恢复草稿 |
| 能力闸门 | 盘中规则、不支持指标及数据访问失败不能假装通过；日频改写须明确确认 |
| 开启确认 | 仅对话可首次开启；准确版本确认、过期确认拒绝、重复确认只创建一个模拟 |
| 持续执行 | 无用户日常输入仍按交易日运行；无信号日也有完整记录 |
| 无前视 | 决策在目标成交时间前冻结；晚到任务和今天的 AI 知识不能制造过去成交 |
| 财务正确 | 已知价格路径可重算净值、成本、仓位和收益；买卖失败、分批交易、公司行动有明确结果 |
| 指标边界 | 零平仓胜率为暂无；未平仓不混入胜率；成本、缺口与样本量可见 |
| 幂等恢复 | 重复调度/重启不重复成交；报告失败不破坏账本；受阻状态可见 |
| Portal 体验 | 在真实浏览器检查开启引导、详情、日记录、周报、错误态和移动端，数字与账本一致 |
| 建议可追溯 | 周报引用真实记录、区分原因；没有证据允许不建议改动；未经确认不改变规则 |
| 多模拟 | 两个模拟各自净值 1、持仓及记录互不污染，用户隔离有效，新旧版本历史保留 |
| 自然运行 | 单列真实行情、自然调度及真实用户体验证据，不能用 fixture 结果代替 |

所需测试集中在业务边界：规则闸门、确认与隔离、时间因果、账本和指标、重试恢复、浏览器主流程。工程阶段按实际改动遵守 service-api-change、db-migration 等项目流程，不为本文新增实现镜像测试。

## 10. 尚需工程验证的事项

- 当前数据能力能否稳定提供开盘/收盘、交易状态、公司行动、所选策略指标及基准；缺失项决定可开放的策略范围。
- 既有策略资产、版本及确认能力的复用程度，不能只依据旧文档认定支持。
- 收盘数据就绪的具体触发和截止时间、自然周周报时间、并发配额及资源预算；在工程设计中给默认值，不再要求用户填写技术参数。
- 基准、成本及异常成交的建议口径在实现前形成版本化执行协议，开启时向用户展示。

这些属于落地验证，不改变本轮已确认的产品目标。若发现核心策略无法日频表达或数据能力不足，应明确缩小试点对象，不静默换成另一套投资方法。
