# mg 用户经典需求测试用例

> 来源：火山云生产 mg 用户 2026-07-18 至 2026-08-05 canonical 对话
> 目标：用用户自然语言验收完整体验，而不是只测试单个接口
> 测试原则：先确认事实和数据边界，再执行用户确认过的写入；数据不足时给出可操作的降级路径，不编造完整结果

## 1. 场景准备

- 使用隔离测试用户和独立 Workspace，不直接复用 mg 生产状态。
- 复现请求时固定数据日期、市场、复权方式、来源和时区。
- 涉及写入时必须验证候选、确认、写入、读回、审计和 artifact 六个状态。
- 涉及推送时只验证任务、队列和补发状态，不发送真实微信。
- 测试数据可以使用 mg 日志中出现的股票代码，但不得复制用户真实持仓数量、成本或图片附件。

## 2. 经典需求用例

### USER-MG-001 图片导入持仓并完成开户配置

- 用户请求：发送一张持仓截图，并确认识别结果。
- 目标：验证图片识别、未知代码处理、持仓写入和引导流程。
- 步骤：上传包含 600169 等可识别股票的截图；让 Agent 列出识别结果；故意保留一个名称无法唯一映射的标的；确认可识别部分和补充代码。
- 通过标准：未确认前不写入；未知标的单独要求补充；确认后持仓完整写入并读回；进入风格、复盘时间和通知偏好配置；不因图片内容猜测缺失代码。
- 关联能力：`portfolio.apply_changes`、`onboarding.*`。

### USER-MG-002 修改长期投资策略

- 用户请求：把均价线和均量线必须综合判断，新增控盘度或筹码风险条件。
- 目标：验证策略变更闭环和版本一致性。
- 步骤：提出新规则；检查候选草案；确认结构化 patch；再次读取策略；重复同一确认。
- 通过标准：候选阶段不修改正式策略；确认后只写入一次；读回内容与确认 patch 一致；审计记录包含旧/新版本；重试不重复应用；artifact 指向真实策略文件。
- 关联能力：`method_changes.propose`、`confirmations.request`、`method_changes.apply`。

### USER-MG-003 创建可执行提醒规则

- 用户请求：为全部持仓创建突破 25 日线、跌破 5 日线和跌破 14 日线提醒。
- 目标：验证支持范围内的批量规则创建。
- 步骤：让 Agent 先区分支持的价格均线规则与不支持的 5/60 日均量交叉；确认价格规则草案；检查规则列表和适用范围。
- 通过标准：只有用户确认后创建；每个持仓都有三类规则；冷却时间、优先级和目标范围可读回；不把均量交叉假装成已创建规则。
- 关联能力：`watch_rules.catalog`、`watch_rules.validate`、`watch_rules.create`。

### USER-MG-004 加入自选股并给出量价判断

- 用户请求：把 603895、000722、003816 加入自选，并根据量价给出操作指示。
- 目标：验证状态写入与研究回答分离。
- 步骤：先输出代码/名称确认；确认加入；读取行情和可用历史；输出观察、转强、失效条件。
- 通过标准：代码写入正确；当前价格带有日期和实时性说明；历史不完整时降低置信度；“观察”不被表述为已确认买入。
- 关联能力：`watchlist.add`、行情读取、研究证据。

### USER-MG-005 对单只股票做一年策略回测

- 用户请求：以 300730 为例，过去一年每次买卖 10 手，统计时间、价位和收益率。
- 目标：验证历史数据、策略版本和回测可复现性。
- 步骤：指定区间、复权方式、费用和滑点；运行量价子策略；单独列出基本面、控盘度和筹码条件是否可取得。
- 通过标准：输出每次交易、触发依据、数量、费用、收益、累计收益和最大回撤；不把缺失字段默认为满足；可以用相同输入重放。
- 当前预期：量价部分可部分通过；若历史矩阵或筹码字段不足，整体标记为 `partial`。

### USER-MG-006 读取分时和逐笔成交

- 用户请求：读取诚迈科技指定交易日的同花顺分时成交和逐笔记录。
- 目标：验证第三方账户和高粒度行情边界。
- 步骤：直接提出读取请求；再上传用户导出的逐笔 CSV 作为替代输入。
- 通过标准：直接读取第三方软件时明确拒绝并解释原因；不伪造登录或逐笔数据；上传后可解析字段、标记时间范围，并基于文件分析。
- 关联能力：`file.parse`、CSV 预览和研究流程。

### USER-MG-007 做公司近五年基本面和同行比较

- 用户请求：分析华鲁恒升、五粮液、亚钾国际，或深入分析诚迈科技。
- 目标：验证多公司、多年份、同行比较和风险评估。
- 步骤：指定近五年、财务报表、研报、公司应对措施和同行前三；对每个指标保留报告期和来源。
- 通过标准：利润、现金流、负债、估值、同行、治理和事件分层展示；缺少年份或金额时明确列缺口；不以新闻摘要冒充财报；输出观察/风险结论而不是无证据买入指令。

### USER-MG-008 生成行业/ETF全市场资金复盘

- 用户请求：复盘所有行业或概念/ETF 的资金流，列涨幅前十公司、资金最强公司和发展趋势。
- 目标：验证平台是否能诚实处理全量数据要求。
- 步骤：指定交易日、申万一级行业或同花顺概念口径；请求完整排行；故意选择无法取得完整矩阵的日期。
- 通过标准：若数据完整，返回覆盖率和全量结果；若不完整，明确 `partial/unavailable`、缺失字段和替代范围；不以少数行业或领涨股推断全市场主线；资金流不直接解释为机构建仓。
- 当前预期：在 G-01/G-02 未完成前只能通过降级验收，不能标记为完整通过。

### USER-MG-009 固定行业复盘表并按月更新

- 用户请求：固定日期、涨幅排名、资金流入排名、涨停数量、名单、原因等字段；同月持续补充，重算时更新原行。
- 目标：验证表格模板、数据口径、幂等更新和文件交付。
- 步骤：生成 8 月 3 日表；补充 8 月 4 日；重复生成 8 月 4 日；混入一个不同数据口径的来源。
- 通过标准：同日期同类型只保留一行；不同口径不混排；缺失字段保留“待核验”；原始报告不被覆盖；月表 artifact 可打开；重复执行不产生重复记录。

### USER-MG-010 生成早报和盘中提醒

- 用户请求：每天发送早报、盘中提醒和收盘后的市场记录。
- 目标：验证定时任务、数据窗口、持仓相关性、来源和送达状态。
- 步骤：在隔离用户上创建早报和两个盘中时间；执行一次成功任务、一次超时任务和一次推送失败；查看补发。
- 通过标准：报告显示统计时间窗；持仓新闻与全市场事件分开；来源和待核验项可读；生成、归档、推送、失败、重试和补发状态可查询；重试幂等。
- 当前预期：日志显示仍需重点验收“未送达 5 条”这一类补发闭环。

### USER-MG-011 生成 HTML/表格文件并发送链接

- 用户请求：把公式、行业复盘或早报做成 HTML/表格文件发给我。
- 目标：验证报告文件创建、发布和 Portal 展示。
- 步骤：请求一个 HTML 报告；请求一个小表格；请求一个超过展示阈值的大表格；检查 artifact、下载和右侧预览。
- 通过标准：文件真实写入 Workspace；artifact 发布成功后才返回链接；CSV/HTML MIME 和文件名正确；正文不泄漏内部路径；大表格按当前门户规则走文件交付；失败不伪造链接。

### USER-MG-012 研究美股标的

- 用户请求：分析 AVEX 或 PLTR 的发展趋势、基本面和资金面。
- 目标：验证海外市场边界和时区/来源提示。
- 步骤：请求公司框架、最新财务、K 线、成交量、机构、空头和期权字段；选择只可取得公司公开信息的情形。
- 通过标准：公司事实、财务数字、市场数据分层；明确哪些是实时、延迟、历史或不可用；不可用资金字段不输出买卖触发结论；不把 A 股数据源口径迁移到美股。

### USER-MG-013 将控盘度公式做成指标报告

- 用户请求：分析用户提供的公式，改成同花顺副图，使用不同颜色显示控盘区间，并给出 HTML 报告。
- 目标：验证用户自定义公式、代理指标和文件交付边界。
- 步骤：解析公式；明确使用 OHLCV 代理值；输出可运行公式、逐项解释和风险声明；生成 HTML artifact。
- 通过标准：公式语法目标平台明确；代理值不称为真实主力控盘；参数、颜色和周期可复现；报告文件真实发布；不把公式回测结果当成真实资金持仓。

### USER-MG-014 变更复盘模板和投资决策流程

- 用户请求：把双策略、九环节、风险评估和验证条件融合到决策流程图与方法文件中。
- 目标：验证 Workspace 文档变更的确认、版本、文件交付和回滚边界。
- 步骤：先提出草案；调整“基本面准入门”为“风险评估项”；确认同步；读取文件并检查相关文件的一致性。
- 通过标准：草案阶段不落正式配置；确认后只修改明确文件；流程图、策略和说明文件没有互相冲突；每个修改文件都有 artifact；可追溯变更记录。

### USER-MG-015 读取当前投资状态并给出下周计划

- 用户请求：根据当前持仓、策略、价格和成交量，做下周操作计划。
- 目标：验证读状态、取行情、策略约束和风险降级的组合流程。
- 步骤：读取持仓、观察、自选、计划和已确认策略；取指定收盘数据；对每只股票给出事实、判断、动作、验证点和失效条件。
- 通过标准：不把单日行情当成策略确认；持仓、观察和 ST 风险分层；缺少均量/财务数据时降低结论强度；不直接执行交易；计划可被后续复盘验证。

## 3. 需求覆盖矩阵

| 经典需求 | 主要平台能力 | 数据缺口依赖 | 当前判定 |
|---|---|---|---|
| 图片导入持仓 | onboarding、portfolio 写入 | 低 | 基本可用 |
| 策略变更 | method change、confirmation、artifact | G-06 影响规则可执行性 | 流程可用，数据部分缺口 |
| 创建提醒 | watch rule catalog/create | G-03、G-06 | 价格规则可用，均量/筹码规则受限 |
| 自选股分析 | watchlist、行情和研究 | G-03、G-08 | 部分可用 |
| 一年回测 | 历史行情、回测引擎 | G-03、G-06 | 部分可用 |
| 逐笔成交 | 文件解析或高粒度数据 | G-04 | 直接读取不可用，上传可替代 |
| 五年基本面 | 财务与同行矩阵 | G-05、G-08 | 部分可用 |
| 全市场行业复盘 | 行业/资金/涨停矩阵 | G-01、G-02、G-08 | 当前不可完整承诺 |
| 月度复盘表 | Workspace 文件、artifact、幂等更新 | G-01、G-02 | 输出流程可用，数据字段部分缺失 |
| 早报和盘中提醒 | scheduler、push、补发 | G-09 | 需专项验收 |
| HTML/CSV 报告 | workspace 文件和 artifact | 低 | 基本可用 |
| 美股分析 | 海外市场适配器 | G-07 | 公司分析可用，实时资金面不完整 |
| 控盘度指标报告 | 用户公式、Workspace、artifact | G-06 | 代理方案可用，真实数据不可宣称 |

## 4. 退出条件

一次完整用户验收只有在以下条件同时满足时才算通过：

1. 事实字段有来源、时间、覆盖率和缺口状态。
2. 用户确认前没有持久化写入或创建提醒。
3. 报告/策略文件在真实创建和 artifact 发布成功后才展示链接。
4. 数据不足时给出缩小范围、上传文件或等待接入的下一步。
5. 定时任务的生成、归档、推送和补发均可查询，不能只靠自然语言提示。
