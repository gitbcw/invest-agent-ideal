# Implementation Standards

```yaml
implementation_standards:
  facts:
    - "代码只能作为证据，不能自动升级成需求。"
    - "业务意图优先于实现细节。"
    - "高风险输出必须分离事实、推断和建议。"
  standards:
    - "所有关键结论都要有 evidence 和 confidence。"
    - "低置信度内容不得写成强制需求。"
    - "策略、预案、复盘、模型是四个不同层次，不要混写。"
    - "工作空间承载用户方法，服务承载确定性执行。"
    - "复杂能力先尝试标准方案，再考虑规则树，最后才考虑沙箱脚本。"
  output_quality:
    - "文档必须可供后续 Agent 独立重设计。"
    - "不得只是项目介绍或周报式总结。"
    - "不得复制旧技术架构名词而不抽象业务职责。"
```
