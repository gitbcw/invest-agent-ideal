# 当前状态总览

更新时间：2026-10-06

## 一句话判断

Invest Agent 已进入生产运行，核心架构和服务边界基本成型；当前阶段的核心不是继续堆功能，而是验证两条主线是否真正带来“越用越好用”：UI 显性化与交互优化，以及 W7 Agent Space 重构后的 Agent/Skill/方法/任务/版本上下文体验。MG 三闭环是这两条主线上的延伸验收，不是新的独立产品主线。

## 已经成立的事实

- 当前生产基线是 `main`；Mastra 主线已接管生产运行。
- Portal、微信、Workspace、服务层、MCP、调度、推送、审计和发布/回滚基础已在真实链路运行。
- 服务层负责权限、确认、幂等、审计、调度和投递等确定性边界；Agent 负责理解、规划和投资判断。
- 程序可靠性闭环较强：测试、超时/重试、Trace、巡查、快照和回滚链已具备。
- 客户策略指标化和 MG 三闭环已有基础证据，但不代表完整策略模拟或自动策略进化已经成立。

## 当前阶段在做什么

### 主线一：UI 显性化与交互优化

- 让用户能看懂当前状态、事实、缺口、失败、任务和产物分别是什么。
- 让对话、Portal、Skill 管理、方法管理和自动化结果之间的关系更容易回读。
- 继续以真实体验中的明显问题为依据，不为内部实现增加用户不需要的控制面。

### 主线二：W7 Agent Space 重构，验证“越用越好用”

- 把 Agent、用户方法、Skills、任务、资产、运行依据、版本、确认和回滚放进清晰的对象边界。
- 让 Agent 进入项目时先获得正确的原则、系统论、用户方法和 Skill 上下文，而不是把整个 Workspace 或历史文档混成提示词。
- 保持用户方法和 Skill 可演化，同时让正式采用、运行生效、历史版本和回滚彼此分离。

### 延伸验收：MG 业务闭环

- 全持仓与关注对象筛选、可靠性分层/失败降级、策略候选确认/采用/回读/回滚已经完成隔离或真实链路验收，状态以各自记录为准。
- 当前重点是用户继续体验 MG，观察是否存在明显的理解、显性化或行动边界问题，不再扩大更多行情编排。

### 探索项：策略模拟与 Agent-first 回放

- 已有 fixture 执行器、日报/周报、候选和版本承接原型，用于验证基础设施方向。
- 当前先验证 Agent 能否理解用户方法并给出有边界的参考判断；不先建设用户维护的业务级结构化节点，也不把自然语言策略宣称为完整历史回测。

## 尚未毕业的门槛

- 语义错误发现仍慢于程序错误发现；语义回归门两级形态经首两份 SCR 实战（2026-09-06 发布）并于 9-12 观察窗口收口（业务终态栏 pass；owner 裁决提前收口）。
- 诊断链生产覆盖率已实测（2026-09-06 首轮 99.6% 串通；9-12 终局复测 GAP-1 断链归零未回升、S7 三率 100%）；GAP-2 遗留一行 n.a. 白名单补登待下次白天发布；发布记录纪律已恢复逐次记录。
- 评估样例、用户反馈和跨场景效果证据仍在扩充，不能把局部测试通过等同于可扩大范围（扩大范围前置条件见 governance-review-2026-09-06.md 与 2026-09-12 增量：条件①②已达成，③待 owner 裁决 BC 关闭）。
- “越用越好用”目前已具备结构基础，但长期用户价值仍需通过实际体验和上下文质量继续验证。
- MG 自然语言策略尚未成为完整、可复现的历史回测协议；缺少上下文或数据时必须保持未知/受阻。
- Agent 上下文入口、原则和系统论刚完成初步收敛，后续仍需检查不同入口是否加载了同一套项目定位。

## 不属于当前阶段的工作

- 继续扩展更多行情工具编排或把策略模拟直接做成完整量化平台。
- 在没有用户体验证据前，把局部回放或 fixture 测试宣布为策略有效或 Agent 已经可靠。
- 把用户的模糊判断强行转写成开发者决定的节点、阈值或代码。
- 以商业化、泛化多租户或大规模平台化为优先目标。
- 在治理证据不足时继续堆叠与真实摩擦无关的新功能。
