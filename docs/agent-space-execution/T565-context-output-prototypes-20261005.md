# T-565 上下文输出样例：默认层与展开层

日期：2026-10-05  
依据：[T-565 上下文与决策体验治理基线](./T565-context-decision-governance-baseline-20261005.md)  
用途：验证同一案例在不同风险和追问深度下，Agent 应该展示多少上下文

## 1. 样例对象

对象：湖南发展 `000722`  
身份：关注股，不是当前持仓  
场景：用户询问“这只现在要不要继续看？”  
已知边界：历史资料中存在价格口径冲突，60 日均量和筹码方向缺少完整证据。

## 2. 默认回答：低负担决策层

> 建议：继续观察，暂时不做买入判断。
>
> 原因是前期放量后出现回撤，关键的成交量确认还不完整。接下来重点看两件事：收盘能否重新站稳关键均线，以及成交量是否同步恢复。
>
> 你现在只需要决定一件事：是否把它加入明日观察清单？

这一层只提供：结论、一个主要理由、两个观察方向、一个用户决定。它不展示评分、规则编号、P0/P1、代理值或完整缺口清单。

## 3. 用户追问“为什么只是观察”：解释层

> 因为目前有两个限制：
>
> 1. 价格从高位回撤后，还没有重新证明趋势恢复；
> 2. 成交量确认所需的历史数据不完整，所以不能把“看起来放量”当成已确认信号。
>
> 因此它适合继续跟踪，但还不足以进入行动确认。

这一层解释“判断依据”和“为什么不能更进一步”，但仍不要求用户理解完整评分公式。

## 4. 用户追问“具体缺什么”：证据层

> 目前缺少或存在冲突的证据主要有：
>
> - 60 日均量没有可靠的完整序列；
> - 筹码方向缺少至少两个时点的历史记录；
> - 同一交易日出现过两个收盘价口径，需要统一来源和时间戳。
>
> 所以当前可以支持“继续观察”，但不能把量价条件写成“已经满足”。这不是判断看空，而是证据不足以支持更强结论。

这一层才出现“证据缺口”和“口径冲突”，并且每个术语都紧跟用户能理解的含义。

## 5. 高风险场景：用户问“能不能买入”

> 目前不能给出买入确认。
>
> 不是因为已经判断它一定会下跌，而是买入所需的几个条件中，成交量确认和部分历史数据还没有被可靠验证。当前最稳妥的动作是继续观察，等数据补齐并重新核对后再判断。
>
> 如果你要继续推进，我可以下一步只做一件事：把“买入确认需要满足的条件”列成清单，供你逐项核对。

高风险场景默认提高解释深度，但仍然围绕用户要做的决定，不直接输出内部治理信息。

## 6. 用户问“提醒为什么没来”：执行层

> 这次没有产生提醒，当前能确认的是：这个对象目前没有绑定盯盘规则。
>
> 所以这不是“条件未满足后的正确静默”，而是“没有进入自动提醒范围”。如果你希望自动跟踪，需要先单独确认观察规则；系统不会自动替你创建。

这里必须把“没有触发”和“没有规则”分开，否则用户会误以为系统已经判断过但选择不提醒。

## 7. 同一信息在不同层级的表达规则

| 信息 | 默认层 | 解释层 | 证据层 |
|---|---|---|---|
| 当前判断 | 继续观察 | 说明为什么不是行动确认 | 展示对应证据与限制 |
| 数据缺口 | “证据还不完整” | 说明缺口影响哪一步 | 列字段、日期、来源和冲突 |
| 规则状态 | 通常不出现 | 用户问提醒时出现 | 展示规则归属和审计记录 |
| 评分 | 默认不出现 | 只有影响结论时简述 | 用户要求复算时展开 |
| 策略版本 | 默认不出现 | 只有涉及变更时出现 | 展示版本、差异和回滚线索 |

## 8. 样例验收问题

用下面的问题人工检查输出是否在合适的层级：

1. 用户只读默认回答，能否知道自己现在要决定什么？
2. 用户不懂“代理值”时，是否仍能完成当前决定？
3. 用户追问后，能否逐层获得依据，而不是重新收到一份完整审计报告？
4. 高风险情况下，系统是否主动说明关键缺口，而不是只给“继续观察”？
5. 没有规则、没有触发、数据不足三种情况，是否能被用户区分？
6. 输出是否把“消息送达”“条件成立”“用户应行动”分成不同概念？

## 9. 当前结论

这组样例支持以下产品方向：

- 默认层不是简单化结论，而是“当前决定所需的最低充分上下文”；
- 展开层按用户追问逐步增加，不一次性倾倒全部内部信息；
- 风险升高时自动提高解释深度；
- 证据缺口必须保留，但要说明它阻断的是哪一个结论，而不是只列术语；
- 规则和运行状态只在与当前问题直接相关时出现。

下一阶段可以把这套分层规则转成 Agent 输出指导，并在不改变业务结果的前提下做隔离会话验证。
