# T-567：MG 策略改进候选草案

日期：2026-10-05  
状态：草案，未确认、未采用、未修改正式策略  
环境：本地 `production-mirror` 的 P0/P1/P2 只读验证结果

## 1. 候选目标

让“判断 → 后续行动 → 结果反馈 → 下一次判断”形成可回看的闭环，同时不把数据缺口、观察信号或一次性推断误写成正式策略。

## 2. 候选规则

### 2.1 证据门槛

- `verified`：本轮已取得、来源和时点明确、口径闭合，可参与判断；
- `proxy` / 二级来源：只能支持观察和方向提示，不得单独触发建仓或加仓；
- `conflicting`：明确列出冲突，不进入评分和行动条件；
- `missing`：受影响结论降级为“待核验”，不以代理值补齐。

### 2.2 行动状态

每个对象只允许处于一个当前行动状态：

- **继续观察**：条件尚未确认，保留触发条件和下一复核点；
- **准备行动**：证据和条件达到预设门槛，但仍不是已执行交易；
- **暂不处理**：证据不足、条件失效或出现硬风险。

“继续观察”不等于看好，“准备行动”不等于买入确认。

### 2.3 提醒承接

- 持仓硬风控：保留即时提醒候选；
- 观察信号：默认进入摘要，不与硬风控共用即时语义；
- 数据缺口：默认静默留痕，不生成交易信号；连续达到阈值后才允许发送明确标注“非信号”的缺口通知；
- 每次提醒单独记录：触发原因、数据时点、投递状态、收盘后是否成立。

### 2.4 版本与确认

- 本草案不覆盖当前正式策略、规则或观察池；
- 进入隔离回放前，固定候选版本和适用对象；
- 回放结束后只输出：保留、修改、拒绝三类结果；
- 用户明确确认后，才生成正式版本；正式采用前保留旧版本和回滚指针。

## 3. 现有证据与限制

支持本候选的证据：

- P0 已发现冲突价格、代理均量和未标时点盘中值不应进入因子评分；
- P1 已发现规则与持仓/关注/预案对象存在错位，且存在疑似僵尸规则；
- P2 影子比较显示“持仓即时、观察摘要、缺口静默留痕”比全部即时提醒更不容易被误读为建仓信号；
- MG 行动状态复验已能输出继续观察、触发条件、失效条件和下一复核点。

尚未证明：

- 生产 MCP 数据完整时，证据门槛是否会误伤正常候选；
- 真实命中、误报、漏报和静默正确的样本是否足够支持参数调整；
- 规则分层在真实投递渠道中是否降低噪声；
- 候选版本回放后是否比当前版本更适合 MG。

## 4. 隔离回放验收

使用 `mirror-mg`，不写生产、不发送微信、不修改正式资产，至少跑三类样本：

1. 数据完整且条件满足：应进入“准备行动”或保持观察，不能直接视为已买入；
2. 数据冲突或缺失：应保持“继续观察/暂不处理”，冲突值不得进入评分；
3. 条件失效或硬风险：应降为“暂不处理”，并记录原因和下一复核点。

每条样本记录：输入对象、固定候选版本、证据状态、行动状态、触发/失效条件、提醒分层、是否产生写入、人工结论。

通过条件：三类样本均能保持证据边界和写入边界，且用户无需理解内部评分公式即可判断下一步。

## 5. 用户确认项

正式进入隔离回放前，只需要确认三件事：

1. 是否接受上述三个行动状态作为用户语言；
2. 是否接受“持仓硬风控即时、观察进入摘要、数据缺口默认静默留痕”的提醒方向；
3. 是否允许以此草案生成隔离回放样本，不影响当前正式策略。
