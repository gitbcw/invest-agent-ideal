# T-562 P2 执行记录：提醒分层与降噪验证

日期：2026-10-05  
环境：`mirror-mg` 本地隔离镜像，OFFLINE 模式  
范围：基于 WF-04 三种影子场景，只读比较“全部即时提醒”和“分层提醒”

## 结果

结论：`Partial`，推荐以策略 B 作为后续草案方向，但尚未进入任何配置或规则变更。

当前镜像中湖南发展 `000722` 没有盯盘规则，因此两种策略在真实当前状态下均产生 0 条规则消息。下文的消息条数是“若该标的已挂规则”的设计推算，不是已经发生的投递事实。

策略 A：全部即时提醒。

- 条件满足：预计 1～2 条即时消息，观察信号容易和风控告警混成建仓信号；收盘回落记误报，守住记命中。
- 条件未满足：0 条消息，但没有“静默正确”的留痕，无法区分引擎未运行与确实未触发。
- 数据缺失：可能静默，也可能因代理值形成伪触发；不确定状态被迫落入命中/误报，污染统计。

策略 B：持仓硬风控即时、观察类进入摘要、数据缺口默认静默并留痕。

- 条件满足：观察类不新增即时消息，进入既有 17:30/19:20 摘要并明确“非建仓信号”；收盘守住记命中，回落记误报，并记录已知延迟。
- 条件未满足：不发新增消息，但保留 1 条静默记录，收盘后可记“静默·正确”。
- 数据缺失：不发交易类提醒，保留 1 条 `data_incomplete` 缺口记录；连续达到阈值时才发送一条明确标注“非信号”的缺口通知，状态仍为不确定。

## 推荐缺省

推荐策略 B，理由是它保留了现有工作流的消息量边界，同时让命中、误报、漏报、静默正确、不确定五类状态可分别统计。即时通道只应覆盖已确认的硬风控事件；25 日线上穿这类观察信号进入摘要，不应和 14 日线跌破同为 P0。

建议草案参数（均待用户确认）：

- 5/14 日线跌破作为即时硬风控，25 日线上穿进入摘要；
- 摘要复用现有 17:30 与 19:20 消息，不新增通道；
- 数据缺口连续 3 个交易日后才升级一条非信号通知；
- 同一逻辑事件每交易日最多 1 次；
- T+0 收盘复核，T+1 补判；静默和缺口记录落文件供周/月复盘引用。
