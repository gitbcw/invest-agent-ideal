# T-563：新手引导、设置与自动化配置边界盘点

日期：2026-09-29
范围：Portal onboarding、Portal settings、自动化任务配置、相关服务契约

## 结论

当前产品把三种不同问题混在了一起：

1. **首次启动**：让用户尽快获得第一次有效结果；
2. **全局偏好**：用户长期希望随时修改的提醒、时间和渠道偏好；
3. **对象配置**：某个自动化、投资模型、策略或 Skill 的具体行为。

应采用以下边界：

```text
新手引导：建立第一次有效上下文 + 选择/接受默认方案
设置：全局、跨任务、低频但可随时修改的偏好
自动化任务：单个任务的时间、输出、投递和输入配置
文件/技能/投资模型：长期业务资产及其版本/生效状态
微信：提醒和轻量补充，不作为唯一配置中心
```

## 当前入口盘点

| 配置项 | 当前入口 | 当前实际语义 | 推荐归属 | 结论 |
|---|---|---|---|---|
| 持仓初始录入 | onboarding 第 1 步 | 形成持仓草案，之后在对话中确认入库 | onboarding + 持仓主管理 | 保留在引导，但允许跳过并明确后续入口 |
| 策略包选择 | onboarding 第 2 步 | 选择趋势/价值预置包，也可跳过 | 投资模型/策略资产 | 不应作为引导必经配置；引导只提供可跳过的默认起点 |
| 复盘/盯盘节奏 | onboarding 第 3 步默认应用 | 应用“收盘复盘 + 盘中只推例外”的默认使用模式 | onboarding 展示默认 + 自动化任务/设置后续调整 | 引导展示摘要；具体任务配置留在自动化 |
| 微信失败提醒 | 设置页 | 只影响微信失败提醒，不改任务事实 | 设置 | 保留设置，不放回引导 |
| 微信恢复提醒 | 设置页 | 默认关闭；不影响运行或网页事项 | 设置 | 保留设置，默认静默 |
| 静默时段 | 设置页 | 字段已存在，但页面标记“暂不强制” | 设置 | 归属正确，但当前功能未完成，不能作为已实现能力宣传 |
| 提醒类别 | 服务/API 有 `categories` 字段，Portal 无控件 | 数据模型预留，用户目前不能配置 | 设置 | 应补到设置，或明确暂不支持；不能保持半可见状态 |
| 单个任务执行时间 | 自动化任务编辑 | 任务 revision 的 schedule | 自动化任务 | 不放全局设置或 onboarding |
| 单个任务是否推送 | 自动化任务编辑 | task revision 的 delivery policy | 自动化任务 | 与全局微信提醒分离：任务声明“要不要推”，设置决定“是否接收提醒” |
| Skill 安装/启停 | 技能管理 | 安装、启用、停用、卸载和版本状态 | 技能管理 | 不放 onboarding；引导最多展示默认已启用能力 |
| 方法/策略文件 | 我的文件 | 用户资产、版本和文件语义 | 我的文件/未来投资模型 | 不放通知设置；避免与普通文件双重编辑 |
| 投资模型 | 设计阶段，尚无完整 Portal/MCP 闭环 | 应组合选股、交易、风控、复盘 | 投资模型主管理入口 | 暂不在本轮 onboarding/settings 改造中假装已支持 |
| 微信账号/通道连接 | 微信侧/系统连接 | 通道能力与身份绑定 | 设置或通道管理 | 微信可触发引导，但复杂配置不应只在微信完成 |

## 对新手引导的建议

### 引导必须完成

- 让用户理解产品能做什么；
- 建立至少一份可用上下文：持仓、研究对象或当前问题三者之一；
- 展示系统采用的默认运行方式；
- 让用户知道以后在哪里修改设置、任务和资产。

### 引导可以跳过

- 持仓录入；
- 策略包选择；
- 非必要的通知细节；
- 高级的复盘/盯盘时间配置。

### 引导不应承载

- 全部通知类别和静默规则；
- 每个自动化任务的详细配置；
- Skill 安装/停用/升级；
- 方法、策略和投资模型的长期编辑；
- 只适合开发或运营人员理解的内部状态。

## 对设置页的建议

设置页应形成“通知偏好”而不是空泛的“低频配置”入口，至少分成：

### 微信提醒

- 失败提醒开关；
- 恢复提醒开关（默认关闭）；
- 提醒类别；
- 静默时段；
- 微信通道当前是否可用。

### 默认行为

- 默认通知渠道；
- 默认复盘/盯盘偏好（仅作为新建任务的默认值，不覆盖已有任务）；
- 时区。

这里必须明确：设置只影响全局默认和提醒偏好，不直接修改已有任务的 schedule/delivery，也不改变运行事实。

## 对自动化任务页的建议

任务页继续是单个任务的唯一主管理入口，负责：

- 执行时间和频率；
- 任务目标与指令；
- 输入资料、方法和 Skill；
- 是否保存/更新产物；
- 是否推送、推送模式和条件；
- 暂停、恢复和运行历史。

全局设置与任务配置冲突时，任务的显式配置优先；全局设置只作为默认值或通知 gate，不重写任务 revision。

## 微信端与网页端分工

### 网页端

- 完整新手引导；
- 配置摘要和可回看状态；
- 设置、自动化、资产、Skill 管理；
- 失败处理和版本/影响查看。

### 微信端

- 首次触达和轻量问答；
- 提醒用户打开网页完成复杂配置；
- 补充持仓/研究问题等自然语言输入；
- 运行结果和失败事项的提醒投影。

微信不应成为通知偏好、任务配置或投资模型的唯一事实入口。

## 当前产品缺口

1. `SettingsShell` 的 `categories` 只存在于类型/API 形态，页面没有配置控件。
2. 静默时段可保存，但页面明确说明尚不强制，产品上容易造成“看起来能配、实际不生效”。
3. onboarding 第 3 步会应用默认使用模式，但没有清楚展示它创建或影响哪些任务。
4. onboarding 的策略选择与投资模型设计存在概念错位：长期目标应是投资模型，而不是并列的“策略包”。
5. 设置页当前标题是“通知偏好等低频配置”，范围暗示比实际能力更大。
6. 当前没有统一的“配置来源/优先级”说明，用户可能不清楚全局设置与单任务推送的关系。

## 推荐的首次使用路径

```text
网页首次进入
  → 说明助手能力与默认节奏
  → 可选录入持仓/研究对象
  → 可选选择起始投资模型或跳过
  → 展示默认复盘/例外提醒摘要
  → 完成并进入聊天
  → 设置页修改全局偏好
  → 自动化页修改具体任务
```

## 后续执行顺序

1. 先冻结字段归属和优先级，不直接搬 UI；
2. 为设置页补齐通知类别、静默时段真实语义和默认行为说明；
3. 收缩 onboarding，使其成为激活流程而不是配置总入口；
4. 在自动化页明确任务级 schedule/delivery 与全局通知偏好的关系；
5. 最后再评估投资模型是否进入正式 onboarding，不用当前策略包占位冒充完整模型。

本文是盘点与产品建议，不改变现有 UI、schema、任务或生产数据。
