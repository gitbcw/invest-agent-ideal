# T-561：显性化人工验收标准与三用户镜像走查

日期：2026-09-29
范围：本地 `production-mirror`，用户 `mg`、`dyk`、`111`

## 验收原则

本记录只判断“用户能否理解并使用显性化结果”，不把 API、单元测试或 T-558 的历史回放当成人工体验证据。每项结论使用：`通过`、`问题`、`未知`。

## 逐用户标准

### A. 用户资产可见性

- 能找到本用户应显性的策略文件和系统模板文件。
- 用户策略与“系统模板”有清晰标签，不因来源不同而被混为同一类。
- 三用户之间不存在会话、文件、策略或 Skill 串读。
- 空列表表示“当前没有”，不被误解为加载失败。

### B. 来源与关联

- 文件或 Skill 能说明来源、版本/状态和关联任务。
- 关联跳转回到唯一主管理入口，不出现同一内容的双重编辑入口。
- 历史文件、系统模板、用户策略和普通报告的语义边界可理解。

### C. 状态区分

- 保存草稿、采用/启用、生效和卸载/停用是不同状态。
- 页面不会暗示“保存后已经改变运行行为”。
- Skill 的系统基础能力、用户可管理 Skill、私有 Skill 和未安装目录项不会混淆。

### D. 失败与问题处理

- 失败事项能在网页入口发现，网页事实不依赖微信是否送达。
- 用户看到的是影响、时间、当前状态和下一步，不要求理解内部 scope、run-basis、trace 或数据库术语。
- “让 Agent 解释并处理”进入与该事项绑定的问题会话，不跳到无关会话。

### E. 旧入口替代

- 旧聊天右侧面板中的报告、附件和文件仍能通过附件卡片或“我的文件”找到。
- 旧面板移除不会造成核心资产不可达。
- 用户能理解新的入口名称和导航关系。

## 目前已知边界

- T-558 的 `73/73` 只证明隔离装配、回放和服务契约，不证明本表的人类可理解性。
- 当前镜像创建于 2026-09-22；正式发布前仍需刷新镜像并重新核对三用户差异。
- 真实微信送达、真实用户采用和长期使用反馈不在本轮本地走查范围内。

## 首轮结论

- **已观察事实**：三用户均能进入新的技能管理入口；三用户均显示 5 个已安装且启用的预置 Skill；三用户均能进入“我的文件”，并看到显性化后的策略文件入口。
- **待人工判断**：系统模板/策略标签是否足够醒目；用户是否能区分“技能已安装”与“本轮一定注入”；“我的策略文件”与普通报告的边界是否直观；旧右侧面板移除后的替代路径是否符合实际习惯。
- **尚未走查**：失败事项到问题会话、通知偏好、Skill 停用/找回、资产关联详情、跨 scope 反例和旧面板替代预览。

## 完成条件

三用户每一栏均有浏览器或可见页面证据；问题项有修订任务或明确延期决定；未知项不被写成通过；形成可直接供 T-559 发布前总验收使用的记录。
