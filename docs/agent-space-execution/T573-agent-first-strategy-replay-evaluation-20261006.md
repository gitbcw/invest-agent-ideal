# T573：Agent-first 策略判断回放评估

日期：2026-10-06  
用户作用域：本地 `production-mirror` 的 `mg / invest-agent-mg`  
评估方式：复用已保留的真实会话和固定证据回放，不新增业务节点、不修改用户 Skill、不写入策略/预案/提醒。

## 1. 评估目标

先验证 Agent 是否能在用户 Skill 和方法上下文下完成真实的策略判断，再决定是否需要进一步建设模拟账本或结构化判断协议。

本轮不评价收益率，不把固定证据回放当成历史行情回测，也不证明 Agent 在所有市场情境下稳定。

## 2. 证据样本

| 样本 | 会话 | 场景 | 主要输入 |
| --- | --- | --- | --- |
| A | `web_3v0cpm2UG_pxDqUD` | 条件较好但关键因子缺失 | 价格站上 MA25、量比 1.08、月周结构通过；筹码和主力资金缺失 |
| B | `web_YyIEqQMC5D_BwvGi` | 冲突值、代理值和缺失值并存 | 收盘价一真一冲突；量比为 proxy；筹码、资金、公告缺失 |
| C | `web_sP5LsMaXudru3iGp` | 破位和硬风险 | 跌破 MA25、跌破近期低点、放量下跌、大股东减持公告 |
| D | `web_ZETfRaCJyOg44URs` | 真实历史资料不足 | 只有二级报道，缺少结构化行情、筹码、资金和公告 |

## 3. 评估结果

总体状态：`Pass with caveats`

### 通过部分

- 能把“继续观察 / 准备行动 / 暂不处理”区分开，没有把观察信号升级为买入确认。
- 能识别 `missing`、`conflicting`、`proxy` 和 `unknown`，并在 B、C、D 中阻止数据缺口升级成行动建议。
- 能维护用户方法中的“不追高、目标仓位不足不自动加仓、需要多条件共同满足”等纪律。
- 能把提醒分成价格触发、数据补齐、风险触发和摘要跟踪，没有把普通观察状态全部变成即时提醒。
- C 中识别了放量破位和减持公告的硬风险，结论降为“暂不处理”，与用户方法边界一致。
- 所有四个样本均保持只读，没有写入策略、持仓、观察池或提醒规则。

### 需要改进的部分

#### 1. 缺失因子时不应继续展示数值评分

样本 A 在筹码集中度和主力资金缺失时，仍给出价格趋势 `90`、量能 `75`，并描述“加权估计已在 60 区间上下”。虽然最终被硬性降级为“继续观察”，但这种数值会制造“总评分已经算出来”的错觉。

这更像 Skill/输出纪律问题，不是模拟引擎问题。改进方向：

- 关键因子缺失时，只输出“因子状态”和“能否参与综合评分”；
- 不展示部分权重合成分数；
- 若必须给分，明确标记为局部观察分，禁止与完整总分比较；
- 最终结论仍使用行动状态和缺口，而不是局部数字。

#### 2. Agent 判断质量仍只有单轮证据

固定回放证明了 Agent 能遵守给定证据边界，但没有证明：

- 换一批标的后仍能保持同样纪律；
- 同一输入重复运行结论稳定；
- 在完整历史行情和财务资料下能正确处理基本面判断；
- 判断结果能否与后续事实形成可计量的验证闭环。

这些暂时应标为 `Unknown`，不能升级为“Agent 已经具备可靠策略回测能力”。

## 4. 对产品路线的决定

本轮不建设用户可见的业务级结构化节点。

继续采用：

```text
用户 Skill / 方法上下文
        -> Agent 判断与解释
        -> 固定格式的回放结果
        -> 人工评估与后续反馈
```

只有在需要自动聚合日报、周报或模拟净值时，才由服务保存一个通用判断记录：结论、证据、未知项、as-of、Skill 版本和行动资格。它是审计载体，不是用户需要管理的业务节点。

## 5. 下一步

1. 先修订 Agent/Skill 输出纪律：缺失关键因子时不展示伪完整评分。
2. 继续用 `mirror-mg` 做 3-5 个不同类型的历史判断回放，包含基本面证据不完整和条件冲突样本。
3. 增加同一固定证据的重复回放，观察结论和行动状态是否稳定。
4. 只有 Agent 判断质量达到可接受水平后，才把判断结果接入策略模拟的日报/周报；不提前建设业务节点。

## 6. 证据边界

- 本报告使用的是镜像中已保留的会话、方法文件和固定证据输入。
- 固定证据由回放会话提供，不等同于本轮重新连接真实行情工具。
- 本报告不证明真实历史收益、不证明模型泛化，也不授权修改 `mg` 的正式 Skill 或策略。
