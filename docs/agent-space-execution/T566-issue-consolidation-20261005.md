# T-566：体验与工作流问题汇总

日期：2026-10-05  
范围：本地 `production-mirror` 的 T-561、T-562、T-565 走查结果，以及生产 MCP 桥接边界  
用途：作为后续修复、补证据和人工验收的唯一问题入口；不把本地镜像结论升级为生产可靠性结论。

## 1. 结论先行

当前不是“页面还有几个小问题”，而是 MG 主线还缺三个闭环：

1. **能及时交付可用结果**：深度复盘存在长时间工具循环、无阶段性结果的问题。
2. **能判断结果有多可靠**：行情、公告、成本和规则数据存在缺失、冲突或历史代理值，降级表达尚未完全统一。
3. **能把判断接到后续行动**：观察对象、提醒规则、收盘反馈和策略改进之间尚未形成可验证闭环。

体验层的主要问题不是单纯信息太多，而是当前决定、必要上下文和可展开证据没有被分层；用户需要先理解内部概念，才能完成投资判断。

## 4. 按证据性质分类

## 4.1 本轮最小实现状态

- `runMastraTurn` 现在会在流式超时/失败时保留已产生的用户可见文本；运行时返回“阶段性结果”并明确剩余数据未完成。
- 没有正式文本时仍沿用原失败提示，不从工具摘要或内部日志拼接伪结论。
- 新增回归用例覆盖“文本已产生、随后流挂起”的场景；类型检查通过。
- MG 第一次复验曾出现无文本工具循环并持续到人工停止；加入平台级研究收敛规则后，同类复验已在约 1 分 05 秒、3 次互补检索后输出事实/结论/缺口骨架，判定 `Pass with caveats`。
- 当前剩余风险是生产 MCP 数据完整度和复杂复盘稳定性，不再是本地镜像中的无界重复检索。
- 第二个闭环已进入实现：平台指令要求区分“本轮已核验 / 可参考但未独立核验 / 当前未知”，并禁止冲突值、代理值和未标时点的盘中值进入评分或行动条件；尚待针对性工作流复验。
- 第三个闭环已进入实现：平台指令要求每次结尾给出行动状态、触发条件和失效条件；任何长期资产变更先出草案，确认后写入并回读；尚待候选→观察对象→规则覆盖工作流复验。
- 行动状态人工复验已完成：`mirror-mg` 对 000722 输出“继续观察”，明确不是准备行动/暂不处理，列出触发条件、失效条件、下一复核点，并确认未修改观察池、预案或提醒规则；判定 `Pass with caveats`。浏览器在完成瞬间未显示正文，但镜像数据库已持久化完整助手消息，需另记为前端刷新观察项。
- P0/P1/P2 的只读验证结果已合并为 [T-567 策略改进候选草案](./T567-strategy-improvement-candidate-20261005.md)，当前不生效；下一步是隔离回放，之后再由用户决定是否进入正式版本草案。
- T-567 固定证据隔离回放已完成三类样本，均守住行动和零写入边界；候选草案可进入“真实 MCP 数据接通后的对照复验”，仍未正式采用。

### A. 已确认的产品/体验问题

- 深度复盘在合理等待窗口内可能没有任何可用交付；
- 数据缺口、代理值和冲突价格可能同时进入中间分析层；
- 观察对象与提醒规则存在覆盖错位；
- 默认层和内部术语的边界需要按当前决定重新装配。

### B. 已发现但需要补证据的问题

- 复盘长时间无结果的具体根因是工具重复、历史资料路径、模型行为还是组合因素；
- 规则错位已经造成多少实际噪声、漏报或无效提醒；
- 缺口通知采用静默留痕还是主动通知；
- 同一 MG 请求在真实生产 MCP 下的耗时和数据完整度。

### C. 产品边界待用户裁决

- 观察信号、预案条件、硬风控的最终用户命名；
- 哪些缺口必须立即告知，哪些只记录；
- 策略改进候选默认展示数量和确认方式；
- 是否需要显式“展开依据”入口。

## 5. 推荐推进顺序

1. **先修复交付断点**：复盘长时间无结果时，至少先返回可用骨架、已取得事实和明确缺口。
2. **再冻结证据口径**：禁止代理值、冲突值和过期值无标记进入评分或行动条件。
3. **再做规则覆盖对账**：只读列出持仓/关注/预案与规则的差集，由用户确认需要覆盖的对象。
4. **再做提醒分层**：区分观察、预案、风控，并补齐静默、命中、抑制、投递状态记录。
5. **再打通生产 MCP 只读桥接**：只为验证真实数据链路，不改变本地镜像默认 OFFLINE 模式。
6. **最后做策略改进闭环**：用一个候选完成草案、确认、版本回读和回滚，再扩展到更多候选。

## 6. 每一步的完成判据

- **交付断点**：MG 能在可接受窗口内看到“当前结论/已取得事实/缺口/下一步”，不再只有处理中状态。
- **证据口径**：任何影响行动的数字都有日期、来源和可信度；缺失时结论自动降级。
- **规则对账**：每个持仓、关注或预案对象都有明确的“有规则/无规则/无需规则”状态。
- **提醒分层**：用户能区分消息送达、规则命中和收盘后判断是否成立。
- **MCP 桥接**：完成只读 discovery、一次安全调用、断开降级和调用审计；不写生产。
- **策略迭代**：改进候选不会直接覆盖正式策略，用户确认后可回读，且可回滚。
