## 结论

结论：`Partial`。

追问后的解释层和状态区分基本符合预期；默认层仍然没有收住。用户明确要求“只给做这个决定所需的简短回答、不要完整报告”时，Agent 仍输出了多段事实、事件、缺口、操作建议和下一步清单。

这证明当前 L1 中“结论先行、分层展开、默认简洁”过于抽象，不能单独约束默认回答的范围。下一次代码改动应优先补充“默认层的停止条件”和“何时升级到解释层”的明确指令。

## 验证输入与观察

### 场景一：默认决策层

输入要求：只判断湖南发展 `000722` 是否继续关注，不要完整报告、不要写入。

观察到：

- 结论正确地落在“暂时维持关注，不升级”；
- 但随后展开了基本面、事件面、多个日期的价格线索、结构化数据缺口、两阶段行动建议；
- 用户已经明确当前只需要一个决定，输出仍然超过最低充分上下文。

判定：`Partial`。事实边界和风险纪律守住，但默认层过宽。

### 场景二：用户追问“为什么只是继续观察”

输入要求：只解释最关键的一两个原因，不重复整段信息。

观察到：

- 回复集中在两个原因：观察前提从未验证、决定性量价字段缺失；
- 没有重新复制默认回答的全部事实列表；
- 能解释“继续观察”是不动作的默认状态，而不是已证明看好。

判定：`Pass with caveats`。逻辑清楚，但个别句子仍可进一步压缩。

### 场景三：用户追问为什么没有提醒

输入要求：一句话区分“没有规则、规则没触发、数据不足”。

观察到：

- 明确回答“没有规则”；
- 补充说明 000722 不在现有规则清单，因此不存在“触发”或“数据不足”二选一的判断。

判定：`Pass`。正确区分了无规则和未触发/数据不足。

## 已完成的最小实现

已只修改 `src/runtime/agent-instructions.ts` 的 L1 输出指导，加入以下可观察约束：

- 用户要求简短、只做一个决定或未要求报告时，默认最多输出：结论、1～2 个关键理由、一个下一步选择；
- 默认层不列完整事实清单、完整缺口清单、全部行动步骤或内部状态；
- 只有在高风险会改变行动结论、证据冲突会误导用户，或用户追问依据时，才升级解释深度；
- 一旦完成当前决定，停止继续解释，不主动追加“怎么用这个答案”长清单；
- 用户要求“为什么”时只回答直接原因，不重复上一轮已经给出的内容。

已通过 `tests/agent-instructions.test.ts`、`tests/agent-space-domain.test.ts`、`tests/best-effort-answering-template.test.ts`。镜像中的后续行为复验仍需在服务重新加载该 L1 指令后进行；本轮镜像验证记录的是改动前行为，不能冒充改动后的运行证据。
