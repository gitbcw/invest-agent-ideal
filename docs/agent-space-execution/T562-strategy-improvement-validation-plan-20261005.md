# T-562 策略改进候选验证计划

日期：2026-10-05  
范围：`mirror-mg` 本地隔离镜像  
目标：把 WF-05 的策略改进候选转成可验证任务，不修改正式策略、不接触生产、不发送微信

## 结论

当前不进入策略改版。先按以下顺序验证：

1. **P0：数据能力与降级边界**：确认 60 日均量、筹码历史和价格口径到底是“暂时缺失”还是“当前能力长期不可得”。
2. **P1：观察对象与规则覆盖**：核对关注股、持仓、预案和盯盘规则是否一致，确认是否存在僵尸规则和裸关注对象。
3. **P2：提醒分层与降噪**：在 P0/P1 结果明确后，用历史影子记录比较即时提醒与摘要提醒的差异，不直接改投递设置。

只有验证结果支持调整，才进入“新版本草案 → 用户确认 → 隔离回放 → 是否采用”的流程。

## P0：数据能力与降级边界

### 要回答的问题

- 000722 及样本标的能否取得真实 MA60 volume、MA25、筹码至少两个时点和统一收盘价？
- 如果连续多个历史交易日都取不到，系统是否明确输出“未验证”，而不是使用代理值完成建仓结论？

### 最小实验

用 `mirror-mg` 的历史资料选取 000722、600313、300482 三只标的，读取同一交易日窗口，逐字段记录：存在、缺失、来源、时间、是否可复算。对缺失字段运行一次只读复盘，检查输出是否阻止“买入确认”。

### 通过标准

- 每个字段都有明确状态：`verified`、`missing`、`conflicting` 或 `proxy`；
- `proxy` 不得进入建仓结论；
- 60 日均量或筹码方向缺失时，建仓结论必须为“不可验证”；
- 同一标的同一日期只保留一个权威价格，冲突必须显式列出；
- 不改变 V1.1 或任何正式方法文件。

### 产物

`T562-P0-data-boundary-record-20261005.md`，包含字段矩阵、缺口证据和是否需要降级协议的建议。

## P1：观察对象与规则覆盖

### 要回答的问题

- “候选 → 继续观察”是否有对应的执行载体？
- 规则是否覆盖真实持仓和关注对象？是否存在已离开持仓但仍在运行的规则？

### 最小实验

只读读取持仓、关注股、预案和盯盘规则清单，生成四方对照表。对每一项标记：应有规则、已有规则、缺规则、疑似僵尸规则、需要用户确认。暂不创建、删除或修改任何规则。

### 通过标准

- 每个对象的状态可解释，不以“记录存在”推断“仍然有效”；
- 关注股没有规则时明确标为“裸关注”，不自动补规则；
- 非持仓规则只标记为待确认，不自动删除；
- 能明确区分规则缺失与规则未授权。

### 产物

`T562-P1-coverage-reconciliation-20261005.md`，包含覆盖矩阵和待确认清单。

## P2：提醒分层与降噪

### 要回答的问题

- 哪些属于持仓硬风控，必须即时提醒？
- 哪些属于观察触发，适合进入摘要？
- 静默、数据缺口通知、即时提醒和收盘确认如何互不混淆？

### 最小实验

用 WF-04 的三个历史场景做影子比较：同一事件分别按“全部即时提醒”和“持仓即时、观察摘要、数据缺口静默”两种方案渲染，比较消息数量、信息完整性和是否误导为买入信号。实验只生成草案，不投递。

### 通过标准

- 提醒原因、数据时点、投递状态和收盘评价分开；
- 数据不足不产生交易信号；
- 观察提醒不会被措辞成买入指令；
- 能统计命中、误报、漏报、静默正确和不确定；
- 不修改现有推送优先级、冷却时间或规则。

### 产物

`T562-P2-notification-layering-record-20261005.md`，包含两种方案的影子对照和人工决策项。

## 任务边界

- 本计划不创建盯盘规则、不删除规则、不写观察池、不改预案、不改正式策略版本。
- 本计划不把本地影子结果当成生产或真实微信证据。
- 任一任务发现真实数据或状态冲突时，先登记为 `Unknown`/`Partial`，不自行补值。
- 三个任务完成后，再由用户决定是否生成正式的新版本策略草案。

## 完成顺序

`P0 数据边界 → P1 覆盖对账 → P2 提醒分层 → 用户确认是否进入版本草案`
