# MG 核心主线阶段汇报与目标对照

日期：2026-10-06  
用途：明日会议汇报、目标一致性检查  
对照基线：P-17 MG 核心循环、T-566 问题汇总、T-574 全持仓编排、T-567 策略生命周期

## 一句话结论

这段时间的主线有两个：一是通过 UI 显性化和交互优化，让 Agent 的能力、状态、来源、版本和下一步更容易被用户理解；二是完成 W7 Agent Space 核心重构，为“越用越好用”建立 Agent、方法、Skill、任务、版本和运行依据的服务边界。最近完成的 MG 三闭环，是建立在这两个基础上的业务体验延续优化，不是本阶段唯一主线。

## 两条真正主线

### 主线一：UI 显性化与交互优化

- 将能力、运行状态、来源、版本、采用状态、关联任务和失败事项显式呈现。
- 优化对话、待处理、自动化、我的文件、工作空间/Skills 等入口，让用户能理解“发生了什么、依据是什么、下一步是什么”。
- 修正离线投递、处理会话、暂停/归档等容易误导用户的交互语义。
- 当前判断：显性化主线已完成一轮系统性建设，后续主要靠真实体验发现明显问题，不预设继续大规模改 UI。

### 主线二：W7 Agent Space 核心重构

- 将 Agent、方法/版本、Skills、任务依赖、运行依据和结果从旧 Workspace 运行依赖中抽离，形成服务-owned 的 Agent Space 装配边界。
- 支持固定版本、scope 隔离、依赖绑定、运行 basis、确认门、审计、失败补偿和回滚边界。
- 三用户灰度和关键真实运行链路已完成验证；旧 Workspace 保留为 history-only/回退来源，不以历史删除作为完成条件。
- 这条主线解决的是系统如何承接用户确认和方法演进，是“越用越好用”的结构基础。

### MG 三闭环：延续优化

- 全持仓真实筛选、可靠性降级、策略版本回滚，是对上述基础在 MG 业务场景中的一次体验延续验证。
- 本轮重点不是重新定义 MG 投资规则，而是检查用户能否得到可用结果、理解结果可靠性，并安全承接后续策略改进。

## “越用越好用”初步目标检查

### 已达到的基础目标：Pass with caveats

- Agent 不再只是一次性对话；Agent、方法、Skill、任务依赖、版本和运行依据已有明确的服务边界。
- 方法可以固定版本并绑定到任务，运行时可以回读本轮实际使用的版本和依据。
- 用户确认可以形成候选、采用新版本、回读结果，并在需要时回滚到旧版本。
- W7 已完成三用户灰度和关键真实运行验证；MG 的真实任务链能够消费已采用的方法，运行和投递结果可追溯。
- UI 显性化使用户更容易看到状态、来源、版本和下一步，为反馈提供入口。

### 尚未证明的产品效果：待真实使用观察

- 还没有经过足够长的真实使用窗口，证明用户反馈会稳定沉淀为下一轮更适合的方法或任务配置。
- 当前策略改进候选已完成隔离生命周期验证，但没有把某个新候选正式推广到 MG 并观察前后效果差异。
- MG 三闭环刚完成一次延续验收，后续仍需要用户实际体验，发现明显的交互或判断问题。
- W7 兼容窗口、旧入口退出和自然运行的长期观察仍需按原边界收口，不能仅凭一次成功运行宣布“越用越好用”已经完全成立。

### 判断

“越用越好用”已经达到**初步工程目标**：系统具备承接反馈、版本化演进和安全回滚的能力；尚未达到**长期产品效果目标**：还需要真实用户使用和至少一轮有对照的策略改进观察。明日会议应把两者分开表达。

## 已完成的关键交付

### 1. 运行和数据链路

- 本地 `production-mirror` 启动入口和健康检查固化。
- 生产行情 MCP 通过临时只读隧道接入，未把凭证写入仓库或长期 `.env`。
- `market-data-tool` 发现 38 个工具，真实调用返回腾讯行情。
- 全持仓真实复跑中观察到：`get_hist_klines` 1 次、ETF `get_realtime_quote` 1 次，并取得筹码和资金流；没有重复行情调用。
- 已建立 MCP 会话中途断开后，系统保留已取得数据，停止无效重试，交付阶段性结果并列出缺口。

### 2. 证据和用户输出

- 每轮结果显式区分已挂载能力、实际调用工具、未挂载能力。
- 代理值、冲突值、过期值不会直接进入评分或行动条件。
- 行动状态统一为“继续观察 / 准备行动 / 暂不处理”，并附触发、失效和下一步复核条件。
- 只读请求不再意外生成文件；无文件请求的回归 artifact 数为 0。

### 3. 策略生命周期

- 候选不会直接覆盖正式策略。
- 采用需要精确确认，篡改 payload、陈旧 revision、重复确认都会拒绝。
- 采用后保存不可变版本并回读。
- 失败会恢复旧策略。
- 用户可以选择旧版本回滚，回滚会生成新的当前版本并回读校验。

## 本阶段的真实边界

- 没有生产部署。
- 没有修改 MG 持仓、关注对象、预案、提醒或正式策略。
- 没有发送微信。
- 没有把本地/临时桥接证据包装成长期生产可靠性承诺。
- 没有继续扩展 UI 细节、模型长思考优化或无关历史迁移；后续 UI 以用户实际体验反馈为准。

## 会议建议说法

> 这段时间真正做了两件事。第一，持续把 UI 和交互做显性化，让用户能看懂 Agent 做了什么、依据什么、现在是什么状态、下一步是什么。第二，完成 W7 Agent Space 核心重构，把 Agent、方法、Skill、任务、版本和运行依据建立成服务边界，为“越用越好用”打基础。最近的 MG 三闭环，是在这两个基础上的一次体验延续优化：全持仓能交付，数据缺失会降级，策略改进能确认、回读和回滚。接下来我会继续自己体验，重点观察是否还有明显的交互问题；微信/自动化长期运营和提醒口径再单独安排，不把它们混成这次主线的完成条件。

## 会议需要的决策

1. 是否把本阶段“三个核心闭环”视为 MG 主线阶段性完成。
2. 是否下一阶段再单独安排微信/自动化投递恢复与提醒分层采用。
3. 是否选择一个策略候选进入正式策略版本，还是先保持当前策略不变。
