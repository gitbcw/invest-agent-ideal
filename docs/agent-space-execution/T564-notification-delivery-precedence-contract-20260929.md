# T-564：通知偏好与任务投递优先级契约

日期：2026-09-29
状态：已按 owner 决策冻结并完成首轮实现

## 目标

明确三类配置的职责，避免新手引导、设置页和自动化任务互相覆盖：

1. 新手引导提供首次使用默认值；
2. 设置页管理跨任务的提醒偏好；
3. 自动化任务管理单个任务的执行和结果投递。

## 三层对象

| 层级 | 负责什么 | 典型字段 | 是否覆盖其他层 |
|---|---|---|---|
| Onboarding 默认 | 首次启动时给出可运行起点 | 默认复盘节奏、默认例外提醒 | 只用于新建/初始化，不回写覆盖已有任务 |
| User Settings | 用户级提醒接收偏好 | 微信失败提醒、恢复提醒、类别、静默时段、新建任务默认渠道 | 作为提醒 gate；不改任务 schedule、任务事实或授权 |
| Automation Revision | 某个任务的运行与结果交付 | schedule、output、delivery.mode、condition、有效期 | 对该任务的执行/结果声明拥有最高对象级优先级 |

## 核心规则

### 1. 执行与提醒分离

- 任务是否运行由任务自身的 `schedule`、状态和服务规则决定。
- 任务是否声明结果投递由任务 revision 的 `delivery` 决定。
- 用户设置只决定用户是否接收符合条件的提醒，不删除任务结果，也不改变任务运行。

### 2. 任务级 delivery 优先于全局默认

- 任务明确声明 `delivery.mode=none`：该任务不产生结果投递；全局提醒开关不能把它变成推送任务。
- 任务明确声明微信摘要或条件微信：先按任务声明判断是否产生投递，再经过用户通知偏好 gate。
- 新建任务未声明 delivery 时，使用用户设置中的默认渠道/默认模式；生成 revision 后，实际 delivery 固定在任务 revision，不随全局默认值静默漂移。

### 3. 失败提醒是独立投影

- 自动化失败提醒不是任务结果 delivery 的替代品；它由服务终态和用户的失败提醒偏好共同决定。
- 关闭失败提醒不隐藏网页“待处理”事实，不改变任务状态、重试、运行授权或审计。
- 恢复提醒默认关闭；成功和恢复默认静默，除非用户明确开启恢复提醒。

### 4. 静默时段

- 静默时段只抑制可延迟的微信提醒投递，不影响任务执行、产物保存、失败事实和网页待处理。
- 当前实现将命中的提醒 job 延迟到静默结束后；任务执行、失败事实和网页事项不受影响。
- 进入静默时段的提醒必须有明确终态：延迟并保留投递状态，不能无记录丢失。

### 5. 通知类别

- `categories` 属于用户设置，控制失败提醒等提醒类型的接收范围。
- 类别过滤不能影响任务结果 delivery 是否生成，也不能删除网页事实。
- 未配置类别时采用服务定义的保守默认值，并在设置页显示当前有效含义。

### 6. Onboarding 规则

- onboarding 只应用一次初始化默认值，或创建带默认值的新任务；不覆盖用户已有任务 revision。
- onboarding 完成后，用户应能从设置页修改全局提醒偏好，从自动化页修改具体任务行为。
- onboarding 不要求用户完成通知类别、静默时段等高级配置才能开始使用。

## 冲突处理

| 场景 | 结果 |
|---|---|
| 全局默认要求推送，任务明确 `none` | 不推送 |
| 任务声明微信摘要，全局失败提醒关闭 | 正常任务结果按任务 delivery 处理；失败提醒不发；网页事实保留 |
| 任务声明不推送，全局失败提醒开启 | 任务结果不推送；若运行失败，独立失败提醒可按偏好发送 |
| onboarding 默认与已有任务冲突 | 保留已有任务 revision；默认只用于新建任务或未初始化对象 |
| 静默时段命中失败提醒 | 任务继续运行，失败事实落库；提醒按已实现的延迟/抑制语义处理并留痕 |

## 已冻结决策与实现

1. 用户设置中的新建任务默认渠道首期只提供“微信摘要”和“不推送”两项，持久化在 `notification_preferences.default_delivery_mode`。
2. 静默时段命中的提醒延迟到结束后发送，并保留 push job 的投递状态。
3. `categories` 首期只做失败/恢复两类，不纳入任务结果 delivery。
4. 新建任务未声明 `delivery` 时读取默认渠道并固化到首个 revision；显式 delivery 和已有 revision 不受影响。

## 验收边界

- 服务层和 Portal 使用同一套优先级定义。
- 修改全局设置不会改变既有任务 revision 的 schedule/delivery。
- 任务级 `delivery` 不会被全局开关反向打开。
- 关闭提醒不会删除网页事项、运行结果或审计。
- onboarding 默认不会覆盖已存在的任务或用户选择。
