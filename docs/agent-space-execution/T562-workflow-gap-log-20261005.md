# T-562 工作流验证发现登记

日期：2026-10-05  
来源：`mirror-mg` 本地镜像，主线 A“收盘复盘 → 次日预案”  
用途：先登记验证中发现的缺口，待全部工作流完成后统一汇总，不在当前流程中立即扩大修复范围

## 登记原则

这里记录的是“本次工作流没有取得或没有重新核验的证据”，不等同于产品缺陷，也不直接推断生产问题。后续需要结合其他工作流、真实数据能力和用户体验判断，再决定是补数据、改流程、改提示还是接受为明确边界。

状态使用：`待汇总`、`需补证据`、`可接受边界`、`确认缺陷`、`不再复现`。

## 当前不处理的事项

- 不因为 G-01 至 G-03 立即扩建数据工具；
- 不把历史记录未核验直接判为错误数据；
- 不把 G-07 的一次失败直接归因于某个模型或数据源；
- 不在本轮验证中补写真实用户资料；
- 不把本地镜像结果升级为生产可靠性结论。

- 输出了节后复核触发条件、任一满足即降级的失效条件和下一复核点；
- 明确本次只读，未修改观察池、预案或提醒规则；
- 数据库中助手消息状态为 `sent`，执行时长约 54 秒；浏览器完成瞬间未立即显示正文，列为前端刷新观察项。

判定：行动语义与写入边界 `Pass with caveats`；前端展示同步 `Unknown`，不影响本次后端消息已持久化的事实。

## 完整工作流结束后的汇总方式

全部主线和特殊工作流测完后，按以下顺序处理本表：

1. 合并重复发现，确认是否在多条工作流中复现；
2. 标记每项缺口属于数据能力、上下文/资产、模型执行、交付、用户资料还是产品边界；
3. 判断它是否阻断 mg 的业务闭环，还是仅降低结论精度；
4. 对阻断项建立修复任务，对可接受项补充产品口径和用户说明；
5. 对仍缺生产证据的项保留 `Unknown`，不提前宣布解决或可靠。
