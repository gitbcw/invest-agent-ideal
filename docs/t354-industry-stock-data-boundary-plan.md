- 关联任务：T-354

## 1. 背景与问题修正

T-354 源自 mg 的“每天行业复盘”任务。用户希望复盘中包含行业资金、行业内涨幅靠前公司、资金流入较强公司等内容，但历史运行只能取得部分个股明细。

原任务标题把“涨跌加速”写成了待建设的数据能力，这个表述不成立：

- “涨跌加速”不是统一、稳定的金融事实字段；
- 不同用户可能用不同窗口、阈值、量价条件和组合信号定义它；
- 平台替用户定义该指标会把个体方法论错误固化成公共接口；
- 每出现一种用户表达就新增专用接口，会使数据服务退化为客户定制代码。

因此，T-354 应收窄为：**补齐通用的申万一级行业个股基础截面、确定性排名和覆盖质量能力；用户自定义信号留在用户自己的自动化任务指令中。**

## 2. 已确认事实

### 2.1 `market-data-tool` 已有能力

- `get_sector_list(kind="industry_sw1")` 可返回 31 个申万一级行业。
- `get_industry_fund_flow_matrix` 内部已有申万一级行业成分映射：31 个行业、约 5,200 只成分股。
- 该矩阵已经可以按交易日返回行业资金流及每个行业的“覆盖成分数/成分总数”。
- `get_realtime_quote` 可以批量返回个股名称、日期、最新价、涨跌幅、成交量、成交额等基础行情，并按缺失代码走多源补齐。
- `get_fund_flows`/资金流快照具备逐股资金字段，但资金流目前为腾讯单源，必须保留来源和缺失边界。
- `get_zt_pool` 是东方财富官方池，但明确不含 ST、科创板，不适合作为全市场行业个股完整性的底表。
- `get_sector_limit_up` 基于新浪板块成分和实时涨幅做启发式推断，分类口径不是申万一级，也不应承担本任务。

### 2.2 当前缺口

申万成分映射只在行业资金流矩阵内部使用，没有以通用、可组合的数据能力暴露“某交易日的申万一级行业个股截面”。Agent 目前只能自行组合多个工具，容易出现：

- 分类口径混用；
- 只拿到头部样本却误当完整候选池；
- MCP 返回硬上限导致全市场行被截断；
- 缺少按行业统计的请求数、成功数、缺失数和排除数；
- 为补齐个股名单产生大量逐行业或逐股票调用，增加超时风险。

## 3. 目标与非目标

### 3.1 目标

1. 提供通用的申万一级行业个股数据原料，不绑定 mg、某张 XLSX 或某个提示词。
2. 对数据源稳定提供的标准原始字段做确定性排序，例如涨跌幅、成交额、成交量、最新价、主力净流入。
3. 接口内部以完整候选池计算，返回结果即使只展示 Top/Bottom N，也必须报告完整扫描覆盖率。
4. 默认排除北交所；主板、创业板、科创板和 ST 在数据源可用时纳入，并逐类报告覆盖。
5. 数据不完整时返回 `partial`/`unavailable` 和缺失明细，不让 Agent 用推测补齐。

### 3.2 非目标

- 不定义或实现“涨跌加速”指标。
- 不内置 mg 的选股方法、阈值、观察窗口或交易建议。
- 不在 Invest Agent 中复制 market-data-tool 的字段转换和数据源降级逻辑。
- 不要求首版支持概念板块；概念分类留作后续能力，且不得与申万一级结果混排。
- 不购买付费数据源，不承诺免费源无法提供的全量字段。
- 不把 ETF 映射、涨停原因、新闻归因混入首版个股基础截面。

## 4. 三方职责边界

### 4.1 `market-data-tool`：事实与质量层

负责：

- 获取申万一级行业目录和当前成分关系；
- 获取指定交易日的逐股基础行情及可用资金字段；
- 做字段归一化、代码去重、市场板块识别和明确排除；
- 对调用方明确指定的原始字段做机械排序；
- 返回来源、数据时间、分类版本/当前成分偏差、覆盖率、缺失和降级告警；
- 负责缓存、批量请求、限频、超时和多源补齐。

不负责：

- 判断什么是“加速”“主力潜伏”“强势启动”；
- 决定哪些行业值得用户关注；
- 生成投资结论、任务文案或 XLSX 行；
- 保存用户报告、管理自动化任务或推送。

### 4.2 Invest Agent：运行与产品治理层

负责：

- 把受信任的只读 `market-data-tool` MCP 装配给交互和定时 Agent；
- 管理用户/实例 scope、调度、并发、租约、超时、任务终态和审计；
- 提供用户状态读取及 `reviews.save`、资产发布、XLSX 提交等受控动作；
- 要求 Agent 尊重数据工具返回的 `coverage`、`warnings` 和 `usage_boundary`；
- 当工具返回 partial/unavailable 时，让任务诚实降级，而不是把部分样本表达成全量。

不负责：

- 为每个 market-data-tool 工具写一层同名代理；
- 在服务代码中维护 mg 的行业筛选规则；
- 把用户自然语言中的每个分析概念升级为系统级指标。

### 4.3 用户自动化任务：方法与表达层

用户负责定义：

- 本次需要哪些行业、哪些原始排名和 Top N；
- 如何根据基础字段组合自己的观察信号；
- 输出到表格的列、顺序、说明文字和缺失时的处理方式；
- 是否把某个自定义信号称作“涨跌加速”，以及它的计算定义。

平台应向用户说明：若任务需要自定义信号，必须在任务指令中写出可计算定义，例如“比较最近 3 个交易日涨跌幅，连续扩大且成交额同步上升”。没有定义时，Agent只能展示基础事实，不应自行猜测。

## 5. 推荐的数据能力设计

### 5.1 不新增用户专用工具

建议在 `market-data-tool` 增加一个通用查询，例如：

```text
get_industry_stock_rankings(
  date,
  standard="sw1",
  industries?,
  metrics=["change_pct", "turnover_value", "main_net_flow"],
  top_n=10,
  include_bottom=true,
  exclude_markets=["bj"],
  limit=1000
)
```

工具名和最终参数可在实现设计中调整，但契约必须保持通用，不出现 `mg`、`review`、`acceleration` 或具体 XLSX 字段。

### 5.2 为什么返回排名而不是全市场 5,000 多行

当前 MCP 列式结果硬上限为 1,000 行，也没有游标分页。直接返回全市场逐股数据会被截断，并增加 Agent 上下文和运行时延。

推荐做法：

1. 工具内部读取完整申万一级候选池；
2. 对所有候选股完成批量取数和质量统计；
3. 按调用方明确指定的原始字段机械排序；
4. 每行业只返回 Top N/Bottom N；
5. 元数据返回完整分母和逐行业覆盖情况。

这样，返回行数可控，但“排名是否基于完整候选池”仍然可验证。

### 5.3 首版字段

必须字段：

- 交易日
- 申万一级行业代码、名称
- 股票代码、名称
- 市场板块标签：主板/创业板/科创板/ST/北交所
- 排名字段和排序方向
- 排名
- 涨跌幅
- 成交额
- 数据来源与数据时间

条件可用字段：

- 主力净流入及其他资金流字段

首版不暴露换手率：当前免费行情链没有稳定、统一的换手率字段契约，不能为满足用户措辞而推算或伪造。

条件字段不可用时应标记缺失，不得阻断基础行情排名，也不得填入推测值。

### 5.4 质量对象

结果至少返回：

```json
{
  "status": "full | partial | unavailable",
  "classification": "sw1",
  "membership_as_of": "当前成分日期或抓取时间",
  "requested_industries": 31,
  "returned_industries": 31,
  "candidate_total": 5200,
  "eligible_total": 5100,
  "covered_total": 5070,
  "missing_total": 30,
  "excluded": { "bj": 100 },
  "coverage_pct": 99.41,
  "coverage_by_industry": [],
  "source_breakdown": {},
  "warnings": []
}
```

数字仅作结构示例，不能成为实现默认值。`candidate_total`、`eligible_total`、`covered_total` 必须来自本次实际执行。

### 5.5 股票范围规则

- 北交所：首版默认排除，并在 `excluded` 中返回数量。
- 主板、创业板、科创板、ST：只要申万成分映射包含且行情源返回有效数据，就纳入候选池。
- 停牌、退市整理或行情缺失：保留在候选分母中，标为缺失/不可排名；不能静默从覆盖率分母移除。
- 官方涨停池不含 ST/科创板的限制，不影响基础行情排名；它只影响“官方涨停名单”这一独立数据集。

## 6. Invest Agent 接入方式

Invest Agent 不增加逐工具 wrapper。现有 external MCP registry 会动态发现 market-data-tool 新工具。

需要做的工作限于：

1. 确认新工具仍是只读、无用户 scope、无 Workspace/服务凭据访问。
2. 通过现有 MCP probe 验证生产 `tools/list` 和一次真实只读调用。
3. 在通用 Agent 数据使用规范中强调：
   - 排名必须说明排序字段和日期；
   - `partial` 不得表述为完整排名；
   - 用户自定义指标缺少公式时不得自行固化定义；
   - 不同分类标准不得混排。
4. 不修改真实用户 Workspace 模板；mg 的既有任务指令如需调整，必须单独得到用户确认。

## 7. mg 自动化任务的建议调整

当前生产指令已经要求“只写可靠数据、不以推断补空、不把有限返回表述为全市场完整排名”，这个原则应保留。

建议只做最小改动：

- 把“行业内涨幅靠前公司、资金流入较强公司”明确为调用通用排名工具，并写明 Top N；
- 把分类固定为申万一级；概念/ETF 仅在有独立可靠来源时作为补充，不与申万排名混排；
- 北交所排除，其他板块按工具实际 coverage 纳入；
- 删除或暂不要求未定义的“涨跌加速名单”；
- 若 mg 后续给出自己的可计算定义，只修改其自动化任务指令，不修改公共数据接口。

该调整属于用户自动化配置，不是本方案自动授权的生产操作。

## 9. 验收标准

### 数据工具

- 同一交易日能基于申万一级完整候选池返回每行业指定原始字段的 Top/Bottom N。
- 默认排除北交所；其他板块按实际可用性纳入并分类计数。
- 每个行业均能看到候选数、可排名数、缺失数和覆盖率。
- 部分源失败时结果为 `partial`，缺失不会被解释成“没有上涨/没有资金流”。
- 不存在名为“涨跌加速”的固定字段或隐含算法。
- MCP 返回不超过 1,000 行且不因展示截断丢失覆盖分母。

### Invest Agent

- 无新增 market-data-tool 同名 wrapper 或 mg 专用服务分支。
- Agent 使用排序字段、日期和 coverage 生成结果。
- 用户没有定义自定义信号时，Agent只展示基础事实，不自行决定指标定义。
- 运行失败、超时和报告发布仍由现有自动化状态机处理。

### mg 任务

- 明确申万一级、Top N、北交所排除和 partial 表达规则。
- 自定义信号仅在用户给出公式后进入任务指令。
- 复盘表中的名单可追溯到工具返回的交易日、排序字段和覆盖信息。

## 10. 风险与控制

- 当前申万成分是“当前成分”，用于历史日期时存在幸存者偏差；必须显式告警。
- 免费源没有 SLA；coverage 必须按每次实际结果计算，不能写固定承诺。
- 全市场逐股资金流是单源且可能限频；基础行情与资金字段要允许分别降级。
- 31 行业全量扫描仍有时延风险；优先复用收盘后快照池和批量请求，不允许 Agent 逐股循环。
- Top N 是展示截断，不是数据覆盖截断；两者必须在 meta 中分开表达。
