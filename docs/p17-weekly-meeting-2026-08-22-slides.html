内核重构 · 为什么换

旧内核的三个痛，新内核逐一拆掉

内核现在 = Mastra，一个进程内 Agent 框架。当时为什么非换不可：

旧内核（Codex）的痛换成 Mastra 之后
① 太重，压垮服务器
Agent 跑在外部子进程，负载失控，几次过载死机		内核与主服务同进程：资源占用可控可观测，超限自动重启
② 模型绑死，成本难控
GPT 只能走中转，中转不稳；国产模型接不进来		模型网关开放：国产模型即插即用——国内更稳、成本更低
③ 黑盒 harness
上下文怎么组装、怎么裁剪完全调不了——harness 不在我们掌控中		上下文与提示词构建全在自己代码里：每一步可调、可测、可审计
换内核、保产品：对外行为原样未动，用户无感切换。

功能规划

接下来全是优化题

  • 性能质量：稳定性与可靠性——重点解决：推送通道 · 上游模型供应稳定 · 行情数据完整性与准确性 等
  • UI 交互：把日常使用路径做得顺滑、直观
  • 交付上手：让新用户更容易上手，更容易向其他人演示推广

不新增功能面——所有投入花在把现有功能做稳、做好用、好交付。
