> 2026-06-01 修订：本文记录的是旧自研 Agent Runtime 阶段的能力审计。新的目标架构已调整为“本机 Codex + ACP + invest-agent 确定性工具/数据层”。详见 [17-codex-acp-runtime-migration.md](./17-codex-acp-runtime-migration.md)。

本文用于确认 Experimental MVP 已经实现的能力、当前行情数据边界，以及与客户会议设想之间的差距。后续项目计划应基于本文拆任务。

## 1. 总体结论

当前版本已经具备完整的 Agent Runtime 闭环：微信接入 + 自然语言理解 + 16 个 Runtime 工具 + 会话记忆 + 盘中巡检提醒 + 复盘闭环 + 只读 Dashboard。产品形态已从"关键词命令机器人"转向"AI Agent + 确定性工具"。

尤其需要注意：

- Agent Runtime 已完全替代旧关键词路由，所有定性判断由 AI 完成。
- 16 个 Runtime 工具已接入：持仓池(3)、自选池(3)、监控概览(1)、提醒规则(3)、信号配置(2)、交易预案(3)、复盘(3)、巡检间隔(1)。
- 复盘闭环已完成：预案→巡检提醒→复盘（含建议）→调整预案。
- 13 个系统信号可配置开关和参数（含资金流信号）。
- Dashboard 可操作看板已完成：网页端直接管理持仓、自选、预案、提醒、信号。
- 东方财富资金流数据已接入：主力/超大单/大单净流入，用于巡检和复盘。
- Agent 决策过程已持久化追踪（`agent_traces` 表）。
- 主力控盘、筹码集中度、盘口异动、逐笔成交等数据目前没有直接数据源。

### 1.1 Agent Runtime 当前状态

已实现：

- 用户消息入口先进入 Agent Runtime。
- Runtime 根据用户消息和会话记忆选择工具、直接回答或追问。
- 工具执行后，AI 会读取工具结果生成最终用户回复。
- 会话记忆保存在 `settings` 表，支持 `activePool`、`lastMentionedStocks` 等字段。
- 已移除旧关键词路由作为主入口；旧 handler 仅作为底层工具复用。
- 查询操作会从 DB 获取实际股票列表，确保指代解析正确。
- 记忆清洗：`lastMentionedStocks` 只保留 `{code, name}`，防止字段污染。

当前支持 Runtime 工具（16 个）：

| 类别 | 工具名 | 说明 |
|------|--------|------|
| 持仓池 | `query_holding_pool` | 查询持有股票池 |
| | `add_holding_stocks` | 添加持有股票 |
| | `remove_holding_stocks` | 移除持有股票 |
| 自选池 | `query_watchlist` | 查询自选池 |
| | `add_watchlist_stocks` | 添加自选股 |
| | `remove_watchlist_stocks` | 移除自选股 |
| 监控概览 | `query_monitor_overview` | 聚合持仓、自选、提醒、预案、事件 |
| 提醒规则 | `query_alert_rules` | 查询提醒规则 |
| | `set_alert_rule` | 设置提醒规则 |
| | `remove_alert_rule` | 移除提醒规则 |
| 信号配置 | `query_signal_config` | 查询信号开关和参数 |
| | `update_signal_config` | 更新信号配置 |
| 交易预案 | `query_stock_plan` | 查询交易预案 |
| | `set_stock_plan` | 设置交易预案 |
| | `remove_stock_plan` | 移除交易预案 |
| 复盘 | `generate_daily_review` | 生成日复盘 |
| | `generate_weekly_review` | 生成周复盘 |
| | `query_review` | 查询历史复盘 |
| 巡检间隔 | `set_alert_interval` | 设置巡检间隔 |

当前缺口：

- 复盘模板不可配置（格式硬编码在 AI prompt 中）。
- 同一股票同类信号短时间内重复触发，无合并降噪机制。
- `direct_answer` 对产品能力说明有用，但不能替代真实查询工具。

## 2. 已实现能力

### 2.1 微信接入

已实现：

- `/admin/weixin` 管理页。
- 扫码绑定微信。
- 服务重启后恢复微信监听。
- 用户从微信发送消息，服务端 Agent 回复。
- 管理页显示最近会话与提醒推送就绪状态。
- 管理页提供"测试提醒"按钮，用于验证主动提醒链路。
- 管理页提供"模拟触发"按钮，用于发送一条不污染真实提醒记录的测试行情提醒。

当前限制：

- 单客户版本。
- 没有多租户、权限、会话管理后台。
- 主动推送提醒已接入实验链路：保存最近互动用户，巡检触发后优先向该用户推送。
- 主动推送能否稳定工作取决于微信服务端是否接受最近会话发送；失败会自动落入内部队列。

### 2.2 自选股与持仓

已实现：

- 加入/移除/查看自选股。
- 维护持有股票池。
- 查询当前持有股票和基础行情。
- 清仓式卖出记录。
- 自选股来源与关注理由字段。
- 人工交易预案：支撑位、压力位、目标位、止损位和策略备注。
- 提醒规则管理：支持目标价、支撑价等指标提醒，可按股票配置。

当前限制：

- 暂不支持部分卖出。
- 不做仓位管理；成本和数量仅为可选备注。
- 预案已有关键价位字段，但还没有目标仓位、分批减仓计划、版本追踪和批量管理。

### 2.3 行情与技术指标

当前行情源：腾讯行情接口。

当前可获取字段：

- 股票代码、名称
- 最新价
- 昨收
- 今开
- 最高价
- 最低价
- 涨跌额
- 涨跌幅
- 成交量
- 成交额
- 换手率
- 行情时间
- 历史日 K：日期、开盘、收盘、最高、最低、成交量

当前可计算指标：

- MA5 / MA10 / MA20 / MA60
- 均线趋势：多头、空头、震荡
- MACD 金叉/死叉/多头/空头
- 成交量相对 5 日、20 日均量的放量/缩量判断
- 近 20 日支撑位、压力位粗略估算

当前限制：

- 没有分钟级 K 线。
- 没有盘口五档深度的结构化解析。
- 没有逐笔成交。
- 资金流数据已通过东方财富 API 接入（主力/超大单/大单/中单/小单净流入）。
- 没有主力控盘、筹码集中度、筹码峰、主力成本等直接指标。
- 当前技术图形只能通过文本指标描述，不能生成 K 线图或图片分析。

### 2.4 盘中巡检与提醒

已实现：

- 调度器启动后每 5 分钟执行一次巡检（间隔可配置）。
- 非 A 股交易时间自动跳过。
- 交易时间判断：工作日 9:30-11:30、13:00-15:00。
- 巡检对象：自选股 + 未卖出持仓。
- 支持 1 小时冷却去重。
- 触发结果会写入 `alert_events`，供日复盘/周复盘反馈。
- 用户可通过微信反馈最近提醒是否有用、无用或误报，反馈会写回 `alert_events.feedback`。
- 巡检会优先使用人工交易预案；没有人工预案时，再使用最近每日复盘生成的临时预案。
- 提醒规则可按股票配置（目标价、支撑价等），用户通过微信自然语言管理。

当前支持 13 个系统信号：

1. 涨跌幅超阈值（默认 3%）
2. 换手率超阈值（默认 5%）
3. 量比超阈值（默认 2 倍）
4. 放量突破压力位
5. 跌破支撑位
6. 接近支撑位
7. 接近压力位
8. 接近目标位
9. 跌破止损位
10. MACD 金叉/死叉
11. 盘口买卖量差偏斜
12. 主力净流入超阈值（资金流信号）
13. 超大单净流入超阈值（资金流信号）

每个信号均可独立开关，参数可调（通过 `query_signal_config` / `update_signal_config` 工具）。

### 2.5 复盘闭环

已实现：

- 日复盘：读取持仓、自选、预案、当日提醒事件，由 AI 生成复盘报告。
- 周复盘：汇总一周提醒事件和复盘。
- 复盘查询：查看指定日期的历史复盘。
- 复盘建议回写：无预案股票自动输出建议（支撑/压力位估算），有预案但价位偏移超 2% 输出调整建议。
- 用户主动触发复盘时强制重新生成（`force: true`），避免返回缓存旧数据。

### 2.6 Dashboard 可操作看板

已实现：

- `GET /dashboard` 深色主题自包含 HTML 页面（Tailwind CDN + 原生 JS）。
- `GET /api/dashboard` 聚合 JSON API。
- 模块：概览卡片、持仓池、自选池、交易预案、提醒规则、信号配置、提醒事件（按推送批次分组）、最近复盘、资金流向数据。
- 提醒事件按推送批次分组（2 分钟窗口内的事件归为同一批），显示真实北京时间。
- 页面支持手动刷新和模块折叠。
- **可操作**：网页端可直接添加/移除持仓和自选、新建/编辑/删除预案和提醒、切换信号开关、调整巡检间隔。
- Dashboard 已集成资金流向数据（主力/超大单/大单净流入）。

当前限制：

- 数据缺口硬编码，不反映实时数据源状态。

## 3. 与客户设想的差距

### 3.1 客户设想

客户希望：

- A 股交易时段内，每 5 分钟自动检查。
- 基于自选股、持仓股、目标股票进行盯盘。
- 条件到位后主动给微信发提醒。
- 提醒依据包括昨晚复盘趋势、当天触发条件、技术形态、主力控盘相关指标。
- 日复盘、周复盘、月复盘基于提醒结果不断校正指标。

### 3.2 当前达成程度

已达成：

- 每 5 分钟巡检框架（间隔可配置）。
- 自选股/持仓股作为巡检池。
- 基础行情与日 K 技术指标。
- 复盘中记录提醒事件，复盘闭环完整。
- 提醒反馈记录，可沉淀"有用 / 无用 / 误报"。
- 最近会话主动推送实验链路。
- 主力控盘缺口会在输出中明确说明，不编造。
- 提醒规则可按股票配置。
- 交易预案管理。
- Dashboard 可操作看板（网页端管理持仓/自选/预案/提醒/信号）。
- 东方财富资金流数据接入（主力/超大单/大单净流入）。
- Agent 决策过程持久化追踪（`agent_traces` 表）。
- 资金流信号接入巡检（主力净流入、超大单净流入超阈值触发）。

未达成：

- 东方财富主力控盘/筹码集中度数据接入。
- 稳定微信主动提醒闭环。
- 分钟级盘中指标。
- 复盘模板可配置。
- 提醒降噪（同股票同信号短时间重复触发无合并机制）。
- 个性化策略指标库。
- 指标命中/误报后的自动参数优化。目前只记录反馈，还不会自动调参。

## 5. 当前判断

当前版本是一个功能完整的 Agent MVP：用户可以通过微信自然语言或 Dashboard 网页完成持仓管理、自选管理、提醒配置、交易预案、复盘生成、信号管理等全部核心操作。东方财富资金流数据已接入巡检和复盘。下一步重点是提醒降噪（避免同股票同信号高频轰炸）和复盘模板可配置。不要恢复旧命令路由。
