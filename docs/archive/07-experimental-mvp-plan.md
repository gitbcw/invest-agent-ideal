# Experimental MVP 任务清单

## 版本定位

Experimental MVP 是基于当前代码雏形的实验版本，不重做架构，不先做独立 App。它的目标是验证最新产品设计中的核心闭环是否可用：

```text
持仓/自选录入
→ 选股问答生成候选
→ 加入自选
→ 夜间复盘生成明日预案
→ 盘中提醒验证预案
→ 收盘复盘记录判断结果
```

本版本承认策略资料还不完整。会议中提到的三本书、思维导图、行业信息源清单、筛选指标细则、自选股截图等，先作为后续输入资料，不阻塞实验版本。

## 实验版原则

1. 不推翻当前架构，只在现有代码上增量改造。
2. 先跑通闭环，再追求策略强度。
3. 所有 AI 输出必须区分事实、推断和建议。
4. 策略不足时明确标注“当前使用实验规则”。
5. 数据缺失时说明缺口，不编造来源。
6. 每个功能都要能为后续复盘反馈留下记录。

## 当前代码基础

已具备：

- Fastify HTTP 服务。
- ACP 消息入口。
- 消息路由。
- 持仓管理 handler。
- 自选股 handler。
- 选股分析 handler。
- 提醒 handler。
- 复盘 handler。
- 腾讯行情接口。
- MA、MACD、量能分析。
- DeepSeek 调用。
- SQLite 存储。

需要改造：

- 持仓卖出和多次交易记录。
- 提醒配置实际生效。
- 提醒重复推送。
- 复盘日期解析和模板。
- 预案记录。
- 选股报告结构。
- AI 输出防幻觉约束。

已知数据缺口：

- 主力控盘、筹码集中度、大单净流入等指标是客户关注重点，但当前腾讯行情接口不能稳定提供完整数据。
- 实验版只能使用可获取的价格、涨跌幅、成交量、换手率、均线、MACD 等指标做替代观察。
- 所有涉及主力资金或控盘的判断必须标注为“当前缺少直接数据，仅作间接观察”，后续通过接入更合适的数据源或图片/软件导出数据补齐。

## 任务分组

### A. 基础问题修正

目标：让现有功能在实验版本中可靠可用。

- [x] 修正持仓卖出逻辑：只关闭未卖出持仓。
- [x] 明确是否支持部分卖出；实验版可先不支持，但要给出提示。
- [x] 查询持仓时，行情获取失败不能把市值算成 0，应标注行情缺失。
- [x] 修正历史复盘查询：带日期的复盘请求应优先查询历史文档。
- [x] 修正周复盘指标判断：避免取 30 条 K 线却要求大于 30 条。
- [x] 清理未使用 import，降低维护噪音。
- [x] DeepSeek API key 缺失时给出清晰错误提示。

验收：

- 持仓买入、查询、卖出基础流程可用。
- 查询历史复盘不会误生成今日复盘。
- AI 配置缺失时不会返回难懂异常。

### B. 数据模型小幅扩展

目标：为预案、提醒记录和反馈闭环留出最小数据结构。

- [x] 新增每日预案表或等价存储。
- [x] 新增提醒触发表或等价存储。
- [x] 新增用户操作记录表或等价存储。
- [x] 自选股记录加入来源和关注理由。
- [x] 持仓记录支持状态字段或更明确的 open/closed 查询。

建议新增概念：

- `daily_plans`：每日预案。
- `alert_events`：提醒触发记录。
- `trade_actions`：用户实际操作记录。
- `strategy_profile`：实验策略方案描述，可先用 settings 存 JSON。

验收：

- 夜间复盘能保存明日预案。
- 盘中提醒能保存触发记录。
- 收盘复盘能读取预案和提醒记录。

### C. 选股问答升级

目标：让选股问答从泛泛分析变成可进入自选股闭环的结构化报告。

- [x] 更新选股 Prompt。
- [x] 输出行业趋势、初筛逻辑、候选公司、入选理由、风险点、资料来源和数据缺口。
- [x] 明确建议加入自选观察的股票。
- [x] 支持用户根据报告中的代码加入自选股。
- [x] 记录自选股加入理由为“来自选股报告”。
- [x] 主力资金、控盘等无法直接验证的信息必须标注数据缺口。

实验版约束：

- 不能保证完整行业数据库。
- 若缺少实时基本面数据，必须说明“当前基于公开常识和模型知识，需后续接入结构化数据验证”。

验收：

- 用户输入行业或概念后，可以得到 3-5 家候选公司。
- 候选公司可被加入自选股。
- 报告不会编造精确财务数字或虚假来源。

### D. 每日复盘和明日预案

目标：把复盘从“行情总结”升级为“明日行动预案”。

- [x] 升级日复盘模板。
- [x] 持仓股和自选股分区展示。
- [x] 每只重点股票生成明日观察点。
- [x] 生成支撑位、压力位、关注条件、风险点。
- [x] 明确 AI 判断记录和置信度。
- [x] 保存每日预案供次日提醒使用。

实验版复盘结构：

```markdown
# 每日投资复盘

## 一、今日市场概况
## 二、持仓分析
## 三、自选股机会
## 四、重大信息过滤
## 五、明日交易预案
## 六、AI 判断记录
```

验收：

- 每日复盘包含“明日交易预案”。
- 至少对持仓股和自选股给出不同类型的关注建议。
- 次日提醒可以引用最近一份预案。

### E. 盘中提醒升级

目标：提醒不再只是涨跌幅异动，而是结合预案和实验规则。

- [x] 读取自选股、持仓股和最近每日预案。
- [x] 固定规则仍保留：涨跌幅、换手率、MACD、放量。
- [x] 新增实验规则：接近支撑位、接近压力位、放量突破、跌破观察位。
- [x] 提醒内容说明是否符合昨晚预案。
- [x] 记录每次提醒事件。
- [x] 增加简单去重或冷却，避免同一信号反复刷屏。

提醒格式：

```text
股票：
当前状态：
触发原因：
与昨晚预案关系：
可选动作：
风险提示：
```

验收：

- 同一股票同一信号不会短时间重复提醒。
- 提醒能说明“符合预案 / 偏离预案 / 未找到预案”。

### F. 收盘反馈和周/月复盘占位

目标：为后续策略优化铺路，不在实验版做完整统计系统。

- [x] 收盘复盘读取当日提醒事件。
- [x] 记录提醒是否初步有效：命中、误报、待验证。
- [x] 周复盘先输出本周提醒列表和初步统计。
- [ ] 月复盘保留占位，但说明实验版暂不完整支持。

验收：

- 日复盘能看到当天提醒记录。
- 周复盘能看到本周信号概览。

### G. AI 输出和防幻觉落地

目标：把防幻觉规则落实到主要 Prompt 和输出模板里。

- [x] 通用聊天 Prompt 增加事实、推断、建议分层要求。
- [x] 选股 Prompt 增加来源和数据缺口要求。
- [x] 复盘 Prompt 增加不确定性和风险提示。
- [x] 盘前提醒 Prompt 增加不编造外部新闻要求。
- [x] 数据不足时返回“需要补充的数据”，而不是强行分析。
- [x] 主力控盘相关输出必须说明是否有直接数据来源；没有时只能写间接观察。

验收：

- 选股、复盘、提醒输出都含有风险提示。
- 涉及数据来源时，不会假装已经读取未接入的信息源。

### H. 实验版使用说明

目标：让第一个试用用户知道怎么用、哪些能力还在实验。

- [x] 新增实验版使用说明文档。
- [x] 列出支持的微信指令示例。
- [x] 列出当前实验策略能力。
- [x] 列出暂不支持能力。
- [x] 列出用户需要继续提供的资料。

验收：

- 用户可以照着说明完成一次完整闭环。

### I. 最小测试和演示流程

目标：后续策略和功能快速迭代时，基础闭环不被改坏。

- [x] 新增 `npm run smoke`。
- [x] 使用独立 smoke 数据库，不污染正式数据。
- [x] 验证自选股来源、每日预案、提醒事件、操作记录。
- [x] 验证部分卖出保护和历史复盘查询。
- [x] 新增本地演示检查清单。

验收：

- 每轮改造后可以运行 `npm run smoke` 做基础验证。
- 演示流程可以指导本地 API 和微信联调。

## 建议实施顺序

1. A：先修基础问题。
2. B：补最小数据结构。
3. D：升级复盘并保存明日预案。
4. E：升级盘中提醒并记录事件。
5. C：升级选股问答和加入自选闭环。
6. G：统一防幻觉 Prompt。
7. F：补收盘反馈和周复盘占位。
8. H：整理实验版使用说明。

## 实验版不做事项

- 不做独立 App。
- 不做自动交易。
- 不做完整行业数据库。
- 不做研报/PDF/视频处理。
- 不做订阅支付。
- 不做多用户复杂权限。
- 不承诺策略准确率。
- 不完整实现技术方案二/三。

## 实验版完成定义

Experimental MVP 完成时，应能演示以下流程：

1. 用户录入一只持仓。
2. 用户添加几只自选股。
3. 用户发起一次行业/概念选股问答。
4. 用户把报告中的候选股加入自选。
5. 系统生成每日复盘和明日预案。
6. 系统在盘中根据行情和预案触发提醒。
7. 收盘复盘记录提醒和预案的初步有效性。
8. 用户继续补充策略资料，系统文档和项目计划随之更新。
