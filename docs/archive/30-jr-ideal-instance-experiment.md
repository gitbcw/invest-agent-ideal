# 30 — JR 方法参考实验测试方案

> Current status: active method-reference test plan.
>
> Supersedes the old Profile/Evolution interpretation in archived docs `31`, `32`, and `33`. Current methodology persistence is Strategy Skill skeleton plus instance expansion candidates. Profile is only a runtime compatibility summary.

## 目的

本实验用于验证 `jr-backend` 中有价值的投资助手工作纪律，能否作为当前 Invest Agent 的方法论参考层被吸收，而不是把 `jr-backend` 作为第二套运行框架塞进平台。

实验实例：

- `instanceId`: `invest-agent-jr-ideal`
- `ownerUserId`: `jr-ideal-tester`
- `skillBundleId`: `invest-agent-jr-ideal`（JR 方法参考实验技能包）
- 来源样板：`/Users/combo/MyFile/projects/jr-backend`

## 重要边界

本实验不原样运行 `jr-backend` 目录，也不创建第二套文件型运行时存储。

`jr-backend` 的 `config/`、`knowledge/`、`memory/`、`reports/` 只作为方法参考和质量基准；当前平台运行时仍使用服务端数据库、实例 scope、sandbox、Dashboard/Investment Workbench、微信推送、trace、Strategy Skill 实例展开候选和 confirmation 机制。

源头优先级：

1. 当前实例服务数据：持仓、自选、预案、提醒、复盘、观点、审计和推送状态。
2. Strategy Skill 的受保护骨架和已确认/待处理的实例展开候选。
3. Profile 运行时兼容摘要，例如偏好摘要、路由残留和旧接口兼容字段。
4. 项目方法论文档，例如 `docs/02-investment-methodology.md`。
5. Hermes 对话记忆，只用于连续性和短中期上下文，不能覆盖 Strategy Skill 实例展开。
6. JR 参考材料，只提供低打扰、强确认、复盘闭环、观点追踪和方法进化纪律。

因此测试结论应区分三件事：

1. JR 的方法纪律是否被保留下来。
2. 当前平台的 Strategy Skill 实例展开、工具、调度、审计和推送机制是否足以承载这些纪律。
3. Hermes 记忆、skill、profile 兼容摘要、服务数据之间是否出现重复事实源或冲突。

## 成功标准

### P0：实例与隔离

- 平台能列出 `invest-agent-jr-ideal` 实例。
- 该实例显示为 `invest-agent` 项目类型。
- 该实例绑定 `invest-agent-jr-ideal` skill bundle，且展示为 JR 方法参考实验，而不是完整 JR 运行框架。
- 该实例不会读取或改写 `invest-agent-primary`、`invest-agent-mg` 或其他实例的数据。

### P0：新手引导

当实例没有持仓和自选时，助手应进入设置引导，而不是生成空复盘。

引导应覆盖：

- 持仓与观察仓录入。
- 投资风格选择或自定义。
- 基本面、技术面、宏观和风控方法确认。
- 日/周/月复盘、公司分析、智能盯盘能力确认。
- 低打扰通知策略确认。

任何长期写入必须先生成结构化草案，再请求确认。

### P0：日复盘质量

日复盘必须包含：

- 今日是否需要操作。
- 今日是否需要关注。
- 今日是否需要用户确认。
- 今日最重要原因。
- 组合健康检查：仓位纪律、集中度、现金安全垫、非核心复杂度、风险事件、风格漂移。
- 观点 / 理由 / 操作建议 / 验证点 / 失效信号或预计复盘时间。
- 数据来源与数据缺口。

若建议买入、卖出或再平衡，必须先输出操作确认单，不得直接要求交易。

### P0：周/月复盘闭环

周复盘必须能消费日复盘观点、提醒事件、预案变化和用户反馈，并输出：

- 周末 10 分钟投资会议。
- 日复盘观点回测。
- 风险雷达。
- 用户行为纠偏。
- 下周执行建议。
- 方法改进候选，但不自动修改方法。

月复盘必须能消费周复盘和观点统计，并输出：

- 策略执行质量。
- 系统性偏差。
- 未来 1-3 个月情景分析。
- 方法、信息源、调度或盯盘规则改进建议。

### P1：低打扰盯盘

盯盘应只在异常触发时推送。

分级规则：

- P0：立即推送。
- P1：晚间汇总。
- P2：仅记录。

提醒必须说明：

- 触发事项。
- 与预案或日复盘观察点的关系。
- 建议动作。
- 是否需要用户确认。
- 验证/失效信号。

### P1：行为纠偏

当用户出现以下倾向时，助手应温和但明确纠偏：

- 频繁短线追问。
- 观察仓未到规则区间却想追高。
- 非核心仓位因短期上涨被临时升格。
- 忽略现金安全垫或仓位上限。
- 没有新增信息却反复要求刷新同一报告。

### P1：平台承载能力

测试过程中记录哪些 JR 方法纪律当前缺少明确承载位，例如：

- Strategy Skill 实例展开候选与确认后的应用机制。
- 方法论变更记录。
- 用户反馈表。
- 信息源可靠性评价。
- 报告 artifact 目录或索引。
- 通知分级和晚间汇总队列。
- Hermes 记忆、Profile 兼容摘要和 Strategy Skill 实例展开之间的冲突处理。

这些不是实验失败，而是平台后续承载能力清单。测试不再要求恢复 JR 的 `config/knowledge/memory/reports` 文件写入。

## 测试用例

### Case 1：空实例新手引导

输入：

```text
我想开始用这个投资助手
```

预期：

- 不生成复盘。
- 请求录入持仓和观察仓。
- 明确所有长期写入需要确认。

### Case 2：持仓录入草案

输入：

```text
我现在持有贵州茅台 100 股，成本 1500；观察中证红利 ETF，如果回调到 1.15 附近提醒我。
```

预期：

- 输出结构化草案。
- 区分持仓和观察仓。
- 不直接写入，等待确认。

### Case 3：风格与方法确认

输入：

```text
我偏稳健价值型，不想频繁操作。技术面只用来辅助买卖节奏，仓位上不要单票太重。
```

预期：

- 总结投资风格、基本面、技术面、风控偏好。
- 请求用户确认。
- 不直接改变方法论。

### Case 4：日复盘

输入：

```text
生成今日复盘
```

预期：

- 如果缺持仓，转新手引导。
- 如果已有持仓，生成符合 P0 日复盘质量标准的复盘。
- 输出动作结论、组合健康检查和观点追踪。

### Case 5：追高纠偏

输入：

```text
这个观察股今天涨很多，要不要现在追进去？
```

预期：

- 不直接鼓励买入。
- 检查是否触发已确认观察条件。
- 若未触发，提示追高风险和等待条件。

### Case 6：周复盘

输入：

```text
生成本周复盘
```

预期：

- 回测日复盘观点。
- 输出周末 10 分钟投资会议和风险雷达。
- 标出方法改进候选但不自动修改方法。

### Case 7：月复盘

输入：

```text
生成本月总结，顺便看下未来一到三个月怎么应对
```

预期：

- 先回顾再展望。
- 未来判断使用情景、触发条件、组合影响、应对策略、验证/失效信号。
- 不给确定性收益预测。
