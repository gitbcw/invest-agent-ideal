# 阶段开发路线图

本文档用于把产品设计转成阶段性项目计划。每当设计文档更新，路线图也应随之调整。

## 阶段 0：文档和共识沉淀

目标：

- 建立产品事实源。
- 明确产品定位、功能范围、核心流程和防幻觉边界。

交付物：

- 产品定位与愿景文档。
- 用户投资方法论文档。
- PRD。
- 核心业务流程文档。
- AI 输出规范与防幻觉规则。
- 阶段开发路线图。

验收标准：

- 后续新信息可以被归入对应文档。
- 能基于文档拆出阶段任务。

当前状态：已基本完成，后续作为产品事实源持续维护。

## 阶段 1A：Experimental MVP

目标：

- 基于当前代码雏形，用最小改造验证最新产品闭环。
- 通过微信完成基础投资助手交互。
- 跑通持有股票池、自选、选股问答、夜间复盘、盘中提醒和收盘反馈的实验闭环。
- 将用户消息入口从旧关键词路由升级为 Agent Runtime。

主要功能：

- 修正现有持仓、提醒、复盘等基础问题。
- 持有股票池维护和查询。
- 自选股添加、移除和查询。
- 行情查询。
- 基础技术指标分析。
- 结构化选股问答报告。
- 选股报告到加入自选股的闭环。
- 每日预案记录。
- 基于预案和触发条件的基础日提醒。
- 升级版每日复盘文档。
- OpenClaw/ACP 微信接入。
- Agent Runtime：AI 选择工具、工具执行、AI 生成最终回复、保存会话记忆。

不做：

- 复杂行业数据库。
- 多技术方案切换。
- 订阅支付。
- 自动交易。
- 视频处理。
- 完整多模态输入。

验收标准：

- 用户可以通过微信录入持仓和自选股。
- 用户可以通过自然语言维护持有股票池和自选池，不需要记命令或股票代码。
- 用户可以发起一次选股问答并把候选股加入自选。
- 系统可以生成包含明日观察点的每日复盘。
- 系统可以在交易时段对自选股或持仓股触发基础提醒。
- 提醒能够说明是否关联昨晚预案。
- AI 输出没有明显编造数据或来源。

详细任务清单见 [07-experimental-mvp-plan.md](./07-experimental-mvp-plan.md)。

当前状态：

- Agent Runtime v1 已在本地实现并通过 smoke。
- 旧关键词路由不再作为用户消息主入口。
- 当前以本地微信测试为主，暂不要求每轮都部署服务器。
- 下一步优先补 `query_monitor_overview`，让用户能询问“当前监控了什么、指标是什么”。

## 阶段 1B：MVP 稳定版

目标：

- 在实验版验证有效后，补齐稳定性、可用性和关键体验问题。

主要功能：

- 完善错误处理。
- 完善 Agent Runtime 工具覆盖，包括提醒、监控概览、预案和复盘。
- 完善提醒去重和冷却。
- 完善复盘反馈记录。
- 补充最小测试。
- 整理部署和试用说明。

验收标准：

- 可以支持一个真实用户连续试用。
- 核心流程有基础测试覆盖。
- 主要异常场景有明确提示。

## 阶段 2：复盘反馈系统

目标：

- 让系统从“生成复盘”升级为“验证预案并反馈策略”。

主要功能：

- 昨晚预案记录。
- 盘中提醒与预案关联。
- 用户操作记录。
- 收盘后命中、误报、漏报判断。
- 周复盘。
- 月复盘。
- 指标调整建议。

不做：

- 自动替用户调整核心策略。
- 复杂收益归因。

验收标准：

- 每条提醒能追溯到触发条件和预案。
- 日复盘能判断昨日预案是否命中。
- 周复盘能统计高质量和低质量信号。
- 用户可以基于复盘决定是否调整规则。

## 阶段 3：行业分析与企业筛选

目标：

- 强化基本面和行业分析，解决人工信息获取耗时问题。

主要功能：

- 信息源清单管理。
- 行业关键词分析。
- 行业公司初筛 5-10 家。
- 精选候选 3-5 家。
- 基本面指标打分。
- 行业和公司资料来源追溯。
- 低相关度信息过滤。

不做：

- 覆盖所有行业的全自动高精度数据库。
- 未经验证的信息源自动入库。

验收标准：

- 给定行业关键词，能产出有来源、有风险提示的候选公司报告。
- 公司筛选逻辑能体现市场容量、占有率、增长空间和研发费用率等指标。
- 用户可以把报告中的公司加入自选股。

## 阶段 4：技术方案可切换和策略模型

目标：

- 将 DaiYk 的技术面方法沉淀成可配置、可验证、可切换的策略方案。

主要功能：

- 技术方案一导入。
- 支持方案二/三后续导入。
- 按股票绑定技术方案。
- 自定义提醒模型。
- K 线形态识别。
- 支撑位和压力位识别。
- 低位放量、缩量回踩、主力资金等组合信号。
- 策略触发记录和效果复盘。

不做：

- 不经用户确认自动替换策略。
- 不把未经实战验证的信号作为强建议。

验收标准：

- 用户可以指定某只股票使用某个技术方案。
- 系统能根据策略方案触发提醒。
- 复盘能评估策略信号有效性。

## 阶段 5：多模态输入

目标：

- 让 AI 能处理用户日常投资资料。

主要功能：

- 自选股截图识别。
- 持仓截图识别。
- K 线图截图分析。
- 研报 PDF 摘要。
- 财经文章截图提取。

不做：

- 初期不做视频深度理解。
- 不把 OCR 结果直接当作事实，必须允许用户确认。

验收标准：

- 用户发送自选股截图后，系统能识别股票并请求确认。
- 用户发送 K 线截图后，系统能给出初步形态分析并标注不确定性。

## 阶段 6：订阅试用和合作支持

目标：

- 支持一个月试用和后续年度订阅合作。

主要功能：

- 试用期记录。
- 订阅有效期。
- 用户权限。
- 使用记录。
- 私有方法论保护。
- 知识产权边界说明。

不做：

- 初期不做复杂计费系统。

验收标准：

- 能区分试用用户和正式订阅用户。
- 用户策略资料可以隔离和保护。
- 产品具备长期合作服务基础。

## 当前优先级建议

1. 继续阶段 1A 本地体验测试，优先保持 Agent Runtime 主入口，不恢复旧关键词路由。
2. 新增 `query_monitor_overview`，让用户能查询“当前监控了什么、指标是什么”。
3. 将提醒规则、交易预案、复盘工具逐步接入 Runtime。
4. 增加 Agent trace 持久化，支持排查“AI 收到什么上下文、为什么这样回复”。
5. 等 DaiYk 提供信息源清单、三本书、技术思维导图和自选股截图后，再细化阶段 3 和阶段 4。
