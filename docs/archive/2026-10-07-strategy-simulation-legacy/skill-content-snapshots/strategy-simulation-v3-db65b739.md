# 策略模拟

本 Skill 是系统播种的初始版本，用户可以复制、修改并形成自己的模拟方法。主流程由 Agent 编排：调用已挂载的行情/筹码/资金流工具，读取上一期模拟记录，按已确认策略分析，并把日报和结构化记录保存为当前用户的资产。服务层只负责自动化任务、数据工具、作用域、幂等、审计和受控文件保存。

## 工作边界

- 首次开启前，必须在一份最终模拟规则预览中确认标的范围、买入、卖出、仓位、分析时点、成本和缺失数据口径；普通模拟请求不进入多轮草案流程。
- 不完整或当前数据能力不支持的规则，进入澄清或受阻状态，不得静默替换规则。
- 日频默认在交易日收盘后运行；报告必须标明数据日期、分析时间和数据来源，不得把事后数据写成当时可见数据。
- 每日运行使用一个稳定的运行键（模拟 ID + 数据日期）；重复触发时读取已有记录，不重复追加。
- 使用 `automation.create` 创建每日任务；任务指令必须包含策略版本、数据范围、输出资产和失败处理方式。
- 使用 `assets.list`/`assets.version.read` 读取上一期记录，使用 `assets.conversation.save` 保存新日报或追加新版本；不得写任意本地路径。
- 文件记录是 Agent 模拟的历史事实源，不得把未取得的数据补成确定值；每条关键数据记录来源、as-of 和质量。
- 必须维护本轮证据表：每个标的、字段、日期范围、来源、单位、覆盖状态，以及“未查询/超时/空结果/不适用/结果被截断/待核验”。“本轮未取到”不能写成“数据源不存在”。
- 用户要求 N 个交易日时，必须先按交易日历列出 N 个判断日，并逐日核验策略条件；单个日期不满足不能外推整个窗口，`比值大于 1` 不能直接写成“发生上穿”。
- 批量工具返回被截断、超时或只覆盖部分标的时，先缩小日期/标的批次重试；未补齐前只能交付“部分覆盖分析”，不能宣布完整模拟完成。
- 只有用户明确要求长期自动运行时才创建自动化任务；一次性分析直接执行，不创建任务。
- 未经用户确认，不采用进化建议，不改变正在运行的策略快照；“采用候选”是一次独立确认，不要为同一候选重复登记多个确认草案。

## 默认运行方式

- 初始净值为 1，按归一化现金和仓位比例估算；如果没有明确的成交规则，只输出信号和条件，不伪造成交账本。
- 每个交易日生成一条运行记录；没有交易也要说明无操作原因。
- 说明信号、假设成交、成本、数据缺口、运行失败和最后成功日期，并将“策略判断”和“行情事实”分开。
- 需要历史复算或严格可重放时，可调用 `strategy_simulation.dry_run`；它是确定性校验工具，不是日常自动化主入口。
- 报告区分策略问题、数据问题和执行器问题，证据不足时允许不提出改动。
- 交付前逐项核对证据表、正文和附件；若任何关键因子未完成，报告标题和结论必须标明部分覆盖/未知，不能把一次调用失败写成数据能力不存在。
- 优先发现并调用筹码历史、资金流和均量工具。批量失败后拆小批次，至多追加两次有区别的尝试；不要连续原样重试。MA60 的每个判断日都需足够的前置交易日数据；可复核计算必须注明公式、单位和输入范围。
- 成交量异常、单位不明时，先核对来源和单位；无法核实则相应量能判断为未知，不得用另一天的数据证明当天结论不受影响。缺失因子不重新分配权重，ETF 不适用与股票数据缺失分开列示。
- 用户指出遗漏时，补齐并修订原请求的报告属于当前任务，不再要求一次确认；不得修改正式策略或实盘持仓。HTML 请求使用已有受控资产保存工具交付真实 HTML，不能用 Excel 替代后宣称完成。

## 进化建议

每周最多提出一个候选，结构固定为：

```text
发现 -> 证据 -> 可能解释 -> 只改变一个条件 -> 下一轮验证方式
```

候选只能进入待确认状态。用户确认后，使用版本化策略变更能力创建新版本；旧版本、旧账本和原始证据保持可读和可回滚。

## 可定制内容

用户可以调整提问方式、关注指标、候选排序、报告结构和可执行的买卖/仓位规则。自然语言规则无法完全执行时，Agent 应明确说明哪些判断由 Agent 完成、哪些数据或条件缺失，不得为了调用 `dry_run` 强行改写成另一套策略。

## 每日任务指令模板

自动化任务应按以下顺序执行：

1. 读取当前已采用的策略版本和上一期模拟记录。
2. 确定本次交易日和允许使用的数据截止时间。
3. 通过已挂载的行情 MCP 获取价格、交易状态、筹码集中度和主力资金流；外部工具不可用时记录缺口，不用代理值冒充原始数据。
4. 按策略逐标的给出“买入/卖出/持有/无法判断”和理由，记录事实来源及未知项。
5. 生成 Markdown 报告和结构化 JSON 记录，使用稳定运行键保存；失败时保留失败摘要，不覆盖上一期成功记录。
