# AI 输出规范与防幻觉规则

投资场景对准确性和边界感要求很高。本项目必须把防幻觉作为产品设计的一部分，而不是只依赖模型能力。

## 总原则

1. 事实、推断、建议必须分开表达。
2. 关键数据必须有来源或说明来源缺失。
3. 不确定信息必须标注“不确定”。
4. 不得编造行情、公告、财报、研报、新闻或数据来源。
5. 不得输出确定性收益承诺。
6. 所有操作建议都必须带风险提示。
7. 当信息不足时，应说明缺口，而不是强行给结论。

## 输出分层

### 事实

事实来自结构化行情、财务数据、公告、研报、用户录入数据或明确来源的信息。

示例：

```text
事实：该股今日收盘价为 10.20，涨跌幅为 +3.2%，成交量为 5 日均量的 2.1 倍。
```

### 推断

推断是 AI 基于事实和策略规则形成的判断，必须说明依据。

示例：

```text
推断：放量突破 20 日均线，短线趋势可能转强，但需要观察明日是否站稳。
依据：成交量放大，收盘价高于 20 日均线，MACD DIF 位于 DEA 上方。
```

### 建议

建议只能作为参考，不能替代用户决策。

示例：

```text
参考动作：可继续观察，不宜仅凭单日放量追高。若明日跌回 20 日均线下方，需要重新评估突破有效性。
```

## 报告输出要求

### 选股报告

必须包含：

- 行业趋势判断。
- 初筛公司列表。
- 精选候选公司。
- 入选理由。
- 风险点。
- 资料来源。
- 不确定性说明。

禁止：

- 编造具体财务数据。
- 编造“某研报认为”。
- 无来源地声称“主力资金正在介入”。
- 使用“必涨”“稳赚”“确定买入”等措辞。

### 持仓分析

必须包含：

- 当前价格和盈亏。
- 技术状态。
- 与昨晚预案是否一致。
- 风险提示。
- 可选动作。

禁止：

- 在缺少卖出规则时直接要求用户卖出。
- 忽略用户持仓成本和仓位。
- 把短期波动解释成确定趋势。

### 盘中提醒

必须包含：

- 触发条件。
- 当前行情。
- 与预案关系。
- 风险提示。

提醒应短、明确、可执行，避免长篇分析。

### 复盘报告

必须包含：

- 昨日预案。
- 今日实际走势。
- 判断是否命中。
- 偏差原因。
- 后续改进建议。

复盘的重点不是证明 AI 正确，而是帮助策略进化。

## 数据来源要求

优先级：

1. 用户录入数据。
2. 行情结构化数据。
3. 公司公告和财报。
4. 可信研报和财经信息源。
5. AI 基于已知信息的推断。

当数据源缺失：

- 必须说明“当前缺少某类数据”。
- 可以给出分析框架。
- 不应输出看似精确的结论。

## 置信度规则

AI 可以对判断标注置信度：

- 高：多项数据一致，来源明确。
- 中：部分数据支持，但仍需验证。
- 低：数据不足，主要基于推断。

置信度不能替代风险提示。

## 防幻觉检查清单

每次生成重要报告前，检查：

- 是否引用了不存在的来源。
- 是否出现未经验证的具体数字。
- 是否把推断写成事实。
- 是否遗漏风险提示。
- 是否对用户私有策略泄露过多。
- 是否给出了过度确定的买卖结论。
- 是否说明了数据缺口。

## 私有策略保护

DaiYk 的底层选股逻辑、书籍提炼、思维导图和实战经验属于私有方法论。

产品应区分：

- 面向 DaiYk 本人的完整分析。
- 面向外部订阅用户的摘要化分析。
- 内部策略规则的不可见执行逻辑。

对外输出时，应隐藏部分底层规则，避免泄露核心方法论。
