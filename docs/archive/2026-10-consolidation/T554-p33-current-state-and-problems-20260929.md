# T-554：P-33 当前状态与问题清单

日期：2026-09-29

## 结论

P-33 已经不是“基础系统还没搭起来”，而是进入了**生产可靠性收口 + Agent Space 灰度收口 + 产品形态决策**并行阶段。

当前主线不是继续扩展能力，而是把已经完成一大段的 Workspace / Agent Space 重构收口成一个可以对用户交代、可以在假期上线、节后进入真实测试的版本。生产自动化问题仍需记录和观察，但按当前节奏不应抢占重构发布准备。

生产可靠性问题（尤其是 `mg` 持仓复盘零写入）列为并行观察线：交易日窗口有限，先保留证据和自然验证点，后续再单独做根因分析。

- 三用户 `mg`、`dyk`、`111` 已切到 Agent Space resolver，当前仍是灰度态；旧 Workspace 保留为 history-only/回退来源。

## 问题分层

### A. 现在必须处理：重构上线收口

1. **把当前可发布范围冻结下来**
   - 建议把首批定义为已完成隔离验证的用户可见闭环：待处理、自动化详情、技能管理、设置/通知偏好、失败问题处理会话和候选审阅。
   - 不把“方法资产”继续写成已上线功能；9-24 的当前代码口径已经将方法聚合页移除，方法内容降为文件语义/后续范围，相关旧需求文档需要以该裁决为准解释。

2. **完成 owner 浏览器复核并形成发布单**
   - 复核入口仍是 T-541 清单；隔离自动化通过不等于用户可理解、可操作，也不等于生产证据。
   - 发布单必须明确：目标分支/提交、首批 scope、数据库增量、Skill/资产 seed、旧面板处理、通知策略、回滚和首个观察窗口。

3. **假期上线，节后测试**
   - 假期内：只执行冻结范围的代码/增量 schema/必要 seed 和逐 scope 冒烟，保留旧路径可回退，不顺手扩范围。
   - 假期结束后：进入真实使用测试，分别观察 Portal 路径、自动化终态、失败告知、通知偏好、Skill 安装/启停和用户是否理解“保存/生效”的区别。
   - 真实用户采用、长期运行质量和微信投递必须单独记为运行证据，不能用本地 20/20 代替。

### B. 并行观察：生产可靠性

1. **T-551：`mg` 持仓复盘零写入复发**
   - 目标不是先改提示词，而是定位 first divergence：任务拿到的实际 context/工具结果是否为空或不完整，模型是否输出了不可写入结果，还是 validator/`outputSkipped` 误判。
   - 最小实验：只读提取 9-18、9-24、9-28 三次运行的完整运行链，按 `context → tool call/result → model output → validator → state transition → delivery` 对齐比较。
   - 修复前不要把“绑定正常”或“重试成功”当作根因结论。
   - 9-29 19:30 是下一次自然验证点；验证标准是有有效 `output_version`、实际写入、delivery 终态，且失败时有可解释的 failure signature。

2. **恢复失败的可观测性**
   - 诊断至少要能拿到完整模型输入、原始输出、工具调用与结果、validator 判定、重试链和 trace/run/task/delivery 关联。
   - 当前摘要日志能证明失败发生，但还不足以证明“no_data”究竟在哪一层首次产生。

### C. 需要继续观察：Agent Space 兼容窗口

- 三用户 resolver 已切换，但旧 Workspace 仍未关闭。
- 需要继续收集自然调度、execution/delivery、微信终态和旧入口计数。
- `dyk` 曾有 `awaiting_user / ret=-2 prepare failed`，`111` 仍需自然调度证据。
- `reports/daily` 旧根路径依赖、旧 Workspace default-load 和模型驱动写入是否为零，仍需在 T-534 独立验收中收口。
- 这条线不能因为本地只读 UI 已完成而自动宣布生产兼容窗口结束。

### D. 已有产物但尚未形成明确产品决策

- 用户侧 Workspace 设计收口（T-521/T-523）与 Agent 自有工作空间/自纠错设计（T-524）已有设计和实现材料，但采用范围、旧入口退出和后续 Portal 发布仍需 owner 决策。
- 产品化工作已拆成 Agent、方法/Skill、自动化详情、失败告知、通知偏好、纠错候选和本地只读控制面；这些属于并行产品化，不应遮蔽当前 P0 可靠性问题。
- mg 产品级策略模拟（T-529）是明确的产品方向，但还没有冻结后的工程排期；不能把个人实验、辅助复盘和产品模拟混成一条已完成主线。

### E. 暂不应抢占主线的事项

- T-520 AI 动态补课：应在 P-33 问题清单明确后，按具体未知建立任务，不做无边界信息消费。
- Portal UI 细节、旧右侧面板移除、surface dry-run 等：有价值，但不优先于生产 P0 和兼容窗口证据。
- 继续堆新 Agent 能力或商业化范围：当前证据不足以支持扩大范围。
