# 微信 ACP 联调测试流程

本文档用于测试微信测试号、轻量微信桥接、ACP 协议和 invest-agent Experimental MVP 的完整体验。

测试目标不是证明策略已经完善，而是验证微信入口下的核心产品闭环：

```text
微信消息
→ 微信 iLink API
→ invest-agent 服务内置微信桥接
→ Codex ACP / invest-agent 确定性能力
→ 持仓 / 自选 / 行情 / 提醒 / 复盘
→ 微信回复
```

## 1. 测试目标

必须验证：

- 微信消息能成功进入 Agent。
- Agent 回复能返回微信。
- 持仓、自选股、行情、提醒、复盘基础链路可用。
- 中文股票名不乱码。
- 每日复盘能生成明日预案。
- AI 输出不编造主力控盘、筹码集中度、大单资金等当前缺失的数据。
- 错误和缺失能力有可读提示。

可以暂时接受：

- 非交易时段没有提醒。
- 选股问答质量还不够强。
- 主力控盘直接数据缺失。
- 周/月复盘仍是实验能力。
- AI key 不可用时走降级或错误提示。

不能接受：

- 微信无响应。
- 服务异常退出。
- 股票名称乱码。
- 数据库写入失败。
- 持仓卖出误操作。
- AI 编造具体新闻、研报、财务数字或主力资金数据。

## 2. 测试前准备

### 2.1 本地基础验证

```bash
npm run smoke
```

预期：

```text
Experimental MVP smoke test passed
```

### 2.2 启动 HTTP 服务

```bash
npm run build
npm start
```

服务默认监听：

```text
http://localhost:22648
```

### 2.3 健康检查

```bash
curl http://localhost:22648/health
curl http://localhost:22648/.well-known/agent.json
```

预期：

- `/health` 返回 `status: ok`。
- `/.well-known/agent.json` 返回 agent 信息、capabilities 和 `/acp/message`。

### 2.4 轻量微信桥接启动

生产/服务器形态下，不需要客户或操作者进入服务器手动执行微信桥接命令。服务由 PM2、systemd 或其他进程管理器常驻运行后，打开后台页面即可：

```text
http://<服务器地址>:22648/admin/weixin
```

在页面中点击“连接微信”，后端会生成二维码并展示在网页上。客户扫码确认后，后端保存微信账号状态并启动监听。

本地开发调试时，才需要手动启动服务：

```bash
npm run build
npm start
```

旧的命令行桥接方式只作为开发者备用调试入口。它也默认使用本项目 `.state` 目录，避免和全局 Claude Code 微信桥接共用 `~/.openclaw`：

```bash
npm run weixin:mobile -- --login
```

### 2.5 OpenClaw 配置检查（可选）

确认 OpenClaw 能访问以下地址：

```text
POST /acp/message
GET /.well-known/agent.json
GET /acp/alerts
```

如果服务不在公网，需要使用内网穿透或部署地址。

当前优先使用服务内置的 `/admin/weixin` 连接页，不要求安装 OpenClaw 服务，也不建议同时运行全局 Claude Code 微信桥接和本项目微信桥接的同一个账号。

## 4. 第一轮：连通性测试

### T01：普通问候

微信输入：

```text
你好
```

预期：

- 有回复。
- 如果 AI key 可用，应返回投资助手相关回答。
- 如果 AI key 不可用，应返回可理解的错误或配置提示。

通过标准：

- 微信有响应。
- 服务不崩溃。

### T02：持仓空状态

微信输入：

```text
我的持仓
```

预期：

- 如果没有持仓，返回“当前无持仓记录”。
- 如果已有持仓，返回持仓列表。

### T03：自选空状态

微信输入：

```text
自选列表
```

预期：

- 如果没有自选，返回“自选列表为空”。
- 如果已有自选，返回自选股列表。

### T04：股票行情

微信输入：

```text
000001
```

预期：

- 返回平安银行行情。
- 中文名称正常。
- 返回基础技术指标。

重点观察：

- 股票名是否乱码。
- 行情接口是否异常。

## 5. 第二轮：核心闭环测试

### T05：录入持仓

微信输入：

```text
买入 000001 10.50 100
```

预期：

- 返回已录入持仓。
- 显示股票名称、买入价、数量、总成本。

### T06：查询持仓

微信输入：

```text
我的持仓
```

预期：

- 返回平安银行持仓。
- 显示买入价、现价、盈亏、数量、日期。

### T07：加入自选并记录理由

微信输入：

```text
加入自选 000001 来自选股报告，理由是实验版候选
```

预期：

- 返回已加入自选。
- 显示来源。
- 显示关注理由。

### T08：查询自选

微信输入：

```text
自选列表
```

预期：

- 返回平安银行。
- 显示行情、来源和理由。

### T09：单股分析

微信输入：

```text
分析一下 000001
```

预期：

- 返回行情摘要。
- 返回技术指标。
- 不应出现确定性主力控盘结论。

### T10：设置提醒

微信输入：

```text
设置提醒 000001 涨跌幅 3
```

预期：

- 返回提醒设置成功。

### T11：查看提醒

微信输入：

```text
查看提醒列表
```

预期：

- 能看到 000001 的涨跌幅提醒。

### T12：生成每日复盘

微信输入：

```text
每日复盘
```

预期：

- 返回复盘摘要。
- 服务端生成 `reviews/YYYY-MM-DD.md`。
- 复盘包含“明日交易预案”。
- 明确说明主力控盘、筹码集中度、大单净流入等直接数据缺失。

### T13：查询历史复盘

微信输入，日期换成当天：

```text
查看 2026-05-26 复盘
```

预期：

- 返回对应日期复盘内容。
- 不应重新生成今日复盘。

## 6. 第三轮：异常与边界测试

### T14：部分卖出保护

微信输入：

```text
卖出 000001 10.80 50
```

预期：

- 返回实验版暂不支持部分卖出。
- 不应关闭整笔持仓。

### T15：完整卖出

微信输入：

```text
卖出 000001 10.80
```

预期：

- 返回已卖出。
- 再查持仓时不显示该未卖出持仓。

### T16：重复加入自选

微信输入：

```text
加入自选 000001
```

预期：

- 提示已在自选列表中。
- 不应重复插入。

### T17：无效股票代码

微信输入：

```text
加入自选 999999
```

预期：

- 提示未找到或行情获取失败。
- 服务不应异常退出。

### T18：选股问答

微信输入：

```text
帮我选 芯片行业
```

预期：

- 输出行业分析。
- 输出初筛公司。
- 输出精选候选。
- 输出风险点和数据缺口。
- 不应编造具体财务数字、研报出处或主力资金数据。

## 7. 提醒队列测试

提醒巡检受交易时间影响。微信侧不一定能直接触发，可在服务端执行：

```bash
curl -X POST http://localhost:22648/api/alerts/check
curl http://localhost:22648/acp/alerts
```

预期：

- 非交易时段可能返回空提醒。
- 交易时段若触发，会写入提醒事件并进入 `/acp/alerts` 队列。
- 如果 OpenClaw 轮询 `/acp/alerts`，微信应收到提醒。

## 9. 问题处理规则

测试时如果出现问题：

1. 记录微信输入和实际回复。
2. 同时查看服务端日志。
3. 判断问题类型：
   - 连接问题。
   - 路由问题。
   - 行情数据问题。
   - AI 输出问题。
   - 数据库写入问题。
   - 产品文案体验问题。
4. 先修阻断性问题，再修体验问题。
5. 修复后补充到测试记录。

## 10. 测试完成定义

本轮测试完成时，应确认：

- 微信消息能稳定进出。
- 持仓、自选、提醒、复盘可用。
- 复盘能生成明日预案。
- 主力控盘数据缺口被清楚表达。
- 异常输入不会导致误操作。
- 至少记录一轮真实测试问题和修复结果。
