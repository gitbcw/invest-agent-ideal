# 20 — 主力控盘数据源与指标可行性调研

> 创建于 2026-06-03。本文用于判断 Invest Agent 后续是否要把“主力控盘情况”做成确定性 API，以及应如何定义、采集和计算。结论先行：不要把“主力控盘”当作单一事实指标；应拆成若干可验证代理指标，并按数据稳定性分阶段接入。

## 结论摘要

1. **仅靠分时 K 线不能可靠计算主力控盘。** 分时 K 线只有分钟级 OHLCV，最多能推断成交节奏、放量缩量、价格承接和波动压缩，不能识别真实买卖主体。
2. **“主力控盘”在多数行情软件里是加工指标，不是交易所直接披露字段。** 它通常由资金流、大单成交、盘口、筹码分布、换手、波动形态等组合推断，算法口径各家不同。
3. **筹码集中度有两种口径必须区分：**
   - 技术分析口径：筹码分布 / 成本分布 / 70% 或 90% 成本集中度，多由历史成交和换手模型估算。
   - 股东结构口径：股东人数、前十大流通股东、机构持股等，来自定期报告，频率低但更接近真实持有人结构。
4. **逐笔成交不是所有“控盘代理指标”都必需，但对大单主动买卖、盘口吸筹/出货、盘中异动分析基本必需。** 如果要做“主力控盘评分”，逐笔成交和盘口 Level-2 最好作为增强层，而不是第一版前置条件。
5. **第一版建议做“主力控盘迹象评分”，不要命名为“主力控盘结论”。** 输出应是：强/中/弱迹象 + 使用了哪些数据 + 哪些数据缺失 + 不作确定买卖结论。

## 概念拆解

### 主力控盘

主力控盘不是交易所原始数据字段。可操作定义应改成：

> 在一定周期内，个股是否表现出较强的筹码锁定、价格承接、低波动控价、关键价位护盘或大单持续净主动买入等迹象。

它应该是综合判断，而不是一个孤立数字。

### 筹码集中度

需要拆成两类：

| 口径 | 含义 | 数据来源 | 稳定性 | 适合用途 |
| --- | --- | --- | --- | --- |
| 成本分布集中度 | 历史成交成本在价格区间上的集中程度，例如 70%/90% 成本区间 | K 线、成交量、换手率、第三方 CYQ 数据 | 中 | 判断成本区、支撑压力、筹码是否收敛 |
| 股东结构集中度 | 股东人数、户均持股、前十大流通股东持股比例 | 财报/定期披露/Tushare 等 | 高但低频 | 中长期持有人结构变化 |

注意：成本分布集中度不是实际股东名册，只是模型估算；股东结构集中度是真实披露，但更新慢。

### 逐笔成交

逐笔成交提供每笔成交时间、价格、成交量、成交额、买卖盘性质等字段。它能支撑：

- 大单成交占比。
- 主动买入/主动卖出金额。
- 大单连续性。
- 关键价位是否有大额承接。
- 拉升/砸盘时成交结构。

但逐笔成交仍无法证明“是谁”在买卖，只能判断大额成交行为。

## 数据源调研

### A. 当前已有：东方财富资金流

项目已有 `src/services/eastmoney.ts`，能取主力/超大单/大单/中单/小单净流入。这可以保留给 Dashboard 和巡检信号，但不建议用于日复盘里的主力控盘判断。

原因：

- 资金净流入是成交方向和订单大小口径的加工数据，不等于主力建仓。
- 用户明确表示自己不看资金净流入。
- 日复盘现在已移除资金净流入输入。

### B. 免费/开源候选：AKShare 包装的公开行情

AKShare 文档显示可获取 A 股分笔/Tick 数据。例如腾讯财经来源 `stock_zh_a_tick_tx` / `stock_zh_a_tick_tx_js`，字段包括成交时间、成交价格、价格变动、成交量、成交额、买卖盘性质；文档也标注腾讯接口曾有不可用状态，并建议缺失时切换网易或当日腾讯 JS 接口。参考：[AKShare 股票数据文档](https://akshare-hh.readthedocs.io/en/latest/data/stock/stock.html)。

AKShare/东方财富还存在筹码分布类接口线索，例如 `stock_cyq_em`，公开资料显示可返回获利比例、平均成本、70/90 成本区间和集中度等字段。参考：[AKShare 筹码分布接口资料](https://glama.ai/mcp/servers/%40peikuo/china-stock-mcp-server/blob/main/stock.md)。

判断：

- 优点：接入成本低，适合原型验证。
- 缺点：多为第三方页面抓取，接口稳定性和合规边界不如正式数据商；不适合作为长期唯一事实源。
- 建议：可以做实验接口，但必须带 `source=akshare/eastmoney` 和 `reliability=experimental`。

### C. 相对稳定候选：Tushare Pro

Tushare Pro 官方文档列出了历史分钟、实时分钟、资金流向、股东人数、前十大流通股东、每日筹码及胜率、每日筹码分布等数据类别。参考：[Tushare 数据目录](https://tushare.pro/document/2)。

判断：

- 优点：比页面抓取稳定；有股东结构、每日筹码、资金流等多类数据。
- 缺点：需要 token/积分/权限；是否覆盖逐笔成交与 Level-2 需按套餐确认。
- 建议：如果后续要做正式版“筹码集中度/股东结构”确定性 API，Tushare Pro 是优先评估对象。

### D. 实时 Tick / Level-2 候选：iTick / AllTick / 商业行情源

iTick 文档显示提供股票实时成交 `/stock/tick`，并宣称覆盖逐笔成交、买卖盘口、十档行情、实时买卖挂单及 Level-2 深度数据，支持上证/深证等市场；但需要 API Key，并有使用和分发限制。参考：[iTick 股票 Tick API 文档](https://docs.itick.org/zh-cn/rest-api/stocks/stock-tick)。

判断：

- 优点：更接近盘中主力行为分析所需数据。
- 缺点：需要评估授权、成本、延迟、A 股覆盖质量、调用限制和二次展示限制。
- 建议：只有当用户真的需要盘中控盘/大单行为分析时再接。第一版不必前置。

### E. 专业终端：Wind / Choice / 同花顺 iFinD / 交易所 Level-2

这类数据源最适合长期稳定生产，但成本和授权复杂。它们可能提供：

- Level-2 委托队列。
- 逐笔成交。
- 逐笔委托。
- 大单资金流。
- 筹码分布或技术面因子。
- 机构持仓、股东结构等。

判断：

- 优点：稳定、合规、字段更完整。
- 缺点：成本高，个人实验 MVP 暂不适合。
- 建议：未来商业化客户明确需要时再评估。

## 能否用分时 K 线计算

### 可以从分时 K 线计算的代理指标

| 指标 | 数据需求 | 含义 | 限制 |
| --- | --- | --- | --- |
| 分时 VWAP 偏离 | 分钟价、成交额、成交量 | 价格是否围绕均价强势运行 | 不能识别资金主体 |
| 量价承接 | 分钟价、成交量 | 下跌放量是否被快速收回 | 易受市场整体波动影响 |
| 波动压缩 | 分钟 high/low/close | 是否被控在窄幅区间 | 可能只是流动性差 |
| 尾盘异动 | 分钟价量 | 尾盘抢筹或砸盘迹象 | 单日噪音大 |
| 关键位放量 | 分钟价量 + 计划支撑/压力 | 关键价位是否有承接/突破 | 需要与日线位置结合 |

### 不应从分时 K 线直接宣称的内容

- 主力已经控盘。
- 主力正在建仓。
- 主力锁仓。
- 主力出货。
- 某机构正在买入。

这些都需要逐笔成交、盘口、股东结构、长期换手和价格行为共同验证。

## 筹码集中度怎么做

### 路径一：直接接入第三方筹码分布数据

候选字段：

- 平均成本。
- 获利比例。
- 70 成本低/高。
- 70 集中度。
- 90 成本低/高。
- 90 集中度。

优点：实现快。  
缺点：算法黑箱，稳定性取决于数据源。

### 路径二：自己用日线 K 线和换手率建模

可做简化版移动成本分布：

1. 取近 N 日成交均价、成交量、换手率。
2. 用换手率作为筹码替换速度。
3. 旧筹码按 `(1 - turnover)` 衰减，新成交按当日价格区间分布进入成本分布。
4. 得到成本分布后计算 70%/90% 成本区间宽度、获利比例、平均成本。

优点：完全可控，可解释。  
缺点：只是模型估算，和软件厂商 CYQ 口径不一定一致。

### 路径三：股东结构低频补充

用股东人数、户均持股、前十大流通股东比例、机构持股变化作为中长期筹码集中度辅助。

优点：真实披露。  
缺点：季度级更新，不能解释日内控盘。

## 逐笔成交是否必要

结论：**不是第一版必要条件，但如果要做“盘中主力行为”，就是必要条件。**

| 功能 | 是否需要逐笔成交 | 说明 |
| --- | --- | --- |
| 日复盘最后一节“主力控盘迹象” | 不一定 | 可先用日线/分时/筹码分布做低置信代理 |
| 大单主动买入/卖出 | 需要 | 至少需要逐笔成交方向和成交额 |
| 盘中护盘/砸盘判断 | 需要 | 最好还要盘口/委托队列 |
| 控盘评分正式化 | 建议需要 | 没有逐笔与盘口，评分置信度应降低 |
| 中长期筹码集中趋势 | 不需要 | 可用筹码分布模型和股东结构 |

## 推荐产品定义

不要输出：

> 主力控盘强。

建议输出：

> 主力控盘迹象：中等偏弱。依据是近 20 日波动收敛、换手下降、90% 成本区间收窄；但未接入逐笔成交和盘口数据，因此不能确认主力建仓。

建议字段：

```ts
interface ControlSignal {
  stockCode: string;
  stockName: string;
  date: string;
  score: number; // 0-100
  level: "none" | "weak" | "medium" | "strong";
  confidence: "low" | "medium" | "high";
  signals: Array<{
    key: string;
    label: string;
    value: number | string;
    interpretation: string;
  }>;
  missingData: string[];
  source: string[];
}
```

## 推荐实现路线

### 阶段 0：当前状态

- 日复盘保留最后一节“主力控盘情况”。
- 无确定性数据时只说明未接入，不作判断。
- 不使用资金净流入替代主力控盘。

### 阶段 1：低成本代理指标

新增服务 API：

```text
GET /api/stocks/:code/control-proxy
```

数据来源：

- 当前已有日线/分钟 K 线。
- 当前已有换手率时使用；没有则先跳过。
- 可选接入筹码分布数据源。

输出：

- 波动压缩。
- 量价承接。
- 关键位表现。
- 近 20/60 日换手变化。
- 筹码集中度如果可得。
- `confidence=low|medium`。

### 阶段 2：筹码集中度增强

新增：

```text
GET /api/stocks/:code/chip-distribution
```

优先评估：

1. Tushare Pro 每日筹码/筹码分布。
2. AKShare/东方财富 `stock_cyq_em` 作为实验源。
3. 自研移动成本分布模型作为 fallback。

### 阶段 3：逐笔成交 / Level-2 增强

新增：

```text
GET /api/stocks/:code/tick-summary
GET /api/stocks/:code/orderbook-summary
```

输出：

- 大单主动买入金额。
- 大单主动卖出金额。
- 大单净主动买入。
- 大单成交占比。
- 关键价位承接。
- 买卖盘不平衡。

数据源候选：

- iTick / AllTick 等实时 Tick API。
- 正式商业行情源。
- AKShare 逐笔接口作为实验源。

## 推荐验收标准

第一版不要追求“主力控盘真相”，只验收“不会误导”：

- 没有逐笔/盘口数据时，不输出“主力建仓”“主力控盘”定论。
- 所有判断都能列出使用的数据。
- 输出必须包含置信度和缺失数据。
- 与日复盘集成时只放最后一节，不进入核心结论。
- 至少连续 20 个交易日能稳定生成，才考虑进入正式日复盘。

## 最终建议

近期最合理的做法是：

1. **不急着接逐笔成交。**
2. **先做一个 `control-proxy` 原型**，只用日线/分钟 K 线 + 换手 + 可选筹码分布，输出“迹象”而非结论。
3. **并行验证筹码分布数据源**，优先 Tushare Pro，其次 AKShare/东方财富实验源。
4. **等这个指标在 20-60 个交易日复盘里证明有用，再接 Tick/Level-2。**

这样既不会让日复盘被不可靠数据污染，也给未来升级留了清晰接口。
