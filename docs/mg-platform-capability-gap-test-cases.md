# mg 用户暴露的平台能力缺口测试用例

> 来源：`docs/mg-data-capability-gap-statistics.md`
> 目标：把 mg 日志中反复出现的缺口转换为平台服务、数据适配器和运行闭环的可验收测试
> 原则：测试通过表示平台能给出可审计结果，不表示结论一定看多或看空

## 1. 通用验收约束

所有数据能力接口必须同时返回：

- `provider`、`source`、`fetchedAt`、`asOf`、`market`；
- `coverage`、`completeness`、`freshness`、`warnings`、`missingFields`；
- 原始统计口径、单位、排序方向和时间区间；
- 当数据不足时返回明确的 `partial` / `unavailable` 状态，不返回推测数字；
- 同一日期、同一市场、同一字段的重复请求可以通过缓存或审计记录复现；
- 服务层负责 scope、权限、审计和超时，不能把这些保证交给提示词。

## 2. 核心数据能力测试

### GAP-DATA-001 全申万行业涨跌与资金流矩阵

- 优先级：P0
- 关联缺口：G-01
- 前置条件：指定一个完整交易日，例如 2026-08-04；市场为 A 股；行业口径为申万一级。
- 输入：请求所有行业的涨跌幅、涨跌排名、净流入/流出、资金排名。
- 预期：返回固定的 31 个行业或明确的市场覆盖清单；每行含行业 ID、名称、涨跌幅、资金金额、排名、单位、来源和更新时间；涨幅榜与资金榜独立排序。
- 失败判定：只返回前 3 名、混用腾讯细分行业和申万一级行业、没有覆盖率，或把单一来源当成全市场完整矩阵。
- 当前基线：未通过。mg 日志多次明确“没有取得完整行业矩阵”。

### GAP-DATA-002 行业内涨停/跌停和成分股明细

- 优先级：P0
- 关联缺口：G-02
- 前置条件：同一交易日和行业口径；能够读取行业成分股和市场状态。
- 输入：请求行业涨幅前十公司、行业内涨停数量、完整涨停名单、逐股涨停理由。
- 预期：数量等于名单去重后的数量；每家公司带股票代码、行业归属、涨停日期、状态和可追溯理由来源；无法核验理由时单独标记。
- 失败判定：使用行业领涨股代替涨停名单、只列代表公司却宣称完整、缺少行业归属或理由来源。
- 当前基线：未通过。2026-08-05 行业表中该字段仍为“数据缺失/待接入”。

### GAP-DATA-003 历史日 K 与均量线矩阵

- 优先级：P0
- 关联缺口：G-03
- 前置条件：指定股票、复权方式、起止日期和交易日历。
- 输入：请求过去一年日 K、5/25/60 日均线和 5/60 日均量线。
- 预期：返回完整交易日序列、OHLCV、复权说明、缺失日期、计算窗口和可复算的均线值；窗口不足时明确标记，不静默补零。
- 失败判定：只拿到最新日或部分区间，仍输出连续均量交叉结论；复权口径、交易日或成交量单位未说明。
- 当前基线：部分通过。mg 的个股分析和回测能取得部分字段，但 603895 半年日 K 和连续均量数据曾明确不完整。

### GAP-DATA-004 策略回测数据和执行引擎

- 优先级：P0
- 关联缺口：G-03、G-06
- 前置条件：指定标的、历史区间、策略版本、数量、复权方式、佣金、印花税和滑点假设。
- 输入：按 mg 的量价策略回测一年，每次 10 手。
- 预期：记录每次信号的事实输入、策略版本、买卖时间和价格、数量、费用、持仓状态、收益、最大回撤、数据缺口和是否存在前视偏差。
- 失败判定：把不可取得的控盘度/筹码字段假设为完整；没有策略版本或费用假设；只给收益率而不能重放交易序列。
- 当前基线：部分通过。量价部分可回测，基本面、控盘度和筹码历史字段被排除。

### GAP-DATA-005 逐笔成交与盘口数据

- 优先级：P1
- 关联缺口：G-04
- 前置条件：指定市场、股票、交易日、时区和数据授权；测试账号只读。
- 输入：请求诚迈科技指定交易日的逐笔成交记录。
- 预期：返回时间戳、价格、数量、成交方向/分类、序号和数据来源；无法读取时返回结构化 `unavailable`，并提供上传导出文件的替代入口。
- 失败判定：用 5 分钟摘要冒充逐笔成交，或暗示已登录/读取第三方软件。
- 当前基线：未通过。助手明确无法直接读取同花顺逐笔明细。

### GAP-DATA-006 五年财务与同行比较矩阵

- 优先级：P0
- 关联缺口：G-05
- 前置条件：指定公司、同行选择规则、报告期和财务口径。
- 输入：请求近五年利润、现金流、负债、估值、同行前三和公司应对措施。
- 预期：每个指标有报告期、单位、来源、合并/母公司口径和缺失原因；同行选择可复现；公告事件与财务字段分开。
- 失败判定：用新闻摘要替代财务报表；缺少关键期仍给出完整趋势；同行样本、币种或报告期未说明。
- 当前基线：部分通过。公开检索可补充，但多次出现近五年和同行字段不完整。

### GAP-DATA-007 筹码集中度与控盘度历史字段

- 优先级：P0
- 关联缺口：G-06
- 前置条件：明确“真实数据”与“代理值”的产品命名；确定流通股、前两大股东排除规则和历史截面。
- 输入：计算 90% 分位筹码宽度、控盘度，并用于策略回测或提醒。
- 预期：返回数据来源、计算公式、截面日期、可用历史长度和是否为代理值；代理值不能进入“真实筹码”字段；数据不足时不触发硬买卖信号。
- 失败判定：把价格/成交量代理值包装成主力真实控盘；无法获得历史截面却执行翻倍规则。
- 当前基线：未通过。mg 日志中的方案明确采用代理值，且缺少完整历史字段。

### GAP-DATA-008 美股与海外市场统一字段

- 优先级：P1
- 关联缺口：G-07
- 前置条件：指定美股代码、交易所、时区和观察日期。
- 输入：请求 AVEX 或 PLTR 的基本面、K 线、成交量、机构净买卖、空头和期权资金。
- 预期：分别返回可用和不可用字段，明确延迟、时区、来源和授权；不能用 A 股资金口径替代美股数据。
- 失败判定：只给公司介绍却暗示资金面已核验；用过期搜索摘要填充实时字段。
- 当前基线：部分通过。PLTR 分析明确缺少可审计实时成交量和机构/空头/期权数据。

### GAP-DATA-009 来源冲突与完整性质量对象

- 优先级：P0
- 关联缺口：G-08
- 前置条件：选择一个公开来源统计不一致的交易日。
- 输入：请求同日行业资金排名。
- 预期：返回各来源独立结果、口径差异、时间、单位、冲突字段和最终采用规则；冲突时降低结论置信度，不做静默合并。
- 失败判定：只保留一个来源；把“主力资金”直接解释为机构建仓；用估算补齐冲突字段。
- 当前基线：文字层面部分通过，机器化质量对象未证明。

### GAP-DATA-010 统一数据缺口协议

- 优先级：P0
- 关联缺口：G-08
- 前置条件：分别模拟完整、部分、空结果、超时和来源冲突。
- 输入：同一个业务请求按不同数据质量状态返回。
- 预期：Agent 能从结构化字段直接生成“可回答/部分回答/不可回答”；Portal 和微信看到同一缺口、时间和来源；不存在只有文字里才有的隐含缺口。
- 失败判定：空数组被当成“没有数据”；超时被当成“市场没有事件”；不同渠道出现不同数据状态。
- 当前基线：未通过。当前主要依赖助手自然语言标注。

### GAP-DATA-011 定时报告生成、归档、推送和补发闭环

- 优先级：P1
- 关联缺口：G-09
- 前置条件：使用隔离测试用户；设置一个短的测试时间窗口；禁止发送真实微信。
- 输入：执行早报、盘中简报或收盘资金报告。
- 预期：生成任务、取数、报告保存、artifact、推送、失败、重试、待补发状态可分别查询；同一报告幂等；补发后状态变为已送达并保留审计。
- 失败判定：只在下一条消息中声称“还有 5 条未送达”；没有任务 ID、失败原因或补发结果。
- 当前基线：部分通过。日志中多次出现此前未送达，最新一次有 5 条待用户手动补发。

## 3. 回归控制用例

### GAP-CTRL-001 用户策略变更两阶段闭环

- 目标：防止新增数据能力破坏现有安全边界。
- 输入：mg 式请求“把买入/卖出策略改成新规则”。
- 预期：第一次只产生候选草案；用户确认后才写入；读回新版本；产生审计和文件 artifact；重复确认幂等。
- 当前基线：已有 `method_changes.propose` / `method_changes.apply` 契约，应保持通过。

### GAP-CTRL-002 自选股与持仓写入读回

- 目标：验证数据缺口不会阻断已支持的状态变更。
- 输入：加入 603895，或确认从图片识别出的持仓。
- 预期：写入前确认，写入后读回代码、名称和范围；无法识别的代码单独阻断，不写入猜测值。
- 当前基线：mg 日志表现为可用，应保持通过。

### GAP-CTRL-003 报告文件交付

- 目标：验证研究结果即使部分数据缺失，也能形成可访问报告。
- 输入：请求 HTML 报告或行业复盘表。
- 预期：文件真实创建、发布成功、Portal 展示 artifact；正文说明数据缺口；失败时不伪造链接。
- 当前基线：已有报告和 artifact 路径，应保持通过。

## 4. 通过门槛

P0 用例中，GAP-DATA-001 至 GAP-DATA-004、GAP-DATA-006、GAP-DATA-007、GAP-DATA-009、GAP-DATA-010 必须先达到通过或明确的可用性边界，才能把“完整市场复盘”“策略回测”“自动提醒”作为稳定产品能力对外承诺。

任何用例若只能依赖搜索摘要或模型推断，最多标记为 `partial`，不能标记为 `pass`。
