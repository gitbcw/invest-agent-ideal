## 一、定位与用途

- ED-P2 首个试点：对 mg 行业复盘任务（`at_60d62fcb`，交易日 19:30）的产出做**人工质量评分**，是「好用」的直接度量；

- 评分**只度量不触发修改**：发现的问题走受阻点/错误分析（ED-P1）进入修复流程，rubric 本身不自动改产品或提示词。

## 三、采样方式

- 每周评 **3-5 个交易日**的产出；分层：3 个常规日 + 若当周有异常日（run 失败/补跑/巡查标注数据缺口）则必含 1 个；
- 样本读取：只读——从绑定资产当日版本或 run output 抽行；对照数据从当次 run 的 trace 工具返回取；
- 时点：每周一受阻清单出炉后，评上一周；评分落档 `data/eval-rubric-scores/YYYY-WW-industry.jsonl`（gitignore 内）。

## 四、评分维度（三级锚点：2 达标 / 1 边界 / 0 不达标）

| 维度 | 定义 | 2 分锚点 | 0 分锚点 |
| --- | --- | --- | --- |
| R1 结构与口径 | 行列结构、序号分段、格式与口径契约一致 | 17 列语义全对、序号/日期格式一致、占位列未写入 | 列错位、语义漂移、写入废弃列 |
| R2 数据完备性 | 覆盖口径约定的行业全集，逐行字段齐全 | 覆盖完整；个别不可得字段有诚实标注 | 行缺失无说明、大面积留空 |
| R3 数值可信度 | 抽查 2-3 行数值与工具返回一致 | 抽查全对、单位正确 | 任一抽查值与来源不符 |
| R4 来源与时效 | 第 17 列来源与时间真实、数据为当日收盘后口径 | 来源+时间戳齐全且真实 | 来源栏空、错、或冒称 |
| R5 分析可用性 | 趋势判断/主要原因/验证条件风险三列对 mg 的策略可用性 | 判断引用当日数据、原因具体、风险带可验证条件 | 套话填充、判断与自身数据矛盾 |

## 五、硬门槛（一票否决，不与维度分平均）

- **H1**：编造数值或来源（幻觉）；
- **H2**：触碰历史行（覆盖/重排/删除非当日行）；
- **H3**：日期错误（非交易日行、未来日期）；
- **H4**：行业张冠李戴（代码/名称/数据三者为不同行业）。

任一命中 → 总评 fail，样本直接转 ED-P1 错误分析候选，并核对是否登记受阻点。

## 六、评分记录格式（JSONL 每样本一行）

```json
{"week":"2026-W36","date":"2026-09-03","target":"industry_review","sample_ref":"run atrun_xxx / asset version_xxx","scorer":"agent-draft","scores":{"R1":2,"R2":2,"R3":2,"R4":2,"R5":1},"hard_gate_fail":[],"total":"pass(9/10)","notes":"R5 趋势判断两行套话","linked_fp":null,"trace":"atrun_xxx"}
```

- `scorer`：起步 `agent-draft`（Agent 初评）+ owner 复核抽改；分歧样本保留双方分（judge 校准的金标准就是这些分歧）；
- 周聚合：均分、各维命中 0/1 分的分布、硬门槛次数、fail 样本链接——并入当周受阻清单的「好用度量」段。

## 七、维护纪律

- 口径契约变更（列定义、任务 revision）时同步升版本号并在本文登记；
- 评分标准本身有争议的样本，记入 notes 留档，作为 rubric 迭代与 judge prompt 的素材；
- 本 rubric 不评调度层（是否到点跑、是否送达——巡查与受阻信号已覆盖）。
