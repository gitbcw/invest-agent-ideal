# 用户产物库与通用自动化设计

> 状态：提议设计，待按后续任务文档实施。
>
> 已确认决策：Portal 增加一级入口“产物库”；任何被自动化更新的产物必须保留可恢复的版本历史。

## 背景

当前 Portal 有两类相近但不等价的对象：

- `conversation_artifacts`：一次对话或正式报告的交付物，带有对话和留存语义；
- `automation_task_assets`：一项表格维护任务私有的 `source/working` 文件。

这两个对象都不是用户可长期管理、复用和维护的“产物”。与此同时，当前自动化创建页强制用户上传 CSV/XLSX，等同于把“自动化”收窄成“定时维护表格”。这不支持用户已经拥有的能力，例如定时收集新闻并微信推送、生成报告、更新一份复盘表，或只在满足条件时通知。

本设计将“用户产物库”与“自动化任务”拆开：产物是独立、持久、可版本化的用户资产；自动化是按时间触发的一段指令，可选地读取、创建或更新这些资产，并可选地推送结果。

## 目标

1. Portal 用户可在一级入口管理自己上传、对话生成和自动化生成的长期产物。
2. 产物可查看、预览、下载、重命名、归档、按来源筛选，并能查看版本与来源。
3. 自动化任务不再要求文件输入；“仅推送”是完整且常见的任务类型。
4. 自动化可以引用已有产物、创建新产物或更新指定产物；每次成功更新产生不可变版本。
5. 后台运行继续由服务负责 scope、调度、幂等、审计、投递和资产提交；Workspace/Skill 不成为权限边界。
6. 旧对话 artifact、旧 Workspace 浏览器、日周月复盘和已经创建的表格自动化保持可用。

## 非目标

- 不把 Portal 变成任意 Workspace 文件管理器或代码编辑器。
- 不开放任意 shell、cron、第三方 webhook 或无界文件格式写入。
- 不允许后台任务未经持久化授权修改持仓、策略、规则、配置或其他确定性投资状态。
- 不在首期实现多人协作、共享链接、外部云盘同步、任意文件夹树或跨任务编排。
- 不自动迁移、覆盖或整理真实用户 Workspace 的现有文件。

## 产品模型

### 概念与边界

| 概念 | 含义 | 权威位置 |
| --- | --- | --- |
| 用户产物（Asset） | 用户可命名、浏览和长期复用的逻辑对象，有稳定 `assetId` | 服务 SQLite 元数据 + 用户 Workspace 私有字节 |
| 产物版本（Asset Version） | 一个不可变内容快照，有 `versionId`、校验和、MIME 和创建来源 | 服务 SQLite 元数据 + Workspace 版本文件 |
| 对话交付物 | 本次对话中可打开的文件卡片；可关联一个用户产物版本，也可保留原有短期语义 | `conversation_artifacts` |
| 自动化任务 | “何时运行 + 做什么 + 用哪些输入 + 如何交付/保存”的版本化定义 | 服务 SQLite |
| 自动化运行 | 一次手动或计划触发的执行、结果、投递和产物版本引用 | 服务 SQLite |
| Workspace 浏览器 | 现有的只读技术/文档浏览面，不是用户产物库 | Workspace 文件协议 |

**用户产物库是产品面，Workspace 是隔离与存储面。** Portal 不展示资产的绝对路径、工作目录、Skill、日志或调试文件。

### 资产类型与首期格式

首期资产库支持服务已能安全交付或预览的格式：Markdown、HTML、CSV、XLSX、PDF、PNG、JPEG、WebP 和 SVG。每种格式必须有明确的上传、预览、下载和大小限制策略；不支持的类型不得只因文件扩展名存在就接受。

首期“自动化更新已有产物”仅承诺 CSV/XLSX 的结构化维护与 Markdown 的完整替换生成。其他格式可以作为只读输入或新建下载产物，不能宣称可被可靠地原地维护。

### 版本语义

- 创建、上传、对话保存和自动化成功输出都会创建一个新版本。
- 版本不可变；当前版本是逻辑资产的 head 指针。
- “恢复到某一版本”创建一个新的当前版本，不修改历史版本。
- 失败、取消、失去租约或未通过内容校验的自动化运行不得创建可见新版本。
- 每个版本记录来源：`upload`、`conversation`、`automation`、`restore` 或 `system`，以及可用的 `conversationId`、`taskId`、`runId`。
- 删除首期采用归档，不直接物理删除有版本或任务引用的资产；彻底删除、留存期和清理策略另行设计。

### 推荐存储形态

逻辑资产及版本元数据属于服务层；字节属于用户私有 Workspace，但不经现有 Workspace 浏览器直接暴露。建议路径：

```text
assets/
  <asset-id>/
    versions/
      <version-id>/
        <safe-file-name>
```

每次写入先落到同一 Workspace 内的受控 staging 位置，完成 MIME/结构/路径/checksum 校验后原子提交版本文件和数据库 head。禁止符号链接、绝对路径、父目录跳转和跨 Workspace 引用。

## 自动化模型

### 任务定义

一项任务版本包含：

```text
触发规则（每日 / 工作日 / 每周指定日；固定 Asia/Shanghai）
+ 用户指令
+ 可选输入产物绑定（assetId + 使用当前版本或指定版本）
+ 投递策略
```

新建通用任务默认采用 `agent` 智能处理：模型可基于任务意图选择更新已绑定文件、创建新文件，或只汇报“未变更”。`none`、`create`、`update` 仅作为旧任务和受控兼容路径的服务执行策略，不在 Portal 中要求用户选择。

| 策略 | 语义 | 示例 |
| --- | --- | --- |
| `agent` | 默认；模型选择更新绑定文件、创建新文件或不变更，服务校验实际动作 | 每周维护跟踪表；无可核验数据时只记录原因 |
| `none` | 不保存产物 | 每日检查新闻，仅在有重要消息时推送 |
| `create` | 每次成功运行创建一个新逻辑产物或一个指定集合中的新版本 | 每天生成晨报 |
| `update` | 将成功结果提交为指定逻辑产物的新版本 | 每日维护复盘表 |

投递策略：

| 策略 | 语义 |
| --- | --- |
| `none` | 不主动推送，只在任务历史和产物库可查 |
| `wechat_summary` | 对成功/有结果的运行推送受控摘要及产物链接/入口 |
| `wechat_on_condition` | 由任务指令返回的结构化“需通知”结果决定是否推送；服务仍负责频控和投递审计 |

自动化并不拥有一套独立的“功能清单”。它使用已经提供给该用户实例的正常能力，但后台会话的工具与写权限必须由服务按任务类型、持久化配置和确认状态收窄。任务启用本身是对已声明投递和资产更新策略的持久化授权，不是对任意服务写入的授权。

### 输入和输出绑定

- 输入产物可以为空、一个或多个；任务引用逻辑资产 ID，不引用浏览器上传临时附件或裸 Workspace 路径。
- 绑定可选择“运行时最新版本”或“固定版本”。默认使用最新版本，但 UI 必须明确展示该语义。
- 每次运行必须把已绑定文件的 assetId、版本、文件名和格式作为权威上下文交给模型；模型不得以全局文件列表中的同类文件替换任务对象。
- `update` 只可选择用户拥有、状态为 active 的资产，且资产格式必须被该执行器支持。服务只接受对本次可更新绑定的写入；没有修改时允许正常完成并保留原因。
- `create` 需要任务定义中声明默认文件名、格式和可选标题模板；不能从模型随意生成服务路径。
- 在创建/编辑任务时上传文件，先创建用户资产，再把它作为输入或更新目标绑定；不再生成任务私有 source/working 心智模型。

### 运行与会话

- 手动“立即运行一次”：创建新的互动会话和唯一 run，用户可查看执行结果后继续讨论；任务定义仍只能在任务编辑页变更。
- 计划运行：只产生运行历史、投递记录和产物版本，不污染普通对话列表。
- “在对话中继续”：创建新会话，带入运行摘要和只读产物引用；不会恢复后台上下文或自动再次写入。
- 每次运行记录输入版本、产生版本、摘要、错误、投递结果、幂等键、lease 和审计引用。

## Portal 信息架构与交互

Portal 一级导航新增“产物库”，与“对话”“自动化任务”并列。现有 Workspace 入口保留为高级只读文档面，不承载用户资产管理。

### 产物库

- 列表：名称、格式、当前版本、更新时间、来源、最近自动化任务；支持搜索和来源/格式/状态筛选。
- 详情：预览或下载、版本时间线、来源与引用关系、重命名、归档、恢复历史版本。
- 上传：用户可从产物库上传已支持文件格式，创建逻辑资产和初始版本。
- 对话：助手生成可保存的文件时，消息卡片提供“保存到产物库”；已保存文件展示同一资产入口。
- 自动化：在资产详情中展示引用它的任务；创建/编辑任务可从资产库选择输入或更新目标。

首期不做文件夹路径移动。用名称、格式、来源、标签（如实施时确认需要）和归档状态解决检索与整理；不要把用户操作映射成 Workspace 的任意 `mv`。

### 自动化编辑器

编辑器改为四段：

1. 基本信息：名称、用户指令。
2. 触发：频率、时间；时区固定显示“北京时间”。
3. 输入与结果：可选输入资产；无保存、创建产物或更新已有产物。
4. 投递：不推送、微信摘要或条件推送。

“立即运行一次”始终可用。无输入、无输出但启用微信推送的任务，例如新闻晨报，是有效任务。

## 服务、协议与安全设计

### 新增服务模型

建议新增以下服务拥有的表，并使用 additive migration：

- `user_assets`：`asset_id`、scope、名称、当前版本 ID、状态、创建/更新时间、归档时间。
- `user_asset_versions`：`version_id`、`asset_id`、安全文件名、MIME、大小、checksum、相对存储路径、来源、来源引用、创建时间。
- `automation_task_asset_bindings`：任务 revision 与输入/输出资产关系、角色、版本解析策略。

现有 `conversation_artifacts` 不做就地语义改造。对话文件“保存到产物库”时创建或关联 `user_asset_versions`；交付卡片可同时携带其 user asset/version 引用。现有 `automation_task_assets` 与旧任务继续工作，迁移到新模型必须显式、可回滚且逐任务进行。

### Connector 与 Portal API

新增 `asset.*` connector 命令而不是复用已废弃语义的 `artifact.library.list`：

- `asset.list`、`asset.get`、`asset.version.get`、`asset.versions.list`
- `asset.upload`、`asset.rename`、`asset.archive`、`asset.restore_version`
- `asset.references.list`（供资产详情显示任务/对话来源）

自动化命令演进为接受通用任务 revision；旧 CSV/XLSX payload 维持兼容适配直到迁移完成。所有命令从 connector 注册 scope 取得 `userId`、`instanceId`、`projectId`，忽略 payload scope 字段。

### MCP 与 ACP

新增受控资产读取/发布能力，使 Agent 能在当前用户 scope 内：读取已绑定资产版本、将 staging 文件提交为新版本、将当前对话生成的文件保存到产物库。服务负责路径、格式、大小、版本、审计与当前会话/run 绑定；Skill 文本不得赋予写权限。

普通对话“保存到产物库”涉及新的长期用户资产，首期应明确确认或由用户在 Portal 按钮确认。已启用自动化可在 `agent` 动作下提交新文件或更新本次绑定的文件，不需要每次再次确认，但不得越过任务绑定的目标资产、格式和 scope。

### 生命周期与兼容性

- 对话附件继续遵守现有短期 TTL；它们不是资产库字节来源。
- `conversation_artifacts` 保持既有报告交付和留存契约；链接到用户资产后，资产版本按自己的长期生命周期存在。
- Workspace 浏览器继续排除 `assets/`，避免资产库与工程/调试树混合，也避免绕过版本、审计与格式控制。
- 原有日/周/月复盘不改保存路径和推送契约；后续若要将其报告纳入产物库，应独立提出迁移决策。

## 分阶段交付

1. **资产基础层**：数据库、受控 Workspace 存储、版本服务、MCP/connector 只读与上传、跨用户安全测试。
2. **资产库 Portal**：列表、详情、预览/下载、上传、重命名、归档、版本恢复。
3. **通用自动化**：任务 schema、通用输入/输出/投递策略、纯推送任务、资产创建/更新运行。
4. **旧表格任务兼容与迁移**：旧任务继续运行；新任务走资产绑定；提供逐任务迁移与回退工具。
5. **端到端验收**：上传资产、对话保存、每天新闻推送、自动更新表格、版本恢复、隔离与故障恢复。

## 验收标准

- 用户可在产物库看到自己上传、对话保存和自动化生成的资产，且不能看到其他用户/实例资产。
- 一个资产可预览或下载当前版本，查看历史版本，并恢复某历史版本为新的当前版本。
- 用户可创建不绑定任何文件、仅按时微信推送的自动化任务并成功运行。
- 用户可将已有 CSV/XLSX 资产指定为更新目标；一次成功运行创建新版本，失败运行不改变当前版本。
- 用户可从资产详情追溯创建/更新它的任务与运行，从运行详情打开其输入和输出资产版本。
- 已有旧自动化任务、普通对话 artifact、Workspace 浏览器和日/周/月复盘行为保持不变。
- 资产 ID、版本 ID、任务 ID 或相对路径均不能跨 scope 读取、更新、归档、恢复或下载；路径逃逸、符号链接、checksum/MIME 不一致必须拒绝并审计。
- 重启、重复投递、运行 lease 丢失或并发触发不会生成重复版本或错误推进资产当前版本。

## 风险与待定项

- 资产格式矩阵与大小上限需要在实施 WP0 固化；不得在 Portal 与 Runtime 各自维护不一致白名单。
- “条件推送”的结构化结果协议需要防止模型自由文本误触发投递。
- 旧 `conversation_artifacts` 已有留存策略；新资产库必须避免把短期附件意外升级为长期文件。
- 用户从对话保存产物时的确认交互、标签/集合、彻底删除和保留期限尚未纳入首期。
- 实施期间不得批量迁移真实用户 Workspace 或任务；迁移仅对明确选择的任务执行，并先备份。
