# Agent 空间与旧 Workspace 退出设计 v3

状态：**owner 已确认产品边界；本文件是后续实现、隔离迁移和验收的当前执行权威。**

关联：T-524 v2 的 Agent 工作状态设计仍有效，但本文件取代它作为 Workspace 整理、对象拆分和运行时切换的总体执行顺序。它不授权直接修改生产用户资产、启动生产任务或结束兼容窗口。

## 1. 目标

结束旧 Workspace 作为“文件、方法、Skill、任务说明、运行上下文混合容器”的时代。新结构必须让以下对象各有唯一权威来源、版本链、引用关系和运行边界：

| 对象 | 权威内容 | 运行时规则 |
| --- | --- | --- |
| 用户数据资产 | 文件、持仓、研究、报告和产物 | Agent/任务按授权引用，不复制正文 |
| 用户方法 | 已批准的规则、参数、例外和风险纪律 | Agent/任务绑定明确版本；默认只加载当前采用版本 |
| 技能 | 可视化、可编辑、可版本化的流程与配置资产 | 安装到 Agent 固定版本；不携带任意代码或扩权能力 |
| 任务 | 调度、输入输出、交付、运行记录 | 固定执行 Agent 及依赖版本；运行记录不可改写 |
| 对话 | 用户沟通原文与会话连续性 | 可追溯、可检索，不自动成为长期规则 |
| Agent 工作状态 | 工作事实、候选/已批准经验、承诺状态 | 作用域和预算受控；状态不拥有执行权限 |

新 Agent 空间是控制面：展示身份、安装技能、方法绑定、资产授权、任务、候选状态及运行依据；它不是第二个文件仓库。旧 Workspace 迁移完成后只作为只读历史与回滚来源，绝不再进入新 Agent 默认上下文。

## 2. 已冻结的产品边界

1. 用户资产归属不等于同一存储容器。数据、方法和私有技能都属于用户，但由各自对象管理。
2. 技能与方法独立：技能描述怎样完成工作，可引用方法；方法不被复制进技能，也不会因技能发布而公开。
3. 技能有系统默认、市场发布、用户私有三种来源；默认私有，发布是显式动作。市场发布与私有后续修改各自形成版本，不自动联动。
4. 首版技能只可使用已有服务能力，不能注册任意代码、工具或权限。服务层继续强制 scope、授权、审计和写入边界。
5. 每个 Agent 持有安装清单而不是 Skill 正文副本；安装固定版本，升级由用户批准。模型允许多个 Agent 具有不同安装组合。
6. 用户可保留多个方法体系与完整正式版本链。只有已批准、生效的修改产生正式版本；草稿不膨胀为正式历史。默认运行只加载当前采用版本，任务使用其固定版本。
7. 定时任务是用户持续授权的独立对象，不是对话承诺或提示词。任务记录执行 Agent、依赖、输入/输出、交付和每轮不可变运行证据。
8. 对话历史保留原始沟通；Agent 工作状态分为有证据的工作事实、候选经验、已批准经验和失效历史。只有已批准经验可改变后续默认行为。
9. 工作状态必须属于会话、任务或具体 Agent；运行只按需注入相关状态及少量有效经验，并保留“本轮为何加载”的依据。
10. 真实用户迁移由 owner 控制，不要求终端用户逐项批准。迁移必须有外部备份、可验证映射、隔离演练、切换证据与回滚窗口。

## 3. 版本、存储与上下文不变量

- 正式版本、底层物理存储和模型上下文是三件独立的事。正式版本必须可比较、可恢复；底层可使用内容去重、快照加差异等方式控制空间；历史版本默认不进入上下文。
- 被任务、运行记录、承诺或其他对象引用的版本为受保护版本，必须可完整重现。无引用历史仍可查询/恢复，但不参与默认发现。
- 同一内容在资产页、方法页、任务页和 Agent 空间可多处展示，但所有展示只引用同一对象和版本。
- 运行开始后，技能、方法、输入资产和 Agent 状态版本固定；执行中补查不得静默替换已加载版本。
- 不得通过目录结构、Skill 文本、State Packet 或模型输出扩大数据权限、工具权限或持续执行授权。

## 4. 当前事实与迁移前置条件

当前代码已有 `user_assets`/`user_asset_versions` 的 scope 与不可变版本基础，以及 automation task/run、对话、trace、审计和 Workspace 文件根。当前尚不存在独立的 Skill catalog/发布版本/Agent 安装关系、方法绑定、Agent 配置或完整长期 Agent 工作状态对象。

因此不得先把旧文件搬到一个新目录就宣称完成迁移。先完成对象和运行时装配，才可在隔离副本上验证迁移。已有 mg、111、dyk 的只读采样、原件、候选映射和加载实验只可作为迁移输入及回归基线；它们不是完整备份、生产切换或用户行为正确性的证明。

## 5. 交付序列与派发边界

各执行 Agent 只负责一个工作单元。涉及 SQLite schema、迁移、回填或生产数据切换的工作单元必须先遵循项目 `db-migration` 流程；不得把真实 Workspace、生产数据库、reviews、`.state` 或微信状态作为测试夹具。

### W0：权威源与迁移基线

**负责人范围**：只读调查与可重复的隔离清单，不改产品代码或生产数据。

**工作内容**：

- 对 mg、111、dyk 按 user/project/instance 生成完整候选迁移 manifest：源、校验和、内容类型、建议目标对象、消费者、引用版本、冲突与不迁移原因。
- 验证外部备份是否真实覆盖将要迁移的每项源；未覆盖项列为阻塞，不能以已有有限采样替代。
- 将旧 Workspace 所有实际上下文入口标为 `default-load`、`on-demand`、`history-only` 或 `unknown`，并记录证据。

**完成条件**：manifest 可机器读取、每项有来源和处置；没有把 `unknown` 写成安全；无生产写入。

### W1：对象契约与数据库基础

**负责人范围**：schema、迁移、服务领域模型与最小 scope/audit 契约。不得改变 Portal 页面、运行时接线或真实用户数据。

**工作内容**：建立可版本化的 Method、Skill、SkillRelease、Agent、AgentSkillInstallation、AgentMethodBinding、AgentAssetGrant、TaskDependency/TaskRunSnapshot 及 T-524 状态对象的领域契约。优先复用 user asset bytes/version、automation run、trace 和 audit 的事实源；新增对象保存语义与引用，不复制既有业务事实。

**完成条件**：

- 所有对象均有 user/project/instance scope，系统级 Skill 与用户私有 Skill 分域。
- 正式版本、草稿、发布、安装、批准、停用与历史引用的状态转换有服务层校验和审计。
- 任务/运行快照可固定依赖版本；对象文本不能绕过授权。
- SQLite 迁移具备隔离升级、回滚/前向修复说明和测试，未碰生产数据库。

### W2：方法与资产产品路径

**负责人范围**：用户数据资产、方法对象、版本/引用 API 与最小读模型。不得实现市场或任务调度。

**工作内容**：让方法以 user asset 的内容版本为底座，并由方法对象表达体系、当前采用版本、并行方法与历史；为 Agent/Task 提供版本绑定读取，不再通过 Workspace 全目录发现方法。保留原始资产来源和 Diff/恢复链。

**完成条件**：当前方法、任务固定方法和历史方法在隔离库中可区分；旧版本不默认注入；任意运行记录能回指实际版本。

### W3：技能目录、发布与安装

**负责人范围**：Skill 对象、私有/可分享/市场公开可见性、发布版本、Agent 安装关系与最小服务 API。不得新增任意代码执行或调整现有工具权限。

**工作内容**：把系统模板 Skill 转为可版本化的系统发布源；用户私有 Skill、市场发布 Skill 与本地派生版本分开；Agent 通过安装固定版本获得 Skill。Agent 只能创建/编辑私有草案，用户批准才可生效/安装/发布。

**完成条件**：私有内容不能被市场查询；发布后私有修改不改变发布版本；安装升级需明确决定；运行时只返回 Agent 已安装且版本固定的 Skill。

### W4：Agent 空间控制面与运行依据

**负责人范围**：Agent 配置读模型、运行时装配、可观察性；不得执行真实迁移或删除旧文件。

**工作内容**：实现 Agent 的已安装 Skill、方法绑定、资产授权、任务引用与有效工作状态装配；生成每轮运行依据记录，说明实际使用的版本、资产、状态、写入和交付结果。交互、generic automation 与其他 scheduled 入口必须分别列出覆盖或明确未覆盖。

**完成条件**：默认上下文只使用新对象引用；可解释每轮装配；长文件按分段/预算策略读取，不把“文件存在”当作“完整进入模型”；旧 Workspace 不可因 `history/` 目录名继续默认影响运行。

### W5：任务依赖、承诺与工作状态闭环

**负责人范围**：任务依赖快照、T-524 State Packet、lesson/workflow/commitment 与 run/delivery 关联。不得重新实现调度器。

**工作内容**：任务绑定执行 Agent、技能/方法、输入/输出资产与版本策略；在交互和自动化中按 scope/预算检索有效状态；把 Agent 纠错事实、候选经验、批准/停用与承诺履约接入现有事实源和运行记录。

**完成条件**：draft 不注入；批准不等于证据正确；任务运行成功不等于履约/发送成功；停用学习不取消既有授权任务；所有注入和版本可在 run snapshot 中查明。

### W6：隔离迁移演练

**负责人范围**：隔离数据库和隔离项目副本中的迁移工具、导入验证、回滚演练。严禁真实用户写入。

**工作内容**：以 W0 manifest 的 mg、111、dyk 内容作为输入，导入新对象，校验内容校验和、版本映射、权限、任务依赖和运行依据。至少覆盖 mg 四因子与 KP 的算法隔离、111 复盘模板与策略的独立绑定、dyk 核心公司模型的恢复可发现性。模拟状态缺口不得凭 Agent 摘要填成空仓。

**完成条件**：新对象可独立提供必需内容；旧 Workspace 关闭 default-load 后不再参与隔离运行；回滚到隔离前快照成功；未解决业务采用项继续标记阻塞。

### W7：owner 控制的真实切换与退出

**负责人范围**：只在 W0-W6 全部验收、owner 指定目标与时间窗后执行。

**工作内容**：创建逐用户/逐对象外部备份，写入新对象，重跑基线验证，切换该用户的运行时读取来源，记录切换审计。兼容期旧 Workspace 只读、history-only；期满前检查零 default-load、无未解决引用和可用恢复路径。

**完成条件**：真实运行依据记录证明新对象为唯一默认来源；旧 Workspace 未参与默认装配；备份和恢复经过验证；owner 明确批准结束兼容窗口后才移除旧运行入口。

## 6. 总体验收门槛

1. 数据、方法、技能、任务、对话和 Agent 状态均有唯一权威对象和版本引用。
2. 同用户多方法、多 Agent、多任务不互相隐式污染；跨 user/project/instance 严格隔离。
3. 运行依据记录足以回答“本轮用了谁、哪些版本、哪些资产和状态、为何写入/交付”。
4. 完整的隔离迁移、旧入口关闭、回滚和重新运行均有可观察证据。
5. 真实切换与用户体验测试分开报告：隔离通过不等于真实用户满意；用户反馈不等于旧入口已退出。
6. 兼容窗口结束时，旧 Workspace 没有任何 `default-load` 路径；只读历史仍可查，直至 owner 决定最终保留/清理策略。

## 7. 执行与验收提示

### 给执行 Agent

> 只执行本文件指定的一个工作单元，先阅读其前置单元交付和当前代码事实。不得扩展到其他单元、生产用户资产、部署、推送或真实任务。保留用户已有改动。报告新增/变更的对象契约、运行路径、测试结果、未覆盖入口和回滚方式；不要把 fixture、隔离运行或模型自述说成生产证据。

### 给验收 Agent

> 按本文件对应工作单元的完成条件独立验收。优先找版本漂移、跨 scope 泄漏、旧 Workspace 绕过路径、资产复制、任务隐式依赖和“运行成功即履约”的错误表述。分别标记代码/自动测试/隔离运行/真实运行/用户反馈证据；缺一项即为 Unknown，不补想象。未满足前置条件时阻止后续单元，不以文档或实现数量替代验证。

各工作单元的详细输入、输出、范围与验收见 [agent-space-execution/](./agent-space-execution/)。总设计与执行稿冲突时，以本文件的对象边界和不变量为准；执行稿不得自行扩大生产授权。
