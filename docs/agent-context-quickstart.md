# Agent Context Quickstart

更新时间：2026-10-06

本文是 Agent 进入 Invest Agent 项目后的最短上下文入口。它不是新的安全契约，也不替代 `AGENTS.md`、服务/MCP 契约或用户 Workspace 内的实际 Skill/方法。

## 先理解项目在做什么

Invest Agent 不是一个把投资判断全部编译成规则的量化系统，而是一个 **Agent 主导的投资决策辅助系统**：

```text
用户目标与历史上下文
  -> 用户方法与 Skills
  -> Agent 理解、研究、判断和解释
  -> 服务/MCP 提供受控事实、写入和运行能力
  -> 用户获得有证据边界的参考与下一步条件
```

Agent 的输出主要是参考，不是绝对正确的事实、收益承诺或自动交易指令。用户方法可能包含“基本面是否健康”“安全边际是否足够”“逻辑是否被证伪”等需要综合判断的内容；不应因为难以公式化，就擅自替换成开发者决定的阈值。

## 角色分工

### Agent / Skill / 方法

- Skill 负责工作方式、提问方式、证据要求、判断框架和表达边界。
- 用户方法负责这个用户自己的投资口径、优先级、例外和风险纪律。
- Agent 负责理解上下文、选择工具、综合证据、表达判断和标出未知。
- Agent 可以提出候选改进，但不能把候选当成已经生效的规则。

### 服务 / MCP

- 服务负责 scope、权限、确认、revision、幂等、审计、调度、投递和事实读写。
- 服务可以保存 Agent 判断的证据、时间和版本，但不替用户决定投资口径。
- Skill 文本不是安全边界；Agent 不能用提示词绕过服务约束。

## 上下文加载顺序

不要把整个 `docs/` 或整个 Workspace 都塞给模型。按任务加载最小相关上下文：

1. [AGENTS.md](../AGENTS.md)：项目红线、当前生产目标和执行方式。
2. 本页：Agent-first 产品定位、参考性输出和上下文原则。
3. [current-state.md](./current-state.md)：当前阶段和正在做什么。
4. [ai-system-governance-principles.md](./ai-system-governance-principles.md)：系统论、反馈、护栏、失败和回滚原则。
5. [system-overview.md](./system-overview.md)：当前运行时、服务边界和所有权。
6. 当前用户的 Workspace `AGENTS.md`、已安装 Skill、已采用方法和相关资产：这些才是该用户的业务口径。
7. 具体领域契约、验收记录和代码：只读与本任务直接相关的部分。

历史归档、旧方案和实验记录只能用于解释来源，不能覆盖当前用户方法或现行契约。

## 判断问题先问什么

遇到一个“要不要做成结构化能力”的问题，先按以下顺序判断：

1. 这是上下文/Skill/方法缺失，还是服务确定性边界缺失？
2. 这个判断是否本来就需要 Agent 综合证据，而不是固定公式？
3. 用户是否已经明确了口径，还是需要先澄清？
4. 当前数据是否足以支持判断，哪些只是参考、哪些未知？
5. 是否真的需要持久化、统计、调度或跨运行复用？只有这时才增加服务记录或通用结果封装。

不要为了“可计算”而过早创建用户需要维护的业务节点。优先用 Skill 管理判断方式；只有在服务需要审计、聚合或恢复时，才保存通用的判断结果、证据引用、as-of、Skill 版本和未知项。

## 当前策略模拟方向

策略模拟当前按两步推进：

- 先用 `mirror-mg` 的真实历史会话和固定证据，验证 Agent 是否理解用户方法、能否遵守证据边界和行动边界。
- 只有 Agent-first 回放达到可接受水平后，再考虑把结果接入日报、周报和前向模拟。

策略模拟已于 2026-10-07 转向 Agent-first：旧版的 fixture 执行器、账本、日报/周报和版本确认原型已移除归档（见 `docs/archive/2026-10-07-strategy-simulation-legacy/`），不再有 `strategy_simulation.dry_run` 入口。但这不代表 `mg` 的自然语言策略已经可以完整历史回测。缺少历史数据或关键上下文时，应明确返回未知/受阻，不伪造收益或完整评分。

## 质量判断

投资 Agent 的“变好”不等于每次判断都正确，也不等于输出更多数字。优先看：

- 是否理解并承接用户方法；
- 是否把事实、判断、行动状态和未知分开；
- 是否使用了正确时点和来源的证据；
- 是否把参考意见误说成确定结论；
- 是否在数据不足时降低结论强度；
- 是否把用户确认权和服务写入边界保留下来；
- 是否能在后续复盘中回读原判断和依据。

### 大结果与历史模拟

工具批量结果超过模型上下文预算时，模型侧仅收到 `requires_smaller_query` 和体积信息，不展示可能误导结论的残缺数据行。必须缩小标的批次重取，保留指标预热窗口。审计中的返回字符数不能证明模型看到完整数据。历史模拟必须逐交易日核验；单次超时表示该次路径失败，不能宣称数据源不存在。
