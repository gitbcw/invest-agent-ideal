## 3. 归因

初步类别：`prompt`（主因）；`model`（次因）

- 根因证据：
  - L1 指令【工具使用原则】与尽力回答规则（「数据缺口只限制受影响的子结论……先完成仍有可信证据支持的部分」）覆盖了缺口下的继续交付与如实报告，但缺失「宣告缺口前先穷尽其他已挂载途径」的规则；
  - 模型初始选择历史/缓存类工具合理，失败发生在恢复步骤：结果为空后未尝试其他途径即向用户宣告缺口；工具输出已含语义边界警告仍放弃，说明该行为不稳定（有时走对）。
- 影响范围：所有「缓存/历史类工具 + 实时直查工具」并存的数据查询场景；交互轮次与自动化轮次同受影响（两者注入同一 L1 指令）。
- 为何不是其他类别：
  - 非 `data`：实时源数据可得（实测证明）；
  - 非 `service-contract`：工具契约与返回均正常；
  - 非 `operations`：无部署/依赖故障。
