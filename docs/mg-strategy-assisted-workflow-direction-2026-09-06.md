# mg 策略辅助工作流方向（阶段性结论）

状态：阶段性方向确认（2026-09-06）

关联：T-478（可行性研究）、T-482（筹码历史共享核对）、T-483/T-485（数据能力与共享契约）、T-484（S1 历史序列回放）

## 一、当前阶段的核心判断

本阶段研究的目标不是单纯把控盘度公式代码化，也不是立即建设通用策略平台或交易信号系统，而是验证：

> **系统能否接住 mg 的一部分投资方法，形成一个新的、更省力的工作流。**

T-478/T-484 已经证明公式、数据链和历史序列回放具有技术可行性；尚未证明的是用户价值和产品工作流可行性：mg 是否认可系统生成的辅助结果，是否真的减少重复查数、手工计算和候选筛选工作。

## 二、mg 当前工作流与待验证变化

当前工作流大致是：

```text
读取市场数据
  → 按控盘度/量价/资金/周期规则判断
  → 自动化写入 Excel
  → 对照同花顺副图
  → 人工发现候选
  → 加入观察池并制定次日计划
```

目标工作流是：

```text
系统读取数据
  → 按 mg 策略计算
  → 生成候选/观察结果
  → 展示原因、数据时点和缺失
  → mg 做最终判断
```

系统要减少的是重复查数据、重复计算、重复筛选和重复解释；不替代 mg 的策略判断、同花顺盘中观察或最终确认。

## 三、三阶段路线

### 阶段一：mg 只读辅助试点

- 只服务 mg；
- 使用 T-484 的确定性回放/计算能力；
- 每个交易日生成辅助结果；
- 展示候选、观察、降级原因、数据时点和缺失；
- 不自动加入观察池；
- 不发买卖信号；
- 不替换 Excel 或同花顺；
- 运行 1–2 周并收集 mg 反馈。

阶段一的目标是验证用户价值，而不是封版所有策略规则。

### 阶段二：优化 mg 工作流

如果 mg 认可试点，再根据真实使用反馈优化候选展示、历史序列、观察池承接、次日计划辅助、Excel 字段、缺失提示和运行频率。

### 阶段三：抽取通用能力并推广

只有在 mg 试点证明有效后，才抽取通用指标定义、序列引擎、候选筛选、观察池、策略版本和反馈机制，并用第二个用户验证复用性。

## 四、责任边界

- **mg**：裁决策略含义和候选结果是否符合其方法。
- **P-33/产品负责人**：裁决是否接入产品、范围、风险和推广。
- **Agent/工程**：负责规则翻译、数据验证、解释和实现，不替 mg 发明策略。
- **P-27/P-29**：提供通用数据与计算能力，不吸收 mg 专属业务规则。

系统可以直接决定的数据纪律包括：缺失不伪造、结果带 as-of、代理不冒充精确、版本可回放、未确认规则不进入生产。

## 五、试点验收问题

试点结束时必须回答：

1. 是否减少了 mg 的重复查数、计算和筛选时间？
2. 候选和降级原因是否比原工作流更有帮助？
3. mg 是否愿意持续使用？
4. Excel 和同花顺在新工作流中还承担什么不可替代的作用？
5. 哪些规则需要调整，哪些是数据/展示问题？
6. 是否值得进入阶段二？

结论使用：`continue` / `revise` / `stop`。

## 六、当前不做

- 全市场自动买卖信号；
- 自动修改观察池或持仓；
- 替代 Excel 或同花顺；
- 面向所有用户的通用策略平台；
- 在 mg 未验证前推广给其他用户。

本文是当前方向入口，不替代策略定义、数据契约或具体任务验收记录。
