## 二、行业前沿实践对照（2026-09 调研）

当前业界共识与本项目现状的映射：

| 前沿共识 | 说明 | 本项目现状 |
| --- | --- | --- |
| Trace first, score second | 先有完整观测，再建自动评分 | ✅ 诊断链/trace 落库完整 |
| Production-to-eval 飞轮 | 生产失败持续转化为评估用例，评估集是长出来的不是一次建成的 | ◐ 有雏形（Bad Case→EV-009/010/013），无例行机制 |
| 错误分析先行（Hamel Husain） | 先人工审查样本→错误分析→失败分类法→修明显问题，**然后**才建 judge/自动指标；"先建大评估集"是常见反模式 | ✗ 未例行化（巡查发现问题但无周期性错误分析与分类法沉淀） |
| 三层评估：final-answer / trajectory / tool-use（Morph、LangChain 等） | 只评最终产出会漏掉 Agent 真正失败处（工具选择、规划、中间步骤） | ✗ 终态断言有，轨迹质量无系统评估 |
| Trajectory > final output | 轨迹级 rubric + 人工复核边缘案例是 2026 主流 | ✗ 同上 |
| LLM-as-judge 需校准 | judge 上线前须有人工校准样本、与人工标注一致性度量、误判记录与停用条件（Eugene Yan / Hamel） | ◐ 前提条款已预写在注册表，从未启动满足它 |
| 安全/事务断言不交给 judge | judge 不可替代确定性测试 | ✅ 治理原则已明确（沿续，不动摇） |

结论：**方向不必推倒重来——前沿验证了既有路线（trace-first、飞轮、judge 校准前提都已对齐）；真正缺的是四块**：

1. **AI 产出质量评估缺位**：现有 33 条 EV 全部评"行为对错/安全边界"，没有一条评"产出好不好"（行业复盘内容质量、简报可读性、选股结果可用性）。这是 owner 所指"AI 效果评估"的主体。
2. **错误分析未例行化**：飞轮的起点环节缺失——没有周期性人工错误分析，失败分类法没有沉淀文档，受阻/失败信号没有稳定转化为评估样例的通道。
3. **评估节奏只有变更门**：变更时才跑，模型路由调整、上游数据源漂移、提示词漂移不会被主动发现；缺周期性抽评。
4. **用户反馈未回流**：Portal 喜欢/不喜欢、催补抱怨等信号没有进入评估体系。

## 三、深化路线（摩擦驱动，三阶段）

### ED-P1 错误分析例行化（飞轮起点，先行）

- 每周一次（建议挂周会前或周一），从**受阻点周清单**（见 customer-friction-signal-collection-design.md）+ 巡查发现 + open Bad Case 中抽 3-5 例，走诊断链拉全上下文做人工归因。
- 产出并持续维护**失败分类法文档**（首版可从既有素材起：15 个失败签名 + 3 个 BC + 巡查历史）：分类→频次→根因→是否已有防线。
- 高频/复发条目转评估 candidate（挂 evaluation-gap-enumeration 队列），修复后升 executable 回归——这就是 production-to-eval 飞轮的例行运转。
- 度量：每周有归因记录；分类法条目在长；candidate 转化数。

### ED-P2 产出质量 rubric 试点（AI 效果评估起步）

- **状态更新（2026-09-02）**：两份执行稿已完成待 owner 审定——[行业复盘 rubric](./evaluation-rubric-industry-review.md)（五维 + 四硬门槛）、[盯盘简报 rubric](./evaluation-rubric-intraday-watch.md)（五维 + 三硬门槛，W1 硬门槛兼幽灵个股回归哨兵）。首评窗口：下周一（9-7）评本周样本，或周四清单后提前热身。

- 选两个核心产出试点：**行业复盘简报**（mg 支柱场景）+ **盯盘简报**（dyk 支柱场景）。
- 每产出一份人工 rubric（维度建议：数据完备性与来源标注 / 口径一致性（对照 17 列基线）/ 结论-证据分离 / 可读性 / 可操作性），先人工评，每周各评 3-5 份生产样本（从 trace 抽，脱敏）。
- 积累 2-4 周即同时得到：①「好用」的直接度量与排序依据；② **judge 的人工校准样本集**（ED-P3 前提）。
- 明确不做：不给全产品所有输出统一建 rubric——试点通过再扩，摩擦驱动。

### ED-P3 LLM Judge 启用 + 轨迹指标（按需，不预先建设）

- **启用条件（沿用注册表既定前提 + 前沿校准要求）**：ED-P2 出现重复评审瓶颈（每周人工评>1 小时或 rubric 维度人工难稳定执行）且校准样本≥20 份。用 glm-5.3 系列做 judge（成本可控），先做 judge↔人工一致性度量（≥约定阈值才上线），保留误判记录与停用条件。
- **轨迹指标轻量起步**：先观测不做门——从 trace/工具观测统计每轮工具调用数、无关探索比、轮次、首字延迟分布，周报呈现；T-400/401 两段式工具发现上线后的效果验证正好需要它。
- 安全/scope/确认/幂等断言**永不**交给 judge（治理原则沿续）。

### 不做清单

- 不采购/引入外部评估平台（共创期量级不需要，自建轻量即可）；
- 不建全量自动化评分（先错误分析与 rubric，judge 按需）;
- 不做即时告警型评估（T-403 已裁决共创期缓）；
- 不用单一总分/平均分替代分层判据（治理原则）。

## 四、两份设计的闭环关系

```
生产信号（S1~S6）→ 受阻点周清单（T-442 设计）
                        │
                        ▼
              ED-P1 每周错误分析（归因+分类法）
                        │
                        ▼
              评估 candidate → 修复 → executable 回归（变更门）
                        │                        │
                        ▼                        ▼
              ED-P2 产出 rubric 试点    19:15 巡查验证关闭
                        │
                        ▼
              ED-P3 judge（校准达标后）
```

一句话：受阻信号采集是**飞轮的原料入口**，错误分析是**飞轮的发动机**，变更门/巡查是**飞轮的落地轮**；产出质量 rubric 与 judge 是在飞轮转起来之后给"AI 效果"装上的**仪表盘**。
