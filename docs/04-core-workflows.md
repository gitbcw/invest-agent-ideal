# 核心业务流程

## 总体闭环

```text
行业/题材输入
→ 行业分析
→ 初筛 5-10 家公司
→ 基本面 + 技术面二筛
→ 输出 3-5 家候选公司
→ 用户选择加入自选股
→ 夜间复盘形成次日预案
→ 盘中触发提醒
→ 收盘复盘判断预案是否正确
→ 周/月复盘评估指标有效性
→ 调整策略指标
```

产品的核心不是单次分析，而是让投资判断进入可记录、可反馈、可优化的循环。

## 流程一：选股问答到自选股

触发：

- 用户输入“帮我分析芯片行业”。
- 用户输入“AI 概念有什么股票”。
- 用户输入某个概念、题材、行业关键词。

步骤：

1. AI 识别主题。
2. 分析行业发展阶段、政策、市场空间和风险。
3. 从行业中初筛 5-10 家公司。
4. 对公司进行基本面和技术面二筛。
5. 输出 3-5 家候选公司。
6. 用户选择“加入自选”。
7. 系统记录加入理由、来源和观察条件。

输出：

- 选股报告。
- 候选公司清单。
- 加入自选的确认消息。

## 流程二：持有股票池到夜间预案

触发：

- 用户告诉助手当前持有哪些股票。
- 用户查询或更新持有股票池。

步骤：

1. 用户通过自然语言提供股票代码。
2. 系统获取实时行情和股票名称。
3. 系统保存持有股票池。
4. 夜间复盘时自动纳入持有股票分析。
5. AI 生成次日交易预案。

预案内容：

- 当前持有股票状态。
- 技术面位置。
- 基本面变化。
- 支撑位和压力位。
- 加仓、减仓、止损和观望条件。

### 交易策略 → 预案(2026-06-23 第一版)

交易策略是用户私人制品(`workspace/config/trading_strategies.yaml`),与预案是 1:N 关系。详见 `docs/trading-strategy-design.md`。

- **触发场景**(三种,最终汇入两道闸门):
  - 场景 A:持仓新增后,系统在录入回复里附"暂无交易预案"提示,在监控概览里标灰。用户**主动**回复"出预案"才进入流程
  - 场景 B:日复盘报告末尾的【预案建议】清单,用户**主动**选择某项才进入流程
  - 场景 C:用户随时说"用 X 策略给 Y 出预案"直接进入流程
- **两道闸门**(所有场景共用):
  1. AI 推荐适用策略(读 trading_strategies + 个股上下文)→ 用户确认
  2. AI 起草预案草案 → 用户确认 → 落库(带 `strategyKey` 溯源)
- **不做的事**:不让机器自动迭代策略(系统不管用户实际交易)、不统计策略命中率、不让复盘反哺策略本体
- **复盘边界**:复盘不感知策略实体,只产出当日 daily_plans + 报告 + 建议清单

## 流程三：夜间复盘到盘中验证

触发：

- 每日收盘后或用户手动发起复盘。

步骤：

1. 系统汇总持仓、自选股、行业 ETF、行情和相关信息。
2. AI 生成每日复盘。
3. AI 为次日生成交易预案。
4. 系统保存预案。
5. 次日盘中根据预案和触发条件发提醒。
6. 提醒明确说明是否符合昨晚预期。

运行约束：

- 自动日/周/月复盘按当前用户助手 scope 调度；内部仍使用 `userId + instanceId` 作为兼容隔离键。
- 如果用户已经在自己的用户助手下手动生成同周期报告，默认自动任务到点不重复生成；只有用户明确确认刷新时才重跑。

提醒示例结构：

```text
股票：示例股份(000000)
状态：放量突破 20 日均线
触发原因：成交量达到 5 日均量 2.3 倍
与昨晚预案关系：符合“放量突破后关注”的预案
可选动作：观察能否站稳压力位
风险提示：若尾盘回落，突破有效性需重新判断
```

## 流程四：盘中提醒到收盘反馈

触发：

- 盘中出现技术信号、消息事件或价格条件。

运行约束：

- 明确规则提醒由 stage2 watch_rules 驱动,即服务层 `alert_rules.relation_to_plan=stage2_watch_rule` 的规则实例。
- legacy `alerts` 只保留作旧 UI/API 兼容,不参与规则巡检、不再自动镜像成运行时规则。
- `market-watch` 是固定时间盘中简报;`rule-alert-check` 是按 interval 独立采样的明确规则巡检。

步骤：

1. 系统发送提醒。
2. 用户可选择操作或忽略。
3. 系统记录提醒时间、触发条件和当时价格。
4. 收盘后系统判断提醒是否有效。
5. 日复盘记录命中、误报或漏报。

反馈类型：

- 命中：信号触发后走势符合预案。
- 误报：信号触发但后续走势不支持。
- 漏报：实际出现重要机会或风险，但系统未提醒。
- 不确定：数据不足或走势尚未完成验证。

## 流程五：周/月复盘到策略优化

触发：

- 每周末。
- 每月末。
- 用户手动发起。

步骤：

1. 汇总周期内所有提醒、预案和用户操作。
2. 统计信号命中、误报、漏报。
3. 评估基本面判断是否被市场验证。
4. 评估技术指标是否有效。
5. 生成指标调整建议。
6. 用户确认是否调整策略方案。

输出：

- 周复盘报告。
- 月复盘报告。
- 策略调整建议。
- 待验证的新规则。

## 流程六：新信息进入文档和项目

触发：

- 用户补充会议内容。
- 用户提供书籍、思维导图、截图或信息源清单。
- 用户反馈某个提醒不好用。

步骤：

1. 先判断新信息属于产品定位、方法论、功能、流程、防幻觉还是路线图。
2. 更新对应文档。
3. 根据文档变化更新项目计划。
4. 如果影响当前阶段，再拆成开发任务。
5. 代码实现完成后，回写文档中的实际状态。
