# mg 策略与工作流诊断

状态：生产只读探索诊断（2026-09-06）

## 1. 范围

- 时间：2026-08-24 至 2026-09-06，北京时间
- 环境：生产
- 用户：`mg`
- 证据：conversation sessions/messages、automation tasks/revisions、Workspace/资产文件路径、现有策略文档与近期任务配置
- 本报告不修改生产数据库、Workspace、任务、资产或推送状态

## 2. 结论先行

mg 当前不是在单独维护一个“控盘度公式”，而是在运行一套多周期投资研究工作流：

```text
月线许可/周线结构
  → 日线持仓与关注股复盘
  → 控盘度/筹码/量价/基本面记录
  → 行业与资金流复盘
  → Excel 按日/月积累
  → 同花顺副图做视觉和口径对照
  → 观察、候选与次日计划
```

Excel 是系统自动化任务维护的用户资产，不是外部输入。它当前承担的是**时间序列积累、历史回看、跨日比较和人工发现问题**的功能。由此推断，mg 需要的不是“把 Excel 搬进系统”，而是把当前积累的记录转化为可查询、可比较、可复现的策略证据。

## 3. 观察到的工作流

### 3.1 日线个股复盘

生产对话显示，日复盘模板要求对全部持仓和关注股逐项记录：价格、K 线、控盘度、90%筹码集中度、资金流、重要信息、当前判断和次日计划，并按自然月持续追加。

### 3.2 高周期过滤

mg 的策略表达为三级流程：月线判断方向许可，周线确认结构是否走坏，日线寻找执行点。已观察到的硬条件包括月收盘高于 10 月均线、5/10 周结构、日线 25 日均线和量能条件。

### 3.3 控盘度与筹码

对话中出现 V1.2/V1.1 控盘度方案、90%筹码集中度、5 日变化、分段评分、回调修正以及“价格下跌本身不扣筹码分”的纪律。策略同时区分东方财富 CYQ 主序列和通达信 COST 近似核验口径。

### 3.4 行业资金流复盘

现有 automation 任务“每天行业复盘”在交易日 19:30 运行，读取并更新当月固定命名 Excel，追加行业/ETF 涨幅、资金流、强势公司、涨停名单和行业逻辑，保留来源、时间和缺失项。

### 3.5 Excel 的实际角色

生产资产中可见多版本的：

- `持仓与关注股日复盘明细（控盘度V1.1）.xlsx`
- `2026年08月行业复盘表_序号分段版.xlsx`
- 技术面扫描、控盘度建仓候选和行业资金流复盘等派生工作簿

这些资产证明 Excel 已经是系统自动化产出的持续记录层，而不是用户在系统外另行维护的孤立文件。

## 4. mg 想达到的目标（证据支持的推断）

### 已观察目标

1. 通过连续记录，观察控盘度、筹码、资金和价格结构的变化，而不是只看单日结论。
2. 用月线和周线过滤日线信号，减少短周期噪声。
3. 把行业资金流、强势公司和个股复盘放进同一观察框架。
4. 让历史记录积累到足以发现策略问题、验证条件有效性和改进参数。
5. 最终形成观察池、候选和次日计划，而不是让 Agent 直接替代交易决策。

### 尚未被生产证据充分证明的目标

- 是否已经明确要求系统自动生成买卖信号；
- 是否接受代理筹码数据用于正式策略判断；
- 是否希望完全替代同花顺副图；
- 哪些字段是真正影响决策的最小集合。

## 5. 当前受阻点

### P-001：策略知识分散在多种载体中

- 类型：能力/可复现性缺口
- 事实：策略规则分散在对话、方法文档、Excel 字段、同花顺公式和自动化指令中。
- 影响：同一策略的口径、数据来源和时间点不容易统一回溯。
- 置信度：高

### P-002：Excel 能积累，但不等于系统已经能解释序列

- 类型：产品能力缺口，非 Excel 本身缺陷
- 事实：任务会持续追加工作簿，但当前证据尚未证明系统可以对跨日期、跨股票的指标序列做稳定查询、比较和误差分析。
- 影响：用户仍需通过 Excel 和同花顺人工发现规律，Agent 更多是在生成记录而不是帮助验证策略。
- 置信度：高

### P-003：筹码口径存在代理与对照分层

- 类型：数据/方法口径风险
- 事实：对话明确区分东方财富 CYQ 主序列和通达信 COST 近似核验；系统当前拥有筹码代理模型，但与用户主序列的偏差尚未完成量化。
- 影响：若直接把代理值接入硬性评分或自动信号，可能把“方向相近”误当成“口径一致”。
- 置信度：高

### P-004：自动化输出存在“记录成功但研究价值未验证”的风险

- 类型：语义评估缺口
- 事实：行业复盘和日复盘任务有明确写入规则、版本和追加机制；但尚未证明字段完整性、证据质量和跨日可比性足以支持策略验证。
- 影响：Excel 可能越积越多，却没有形成可检验的策略反馈。
- 置信度：中高

## 6. 资产化研究的正确目标

第一阶段不应是“开发控盘度指标”或“接入买卖信号”，而应验证：

1. 策略规则能否被完整、无歧义地定义；
2. Excel 中已经积累的记录能否被系统结构化读取；
3. 指标能否形成按股票/日期/版本可回放的序列；
4. 系统能否解释缺失、代理和口径差异；
5. 序列是否真的帮助 mg 发现策略问题，而不只是生成更多表格。

因此，研究成功标准应从“系统算出分数”改为“系统能支持客户验证自己的方法”。

## 7. 建议的下一步研究边界

先做一个窄切片，不覆盖完整策略：

- 选择控盘度 V1.1/V1.2 的一个核心子链；
- 使用已有日复盘 Excel 的真实历史行；
- 选少量股票和连续交易日；
- 对照同花顺副图/用户记录；
- 只验证定义、序列、口径差异和可解释性；
- 暂不接自动推送、买卖信号或全市场筛选。

研究结束时只需做三选一：

- `go`：进入一个最小客户指标资产化试点；
- `revise`：先补数据或重写方法定义；
- `no-go`：当前资料不足以支持可靠资产化。

## 8. 待用户确认的问题

1. 第一阶段是否以“帮助 mg 验证自己的策略”作为最高目标，而不是替代 Excel 或同花顺？
2. 第一阶段应优先验证控盘度核心子链，还是先验证日复盘/行业复盘的序列积累能力？
3. 同花顺副图是否只作为对照基线，还是有部分公式需要作为兼容口径保留？
4. mg 是否愿意提供一组明确的历史样本和“哪些结果算对”的人工判断？
