# 运营周报生成（P-33 投资助手）

## 触发与节奏

- **定时触发**：Hermes 每周五 20:00 推送简报（先推给用户查看，用户调整后定稿）。
- **手动触发**：随时手动拉近期数据（周六上午周会前常用）。
- **统计周期**：上周六至本周五。

## 板块一：客户使用情况

- 数据源：生产端使用日志（用户：mg / dyk / 111 / 团队成员）
- 字段：活跃度（对话次数、自动化任务执行次数与成功率）、功能使用分布（复盘 / 盯盘 / 选股 / 文件生成）、环比上周趋势
- 满意度信号：本周反馈条数及性质（好评 / 问题 / 建议）、点赞踩、沉默用户预警（上周活跃本周沉寂）
- 判读：一句话结论先行——「谁在怎么用、有没有人要流失、谁的功能该跟」

## 板块二：token 开销与成本

- 数据源：新口径计费统计（mastra 迁移后）
- 字段：总开销、按用户分、按模型分、按任务类型分（交互对话 vs 自动化任务）、环比变化
- 异常点：某天暴涨 / 某模型涨价 / 某任务预算超标，各附一句原因
- 判读：本周成本是否健康 + 一条最值得做的优化建议

## 板块三：本周改动清单

- 数据源：git log（本周 commits）+ OS 任务系统（本周完成/关闭的任务）+ 部署记录
- 分类：新增功能 / 修复 / 优化 / 治理，每条一行说人话（守则：让人能理解、方便决策），标注影响面（哪个用户受益）
- 不确定的归属不硬编，标注「待确认」

## 板块四：重点用户反馈问题

- 数据源：本周巡查记录 + 微信反馈处理记录
- 字段：本周新问题（现象 / 根因归类 / 处理状态：已修复 / 观察中 / 未处理）、老问题变化、下周风险预判
- 与板块一联动：使用情况异常点交叉核对

## 输出与双产物

落盘位置：本仓库 `docs/weekly/YYYY-MM-DD-weekly-*.md`（日期取周期周五）。首跑模板：
[2026-09-05-weekly-ops.md](docs/weekly/2026-09-05-weekly-ops.md)（自用版）、
[2026-09-05-weekly-client.md](docs/weekly/2026-09-05-weekly-client.md)（客户版）。

- **自用版**：详细。四板块全量（含 token 成本、内部治理细节、跨客户对比），服务自己决策与周会，不限长。
- **客户版**：唯一验收标准 = **对客户有用、客户看得懂**。从自用版裁剪改写：① 本周系统改进中与客户使用相关的部分（说人话）② 客户自己账号的使用情况与亮点 ③ 该客户所提问题的处理进展 ④ 值得客户知道的新功能/注意事项。**不含**：token 成本、内部治理与团队信息、其他客户的可识别数据。
- **客户版形态（已定稿）**：粗体短语 + 一句话（短语给专业性与扫读，句子说人话，关键处给具体数字如「9.5→14 分钟」），全文 ≤20 行；开头一句批次汇总（N 批修复 / N 项新能力 / 1 轮优化，全部已发布生产）。
- 数据可获取性标注：每个字段标 [自动] / [需人工输入]，避免静默编造。

## 取数路径（2026-09-06 首跑验证过）

- 使用量 / 成本：SSH 只读查生产（端口 22，服务器非 git 仓库、无 sqlite3 CLI），用 node:sqlite（better-sqlite3）聚合 runtime.db 的 `agent_traces` / `conversation_messages` / `automation_task_runs`，北京时区 +8h 口径。
- 本周改动：本仓库 git log + OS 任务系统 `os list_tasks`。
- 用户反馈：巡查记录（data/patrol-reports/）+ 任务系统事故记录。
- 四板块均可自动取数，[需人工输入] 目标为零；跑一次约 10 分钟。

## 待打磨项

- 各板块字段增删与权重（首跑后调）
- 客户版的送达方式：随简报给自己转发，还是直接推送到客户微信
- 客户版是否按客户个性化（mg / dyk 各一份）还是一份通用
