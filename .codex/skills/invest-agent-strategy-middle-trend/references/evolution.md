# Evolution Rules

## Instance Expansion Candidate

Create an instance expansion candidate when a confirmed user preference or review lesson changes how this instance should operate.

Examples:

- The user prefers pullback confirmation over breakout confirmation.
- The user wants less frequent reminder language.
- A review shows a repeated mistake in chasing high-volatility themes.
- The user confirms a personal interpretation of trend discipline.

The candidate should include:

- Target file or expansion area.
- Proposed text.
- Reason.
- Evidence source.
- Validation condition.

## Skeleton Improvement Candidate

Create a skeleton improvement candidate only when the lesson may improve the base strategy itself.

Single-user confirmation is not enough to update the skeleton. Mark it for maintainer review.

## Do Not

- Do not silently rewrite strategy rules from one conversation.
- Do not let Hermes memory override confirmed instance expansion.
- Do not let instance expansion contradict the protected skeleton without surfacing the conflict.
