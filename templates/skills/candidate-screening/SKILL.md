# 候选筛选与等待条件

这是系统播种的用户方法 Skill，负责把筛选问题整理成可比较、可跟踪的候选和验证条件。它不把一次分析升级为长期规则，不固化特定用户、行业或数据源的结论。

## 适用范围

当用户提出行业、题材、公司或其他资产的候选发现、候选排雷、跟踪清单或买入等待条件问题时使用。核心工作只有三类：

1. **候选发现**：根据用户给出的范围、偏好和筛选目标，形成候选集合并说明进入理由。
2. **风险扫描**：逐项检查候选的基本面、估值、治理/监管、流动性、拥挤度和风格适配风险。
3. **等待条件**：把值得继续观察的价格、估值、事件、财务或技术验证条件写成可复查的条件，并说明失效信号。

这不是“今日推荐”或交易执行能力。用户要求直接给买入结论时，改为输出候选、风险和重新评估条件，不把观察意见写成无条件行动建议。

## 候选发现

- 先说明候选宇宙：资产类别、市场范围、行业/题材口径、纳入与排除条件，以及数据截止时间。
- 按用户明确的筛选目标比较候选；用户未指定数量时给出适量的代表性候选，并明确展示数量不等于完整宇宙。
- 每个候选必须有进入理由、可核验事实、来源和时间；只有叙事或短期热度不能单独构成理由。
- 区分事实、推断、用户偏好和未知项。名称相似、分类不一致或证券身份不确定时先标记，不能猜测合并。

## 风险扫描

对每个候选分别记录：

- 财务质量、盈利和现金流的已知事实与缺口。
- 估值依据、可比性和估值风险；缺少可比口径时降低结论强度。
- 治理、监管、诉讼、重大事件或信息披露风险。
- 流动性、停牌、交易限制、规模和价格波动风险。
- 题材拥挤、情绪过热、叙事与经营事实不匹配的风险。
- 与用户已表达目标或风格的适配点和冲突点。

每项结论都标记为事实、推断或未知；缺少一项证据不能被写成“没有风险”。不把基本面、技术面或仓位判断混成一个未经定义的总分。

## 买入等待条件

等待条件是“何时重新评估”，不是“现在买入”。每个条件尽量包含：

- 触发对象和可观察字段。
- 需要达到的方向、区间或事件状态；没有用户定义时不擅自发明阈值。
- 需要复核的时间范围和证据来源。
- 触发后要重新检查的风险项。
- 逻辑失效、暂停跟踪或移出候选的信号。

价格和技术结构的细节遵循 `technical-analysis` 方法；财务、商业模式和估值深度分析交给 `fundamental-analysis`；仓位上限、暴露控制和交易纪律交给 `risk-control`。本 Skill 只负责把这些维度组织到候选和等待条件中，不替代它们制定规则。

## 覆盖、样本与缺失

每次输出都要披露：

- 请求的候选范围、实际检查范围、数据日期和来源时间。
- 请求数量、实际返回/检查数量、失败或排除数量；必要时说明分类口径。
- 结果是完整扫描、限定范围，还是代表性样本。只有证据证明扫描宇宙完整时，才可使用“全部”“全市场”或排名表述。
- 每个候选和字段的缺失项，以及缺失对结论的影响。

数据覆盖不足时，保留不受影响的已核验维度并降低置信度；不要用少量样本推算整体分布、用旧数据冒充最新数据，或把代表性候选说成完整名单。数据源定义冲突时并列说明口径，不能静默拼接。

## 输出结构

用短表或分组清单输出：

1. **范围与覆盖**：筛选口径、数据日期、实际样本和缺失。
2. **候选清单**：标识、进入理由、事实与来源、主要风险、未知项、置信度。
3. **等待条件**：重新评估条件、需补充证据、失效信号和下一观察点。
4. **边界说明**：未覆盖的范围、不能得出的结论和仍需用户决定的偏好。

不要输出未经定义的综合分数、伪造的全市场排序或最大仓位建议。仓位与执行问题属于 `risk-control` 方法；候选筛选结果只作为后续观察和用户判断的输入。

## 与其他 Skill 的分工

- `automation-task-designer` 负责把用户想要自动完成的工作整理为任务定义；本 Skill 提供候选筛选内容，不负责任务时间、输入输出资产或交付设计。
- `fundamental-analysis` 负责基本面、商业模式、财务质量、同行和估值的深入分析；本 Skill 负责把其结论归入候选风险与理由。
- `technical-analysis` 负责趋势、量价、支撑压力和技术触发规则；本 Skill 负责把其结论归入等待条件与失效信号。
- `risk-control` 负责仓位、暴露和交易纪律；本 Skill 不给出仓位或交易执行指令。

用户长期、明确表达的筛选偏好可以作为个人方法的候选规则；单次样本、临时热点或未经验证的推断不能自动成为长期标准。
