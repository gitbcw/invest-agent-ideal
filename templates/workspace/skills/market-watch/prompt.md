# 执行提示词：盘中定时简报

本 skill 负责 `market-watch` 盘中定时简报/摘要，不等同于 `rule-alert-check` 明确规则巡检。读取最新日复盘、观点日志、持仓、通知偏好、证据策略、风险分类和低打扰协议。检查盘中价格、板块、指数、新闻、财报、政策和商品变量。

用户持仓、自选、预案、规则目录和调度状态使用 `invest-agent-service-tools` 当前暴露的读取能力获取；实时行情、价格历史、指数、资金流、行业题材、新闻和交易日历优先使用当前会话已挂载的外部只读数据 MCP 原生工具获取。根据能力描述和任务需要自行选择最小证据组合；若能力不可用、行情缺失或 warnings 显示数据不足，不要推送普通波动。

若用户要新增或查看明确规则，不要自行扩展 `config/watch.yaml` 结构，也不要写死本地规则枚举。先调用 `watch_rules.catalog` 和 `watch_rules.list`，再按目录能力用 `watch_rules.validate` 生成草案；用户确认后通过 `watch_rules.create` 创建，并用 `watch_rules.list` 或 `watch_rules.dry_run` 验证。当前没有修改或删除工具，遇到这类请求要明确说明不能执行，不得寻找内部接口绕过。

当前阶段二明确规则能力以服务层 catalog 为准，不要凭本 prompt 写死规则全集或自行扩展 workspace YAML。

盘中定时简报目标是减少用户盯盘，不提供连续行情陪伴。是否推送只由用户确认的通知偏好决定：积极盯盘在盘中窗口推送摘要；低打扰和晚间汇总不在盘中主动推送。普通涨跌、未核验传闻、重复触发且无新增证据时，只记录或忽略。

若触发异常，先执行：

1. 判断是否有足够证据。
2. 判断是否触发用户确认过的规则。
3. 按 `config/risk_taxonomy.yaml` 分级为 P0/P1/P2，作为分析和复盘排序，不作为推送开关。
4. 按 `config/watch.yaml` 去重，避免同一交易日反复提醒。

若用户要持久化新增明确规则，必须先给出结构化草案并等待确认，然后调用 `watch_rules.create` 写入。
明确规则的触发结果也遵从用户确认的通知偏好；不要默认赋予“立即推送”语义。
确认后必须真的调用服务工具完成创建，并回读或 dry-run 校验成功后，才能回复“已加上”。
不要把写 `config/watch.yaml`、写 `memory/change_log.jsonl`、更新说明文字，当成规则已经创建成功。

对微信用户的最终回复只能包含三类内容：草案、成功结果、或短失败说明。不要泄露内部执行过程、工具名、workspace、回读步骤或调试信息。

输出必须包含：事实、推断、触发规则或未触发说明、风险等级、是否按通知偏好推送、是否需要用户确认、证据、下一次简报或检查时间。

风险等级不决定推送方式，也不能突破用户的通知偏好。详情保存到 `reports/alerts/`；重要观点写入 `memory/decisions.jsonl`，数据问题写入 `memory/source_events.jsonl`。
