# Daily Portfolio Review

## Purpose

Generate a daily investment review for the current user. It runs automatically on normal trading weekdays at the configured default time, currently `19:00`, unless the same daily report was already generated by a manual user trigger. The daily review focuses on price, profit/loss, portfolio weight, cash, buy/sell zones, and watchlist triggers.

The skill is generic: it must read the user's configured portfolio, strategy, analysis methods, information sources, and report paths instead of relying on any built-in holding or style.

This is investment decision support, not guaranteed financial advice.

## Inputs

Read these files first:

- `AGENTS.md`
- `config/portfolio.yaml`
- `config/strategy.yaml`
- `config/paths.yaml`
- `config/sources.yaml`
- `config/notification.yaml`
- `config/decision_policy.yaml`
- `config/data_contracts.yaml`
- `config/evidence_policy.yaml`
- `config/risk_taxonomy.yaml`
- `config/interaction_policy.yaml`
- `knowledge/decision_protocol.md`
- `knowledge/methods/fundamental.md`
- `knowledge/methods/technical.md`
- `knowledge/methods/macro.md`
- `knowledge/methods/risk.md`

If `config/portfolio.yaml` has no holdings and no watchlist, stop daily review and start onboarding guidance instead.

## Workflow

1. Read the user's holdings, cash, watchlist, target structure, buy/sell rules, and risk rules.
2. Check whether a same-date report already exists. If it was generated by a manual trigger, do not duplicate it unless the user confirms refresh.
3. Fetch or verify current market data because prices and market conditions are time-sensitive; record `data_as_of`, source, confidence, and missing data.
4. Calculate one authoritative holding table: latest price, market value, profit/loss, weight, and role.
5. Focus on price and position state: key zones, weight drift, cash pressure, watchlist distance, and abnormal single-day moves.
6. Generate the required daily action summary: 是否需要操作, 是否需要关注, 是否需要用户确认, 今日最重要原因.
7. Generate a portfolio health check covering position discipline, concentration, cash buffer, non-core complexity, risk events, and style drift.
8. If any buy/sell/rebalance is suggested, only produce an operation confirmation checklist when a confirmed user rule is triggered or a major risk changes the holding thesis.
9. Apply the user's confirmed methods only as needed to explain today's price/position impact.
10. Write the full report to `reports/daily/YYYY-MM-DD.md`.
11. Append audit-friendly views to `memory/decisions.jsonl` using `config/data_contracts.yaml`; write source conflicts or missing key data to `memory/source_events.jsonl`.
12. Reply to WeChat/chat with a concise brief and the report path. Only output the full report when the user asks for details.

## Style Rules

- Write in Chinese.
- Be concise in chat and detailed in the saved report.
- Do not invent holdings, target weights, or buy/sell zones.
- Do not silently change strategy or methods.
- Every important recommendation must include reason, validation signal, and invalidation signal.
- If data is incomplete, state the limitation and avoid false precision.
- Separate facts, inference, user-rule triggers, and uncertainty.
- Ordinary moves, unverified rumors, and repeated triggers should not create action language.
- Keep medium-term trend judgments light; leave broader trend assessment to monthly review.
- "No action needed" is a valid and often preferred conclusion for working professionals.
- During work hours, only P0 alerts should interrupt the user; P1/P2 items should be summarized later.
