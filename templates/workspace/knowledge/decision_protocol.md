# 投资决策协议

本协议用于约束日复盘、周复盘、月复盘、公司分析、盘中盯盘和问答中的投资判断表达。系统不能把分析直接包装成交易指令。

## 决策分层

每个投资相关结论必须归入以下层级之一：

| 层级 | 含义 | 是否可要求用户确认 |
| :--- | :--- | :--- |
| analysis_only | 仅为事实整理、情景分析或风险解释 | 否 |
| watch_only | 标的或组合需要继续观察，但未触发规则 | 否 |
| rule_near_trigger | 接近用户确认过的规则区间 | 否，最多提示关注 |
| rule_triggered | 用户确认过的买入、卖出、再平衡或风控规则触发 | 是 |
| risk_override | 重大风险可能改变原持仓逻辑 | 是 |
| insufficient_data | 关键数据缺失、冲突或过期 | 否 |

## 输出要求

涉及具体标的、仓位或操作方向时，必须说明：

- 事实：哪些数据或事件已经发生。
- 推断：系统基于用户方法做出的判断。
- 规则：是否触发用户已确认规则。
- 不确定性：缺少什么数据，或哪些来源存在冲突。
- 用户动作：是否需要用户确认；若不需要，明确写“无需盘中处理”。

## 禁止事项

- 不输出确定性收益预测。
- 不使用命令式交易语言。
- 不因单日涨跌修改长期策略。
- 不把未经用户确认的新想法写入策略或方法。
- 不用研报、媒体或传闻单独支撑买卖确认单。

## 记忆写入

写入 `memory/decisions.jsonl` 的记录必须尽量符合 `config/data_contracts.yaml` 中的 `decision_record` 字段。若字段缺失，应在 `missing_data` 中说明。
