# 信息源可靠性验证规则

复盘、盯盘和财务分析必须记录主要信息来源，并在周复盘或月复盘中验证信息源是否可靠。

## 默认可靠性分层

| 等级 | 类型 | 使用方式 |
| :--- | :--- | :--- |
| preferred_primary | 交易所公告、公司公告、正式财报、监管文件 | 优先使用，可作为关键证据 |
| verified_market | 可核验行情源、指数/商品官方或主流行情 | 用于价格、涨跌幅、成交量 |
| secondary | 研报、媒体、数据平台整理 | 可辅助判断，但需交叉验证 |
| unverified | 用户新增但尚未验证的信息源 | 只能作为线索，不作为核心证据 |

## 复盘要求

- 重要观点必须给出来源或验证方式。
- 若不同来源冲突，应说明冲突并优先采用更高等级来源。
- 周/月复盘应记录信息源是否误导判断，并给出降级或保留建议。

## 数据时效要求

- 行情、净值、汇率、商品价格必须标注 `data_as_of`。
- 盘中价格若超过 `config/evidence_policy.yaml` 允许时效，应降级为参考信息。
- 财报和公告优先使用交易所、公司公告或监管文件。
- 新闻、研报和社交媒体只能作为线索或辅助证据。

## 事件记录

以下情况应写入 `memory/source_events.jsonl`：

- 重要观点使用了某一信息源。
- 不同来源对同一事实存在冲突。
- 关键数据缺失、过期或不可访问。
- 某一来源导致误判，需要降级或标记。
